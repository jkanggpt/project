# GPU 픽셀 풍경 실험 빌드

기존 2D 픽셀 그림에 법선 조명·큰 그림자·잎과 풀의 흔들림·물결·굴뚝 연기를 더했습니다. 게임과 비교 실험실은 같은 OpenGL 4.3 렌더러를 사용합니다. 화면에 입체 모델이나 세운 종이판을 그리지 않습니다. 상자·지붕·굴뚝과 둥근 입체 범위는 빛을 가리는 계산에만 사용합니다.

사용자가 Windows 11·노트북 RTX 4060에서 실행한 12사례의 요약을 제공했습니다. 1080p 밀집 낮은 GPU p95 4.9203ms, 벽시계 p95 5.3819ms입니다. 출처와 한계는 [하드웨어 기준값](benchmarks/RTX4060_BASELINE.md)에 기록했습니다. 클라우드의 llvmpipe 실행은 기능 검사입니다.

최신 자연 풍경 실행본은 [구현 기록](NATURAL_SCENERY.md)에 있습니다. 전체 아트 방향과 구현 순서는 [자연스러운 픽셀 풍경 계획](PLAN_NATURAL_SCENERY.md), [아트 방향](SCENERY_ART_DIRECTION.md)에 있습니다. 아래 실행 방법은 기존에 배포한 GPU 실험실에 해당합니다.

## 바로 실행

Windows 압축 파일을 모두 푼 뒤 `demo.cmd`를 두 번 누릅니다. 실험실 실행 파일은 `castle_gpu_lab.exe`입니다. 게임을 함께 담은 묶음에서는 `castle_game.exe`로 실제 게임의 풍경도 확인할 수 있습니다. 실행 파일 옆의 `assets`와 `data` 폴더를 함께 둡니다. 별도 설치나 관리자 권한은 필요하지 않습니다.

| 조작 | 동작 |
|---|---|
| `1` / `2` | 낮 / 밤 |
| `S` | 큰 그림자 켜기·끄기 |
| `G` / `L` | 풀 / 잎 움직임 켜기·끄기 |
| `W` / `M` | 물결 / 연기 켜기·끄기 |
| 방향키 | 태양 방향·고도 변경 |
| 오른쪽 마우스 누르기 | 마우스 위치에 움직이는 횃불 |
| `Tab` | 조명 → 명암 완화 원화 → 법선 → 태양 차폐 보기 |
| `H` | 안내 표시 켜기·끄기 |

기본 비교 장면에는 기존 집·참나무·주민·잔디·돌길·바위와 게임의 물 타일이 있습니다. 물가의 큰 칸 모양은 시험 지형의 경계이며, 움직임 자체는 타일마다 반복 재생하는 영상이 아닙니다.

```powershell
.\castle_gpu_lab.exe --dense --night --lights 4
.\castle_gpu_lab.exe --width 1920 --height 1080
.\castle_gpu_lab.exe --check-compute
.\castle_gpu_lab.exe --check-effects
```

`--dense`는 건물 100채·주민 500명·나무 200그루·약 10,000개 풀 묶음·굴뚝 64개·연기 입자 최대 2,048개를 제출합니다. 실제 풀 개수와 차폐 범위 수는 결과 JSON에 기록됩니다. 이 장면은 그림 부하 검사이며 게임 규칙이나 저장 자료를 바꾸지 않습니다.

## 노트북 성능 검사

전원을 연결하고 `benchmark.cmd`를 실행합니다. 실제 선택된 렌더러 이름을 확인한 뒤 네 해상도에서 기본/밀집/밀집 야간 장면을 효과 전환 전후로 실행합니다. RTX 4060 대신 내장 그래픽이 선택되면 Windows 설정의 **디스플레이 → 그래픽**에서 해당 실행 파일을 **고성능**으로 지정합니다. 실행 파일도 고성능 GPU 선택을 요청하지만 최종 선택은 로그로 확인합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\benchmark_gpu.ps1 -Extended -SoakMinutes 30
```

결과는 실행 파일 옆의 `benchmark-날짜-시간` 폴더에 있습니다. `summary.json`과 개별 `.json`·`.log`를 보관합니다. 확장 검사는 지역 광원 8개·16개를 추가합니다. 장시간 검사는 준비 구간 뒤 GPU 자원 수·텍스처와 버퍼 사용량이 늘지 않는지도 확인합니다.

GPU 단계는 바람·물·입자 계산, 스프라이트, 차폐 목록·캐시, 조명, 연기 합성으로 나눕니다. 비동기 시간 질의를 사용하며 표본 수를 함께 기록합니다. `wall_ms`에는 CPU 제출·동기화·표시 시간이 포함됩니다. GPU 단계 시간과 전체 프레임 시간은 서로 다른 값입니다. 두 실행의 p95 차이는 움직임 추가 비용의 근사이며 프레임별 비용 차이의 p95는 아닙니다.

1080p의 네 움직임 효과에 대한 추가 GPU p95 4ms는 검증할 목표입니다. 전체 게임 60 FPS를 확인한 결과가 아닙니다. 기존 게임의 시뮬레이션·UI·CPU 제출 시간도 별도로 포함해야 합니다.

## 구현

| 기능 | 실제 실행 경로 |
|---|---|
| 질감 조명 | 알베도·월드 법선·높이/재질·32비트 소유 번호를 MRT에 저장한 뒤 컴퓨트에서 태양·지역 광원 합성 |
| 큰 그림자 | 건물은 벽 상자+박공 지붕+굴뚝, 작은 물체는 둥근 범위. 지면의 고정 차폐는 보이는 청크에 캐시하고 움직이는 물체는 따로 계산 |
| 바람 | 서로 다른 월드 공간 크기·시간의 잡음 필드. 물체마다 고유 위상. 화면 이동과 타일 경계에 종속되지 않음 |
| 잎 | 원본 그림을 세로 구간으로 나눠 수평으로 조금 휨. 줄기 아래쪽 고정, 법선과 수관 차폐도 함께 움직임 |
| 풀 | 월드 칸·씨앗에서 GPU가 묶음 배치·제외·밀도를 계산. 간접 인스턴스 그리기, 뿌리 고정, 거리별 개수 제한 |
| 물 | 여러 크기의 흐름을 섞은 GPU 파동·동적 법선, 단계화한 밝기와 작은 반짝임. 물가 가까이 움직임을 줄이고 원래 지형 경계를 유지 |
| 연기 | 고정 크기 GPU 입자 풀. 굴뚝 위치에서 생성·예열·상승·바람·수명 갱신. 높이 자료로 지붕과 가림 처리, 픽셀 마스크와 단계화한 투명도 사용 |

풀·연기 마스크는 `art/sources/gpu_scenery/masks.txt`에 보관한 Codex 작성 자료입니다. 아트 파이프라인이 팔레트 세 단계와 정수 변형 여덟 개를 재생성합니다. 두 매니페스트·제작 근거·권리를 등록했습니다. 정적 그림의 필터는 최근접이며 바람·물의 계산 필드만 보간합니다.

컴퓨트 뒤에는 이미지·텍스처·SSBO·간접 명령 용도에 맞는 메모리 장벽을 둡니다. 정상 실행 중 계산 결과를 CPU로 되읽지 않습니다. 검사 종료 때만 풀 개수·차폐 목록 초과를 확인합니다. 타일 목록 한도 128개를 넘으면 물체를 버리지 않고 전체 범위 검사를 사용합니다. 반복 크기 변경과 종료 때 GPU 소유 자원을 해제하고 계수로 확인합니다.

## 원화 적용 범위

기존 여섯 종류의 보정 알베도·법선·높이 아틀라스는 그대로 사용합니다. 해당 셀의 집 정면·참나무 성장 프레임·주민 첫 프레임·잔디·돌길·바위에는 보정 자료를 연결합니다. 좌우 반전 시 법선 X축도 뒤집습니다. 다른 프레임은 원래 그림과 재질별 큰 표면 방향·국소 밝기 기울기에서 유도한 법선을 사용합니다.

| 원장 영역 | 텍스처 파일 수 | 현재 연결 |
|---|---:|---|
| 건물 | 326 | 건물/밭 구분, 보정한 집 한 셀 이외는 유도 법선과 발자국 기반 차폐 범위 |
| 지형 | 10 | 땅·물·나무·바위 구분, 참나무/잔디/바위 표본 보정, 나머지는 유도 법선 |
| 주민·적·복장 | 8 | 원래 동작 프레임 유지, 한 주민 셀 보정, 나머지는 유도 법선 |
| 길·다리 | 3 | 지면/난간 구분, 돌길 표본 보정 |
| 배·어망·물보라 | 21 | 기존 겹침 순서와 그림 유지, 유도 법선. 물보라는 효과 전용 표현 유지 |

이는 전체 방향·외형·동작 프레임의 수작업 법선 제작 완료를 뜻하지 않습니다. 굴뚝과 지붕 범위도 건물 크기·방향에서 얻은 근사입니다. 모든 건물의 실제 굴뚝 화소 위치와 유리·금속 등 특수 재질은 후속 아트 검수가 필요합니다. 회전 사망 동작·전투 광선·UI 표시는 기존 합성 경로를 유지합니다.

## 검사와 남은 확인

- GCC 릴리스 `CASTLE_WERROR=ON` 빌드와 MinGW Windows x64 교차 빌드를 확인했습니다. 실제 MSVC 실행 결과는 아직 없습니다.
- GPU에서 SSBO 64개 값을 계산해 CPU 기대값과 대조했습니다.
- llvmpipe에서 잎·풀·물·연기의 개별 움직임, 고정된 줄기, 물 바깥 변화 0, 정지 장면 변화 0을 확인했습니다.
- 32비트 소유 번호의 높은 바이트를 바꿔도 같은 차폐 결과가 나옵니다. 타일 목록 초과 시에도 전체 검사와 결과가 같습니다.
- 네 해상도와 1180×812의 소수 배율을 세 차례 왕복해 GPU 자원 수·메모리가 안정되는지 확인했습니다. 아틀라스 셀의 경계를 안쪽 화소 중심으로 제한해 바닥 이음매의 빈 화소도 검사합니다. 게임에서는 메뉴→새 게임/튜토리얼/이어하기/불러오기→메뉴를 세 번씩 통과하고 종료 후 GPU 소유 자원 0을 확인했습니다.
- Linux 전체 284개 검사에 모두 통과했습니다. 아트 재생성·재현성을 포함한 결과는 `build/reports/lighting-prototype/gpu-full-tests.log`에 있습니다. 이후 이음매 수정의 GPU 회귀 결과는 `gpu-final-tests.log`, 기능별 수치는 `gpu-effects-final.log`에 기록했습니다.
- 실제 클라우드 창에서 낮·밤과 네 효과의 단축키, 한글 안내, 연기와 원본 픽셀 그림, 소수 배율의 바닥 이음매 수정을 확인했습니다. 이 창은 소프트웨어 렌더러임을 화면에 표시합니다.
- 제목 화면은 800×600·1024×768·1440×900·1920×1080에서 캡처해 확인했고 튜토리얼·게임 캡처도 유지했습니다. 밀집 장면은 풀 9,970개와 연기 2,048개를 실제로 제출했습니다.
- ASan·UBSan을 켠 게임의 반복 전환을 확인했습니다. 원본 LSan 결과에는 Mesa GLX 드라이버의 481개 할당, 108,124바이트가 남았습니다. `libGLX_mesa.so.0` 스택에만 적용한 필터 뒤에는 게임 코드의 메모리 오류·누수 보고 없이 전환과 종료가 완료됐습니다. 원본과 필터 적용 로그를 각각 `gpu-sanitize-transitions.log`, `gpu-sanitize-filtered.log`에 보관합니다. Windows 드라이버의 검사를 대신하는 결과는 아닙니다.
- Windows 벤치마크 스크립트의 구문을 확인하고, 실제 소프트웨어 렌더러 결과를 하드웨어 결과로 받아들이지 않는지도 실행해 확인했습니다.
- 사용자가 제공한 RTX 4060 요약에는 네 해상도의 기본/밀집 낮/밀집 밤 합계가 있습니다. 단계별 원본 표본·전체 게임 프레임·광원 8/16개·30분 실행·Windows 창 비활성/복귀·MSVC 전체 검사와 새 아트 방향의 성능은 별도로 확인합니다.

## 소스에서 빌드

```powershell
cmake --preset windows-msvc -DCASTLE_WERROR=ON -DCASTLE_GPU_TESTS=ON
cmake --build --preset windows-msvc
ctest --preset windows-msvc --output-on-failure
```

같은 명령은 저장소의 `tools/lighting_lab/build_msvc.ps1`에도 있습니다. 창과 OpenGL 4.3 문맥이 없는 CI에서는 `CASTLE_GPU_TESTS`를 끈 채 기존 코어·자료 검사를 실행할 수 있습니다. GPU 검사를 통과했다는 의미로 기록하지 않습니다.

```sh
cmake --preset linux-release -DCASTLE_WERROR=ON -DCASTLE_GPU_TESTS=ON
cmake --build --preset linux-release
ctest --preset linux-release --output-on-failure
build/linux-release/bin/castle_gpu_lab
```

macOS의 기본 OpenGL 4.1은 이번 경로의 대상이 아닙니다. 실제 게임의 기본 경로·설치·통합 검사는 [그래픽 통합](GRAPHICS_INTEGRATION.md)에 기록합니다.
