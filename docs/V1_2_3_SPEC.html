0.2 기존 수치·기능의 보존 원칙 [유지]

  • 기본 6등급(개척지0·촌락1·마을2·도시3·성채4·왕성5), 15종 자원, 24종 연구, 계절당 12일·1년 48일·10게임분/틱·144틱/일, 실제 이동·근무·교대, 8인 보호, 5능력치·12직업분야, 벌목 균등 분산, 전 타일 돌 기본 재고, 보호구역·습격·시장 재입고·위생·행복 산식 유지.
  • 기존 일반 건설 대상 65종(CORE_BLD_1..65)에 신규 4종을 추가하므로 일반시설 69종, 영주관까지 포함한 CORE_BLD_COUNT = 70입니다. 도로/교량은 기존 enum 관례대로 시설 유형 집계에 포함되며, 이를 새 건축물 69채의 실제 존재 수로 오해하지 않습니다.
  • 새 건물은 66=채토장, 67=급수탑, 68=천문대, 69=미술관 순으로 enum 끝에 추가합니다. '채토장이 채석장보다 앞'은 UI 분류 내 표시순서이지 채석장 등 기존 enum/세이브 ID를 재배열하라는 뜻이 아닙니다.
  • 치료소·군영의 해금/건설비/유지비만 바꾸며 치료소 2×2·1명·지능 4 의료자격, 군영 5×3·6명·10시간 순찰·기존 강화 방어 수치는 유지합니다.
  • 신규 건물의 생산·서비스는 실제 직원, 접근 가능한 도로, 근무, 원자적 자원 차감, 정밀 소수 잔여와 결합해야 합니다. UI만 변경해 실질 규칙이 바뀌지 않는 구현을 인정하지 않습니다.
  • 이번 요청은 후반 승급 인구·연구·금화 조건 자체를 바꾸지 않습니다. 중간 성장 병목은 1.2.3 장기 QA로 별도 확인하고 임의로 완화하지 않습니다.

1.2 기존 플레이 세이브 [확정: 보호 / 제안 구현 결정]

이미 생성한 v1.2.2.2의 192×192 진행 세이브를 160×160으로 잘라내거나 강제로 축소하지 않습니다. 그렇게 하면 변두리 건물·탐사·자원·동물·습격 경로를 보존할 수 없기 때문입니다. v1.2.3으로 새로 만든 확장 월드만 160×160이며, 구세이브는 원래의 192×192 크기 그대로 로드하고 v1.2.3의 새로운 시설·거래·AI를 사용합니다.

  • save_version: 10 → 11 [제안 구현 버전], 저장/로드 하위 호환. 공개 C 구조체 크기·ABI가 달라지는 경우 CORE_ABI_VERSION: 12 → 13 [제안 구현 버전]; 기존 이진 배포용 버퍼/공개 ABI 검사를 동반합니다.
  • 구세이브의 지도·호수·광맥·점유·탐험·도로를 다시 생성하지 않습니다. 새로운 점토 매장량은 옛 맵의 바이옴과 호숫가를 기준으로 1회 결정론적 기본값 보정하고 이후 재적용하지 않습니다.
  • 구세이브에서 구버전 치료소·군영은 철거하거나 환불하지 않습니다. 기존 완공 건물을 유지하되 신규 해금은 새로운 건설 명령에만 적용합니다. 미완공 군영도 기존 공사 진행률과 비용을 보존하고 공사 재개를 허용합니다.
  • 기존 클래식 모드는 96×96 및 종전 클래식 상인·기본 규칙을 유지하며, 확장 상인을 클래식 세계에 두 번 생성하지 않습니다.

2. 바이옴 분산형 생성 [확정 방향/제안 알고리즘]

2.1 원인 분석 및 목표

현행 biome_at()은 4×4 고정 중심, 중심 간 48칸, 종류별 16개 시드 중 최근접을 고릅니다. 또한 191−x 반전과 축 교환이 들어가 실제로 같은 바이옴이 덩어리로 나오며 월드 축소와 충돌합니다. 1.2.3은 이 방식을 시드 기반 분산 패치 + 완만한 노이즈 워핑 + 수면 최종 분리로 대체합니다.

[확정] 초원 등 주요 바이옴은 한 곳에만 모이지 않고 2~3개 이상의 별도 지역에 나뉩니다. 희소 바이옴은 원래의 점유를 유지하면서 한두 개의 충분히 탐사할 만한 큰 덩어리로 둡니다. 즉, 한 칸짜리 색 점들이 무작위로 흩뿌려진 지도는 요구를 만족하지 않습니다.

2.3 생성 절차 [제안 구현]

  1. 160×160에서 바이옴별 목표 면적과 패치수 계산. 시드별로 서로 다른 방향의 중심 후보를 뽑되 격자 4×4 고정좌표 사용 금지.
  2. 같은 바이옴 시드는 서로 최소 24칸, 서로 다른 바이옴 중심도 최소 12칸 이격시키되 가장자리 예외는 허용. 난수는 코어의 저장 RNG 또는 별도 해시 스트림을 사용하고 재현 가능해야 합니다.
  3. 시드마다 비대칭 타원·방향성 및 멀티옥타브 좌표 워핑을 적용한 가중 보로노이/영역 성장. 가중 점수: D=(dx/a)^2+(dy/b)^2 + noise_bias; a/b는 각 종 면적 목표와 패치 목표에 맞춰 보정하고, 2~5칸 규모 경계 잡음을 겹칩니다.
  4. 동일 종 패치가 맞닿아 의도된 분산 패치들이 한 덩어리로 합쳐지면 해당 시드의 위치를 재추첨합니다. 1~3칸짜리 불필요한 섬은 인접 종으로 병합하며, 호수로 물을 채우기 전 육상 생물군계를 확정합니다.
  5. 시작 영주관 주변 12칸은 초원·숲이 중심인 안전 지형으로 부드럽게 블렌딩하며 산악·늪·절벽·수역으로 시작 진출을 봉쇄하지 않습니다.
  6. 바탕지형을 확정한 후 나무·광맥·호수 생성을 처리합니다. 호수로 잠긴 타일은 CORE_BIOME_LAKE가 되며, 주변 육상 바이옴 원본을 수온 판정용으로 따로 보존하거나 그 시점의 주변 육지 타일을 참조합니다.
  7. 맵 검사 패널·디버그 덤프에서 종별 면적·4연결 구성 수·평균 직경·시작 중심까지의 최단 이동거리를 출력합니다.

중반 탐사 품질 [QA/제안] 영주관 중심으로부터 실제 이동 가능한 거리 25~65칸 구간에 육상 바이옴 최소 6종을 관찰할 수 있는 시드 비율 90% 이상(산맥에 통로가 없는 시드는 실패). 6종은 생물군계 존재량을 바꾸는 새로운 업적/승급 조건이 아니라 QA 측정 기준입니다.

11.3 나무·동물·광물·시설 모든 툴팁의 절단 방지 [확정]

[현행 코드] game/src/ui.c의 일부 툴팁은 높이 110px를 가정하며 줄폭을 정확히 접지 않아, 나무 성장량·재발아·타일 점토량 같은 장문이 잘립니다. 정적 박스 확대만으로는 모든 문자열을 보장할 수 없습니다.

  • 텍스트 레이아웃과 그리기를 공통 줄바꿈 엔진으로 통일합니다. max_width=min(400px, viewport_width−24px) [제안], 내부 좌우 여백12px, 줄 간격 22px, 제목+섹션 간 추가 5px.
  • UTF-8 한글 음절, 공백, 숫자, 아이콘 인라인 폭을 실제 현재 글꼴로 측정합니다. MeasureTextEx 등 실제 렌더러와 동일한 측정 함수를 사용합니다. 개행과 긴 끊어쓰기 없는 토큰은 명시적으로 분할.
  • 높이 = 위아래 패딩24 + 각 줄 높이 합 + 섹션 간격 + 아이콘/바 최대 높이로 계산. 화면 아래 걸리면 포인터 위쪽으로 배치, 오른쪽 걸리면 좌측으로 이동, 어느 쪽도 못 들어가면 화면 안 스크롤 영역으로 전환.
  • 화면이 1280×720이면 기본 최대 높이 약 600px, 1024×576이면 약 456px, 그보다 작은 화면에서는 viewport_height−24px 이하로 제한하고 휠/스크롤바로 전체 내용에 접근하도록 구현.

12.2 실제 지도 이동·대기·퇴장
