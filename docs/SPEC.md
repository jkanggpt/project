# 마법성채 키우기 — 현재 구현 기준

현재 릴리스 표시는1.2.4입니다. 이 문서와 역할별 정본 문서는 하나의 현재 구현을 설명합니다. 사용자 후속 지시는 문서보다 우선합니다. 패치 번호를 소스·함수·에셋·테스트·저장 폴더의 분기 기준으로 쓰지 않습니다.

## 기술과 소유권

C11과 raylib5.5를 사용합니다. 공개 API는 core/include, 규칙은 core/src의 역할별 모듈, 이동·전투 실행기는 game/src/runtime에 있습니다. 그래픽과 콘솔은 같은160×160 지도·73건물·생산·전투·저장을 사용합니다. Godot/C#/.NET은 빌드나 실행에 필요하지 않습니다. CMake3.21 이상과64비트 C 컴파일러가 필요하며, 지원되는 Windows 도구는 MSVC와 MinGW입니다. raylib 소스 아카이브와 해시를 저장소에 포함해 기존 빌드 캐시가 없어도 구성할 수 있게 합니다.

구조체·포인터·함수 포인터·동적 메모리·배열·파일 입출력·입력 오류 처리를 실제 게임 경로에서 사용합니다. CoreWorld는 정의 사본과 엔티티/타일/이벤트의 주인입니다. GameSession이 실제 이동·전투 객체를 소유합니다. 모든 할당의 실패를 처리하고 생성 실패 중간 상태를 정리합니다.

## 세계와 시간

논리 지도는160×160이며,10게임분 고정 틱, 하루144틱, 계절12일, 연도48일입니다. 실제 이동·공격은 공용 실행기가 최대2게임분 단위로 나눕니다. 바이옴·호수20개·수역 온도·광상 예산·유한 점토·수목 성장/계절과 지역 생물량을 유지합니다. 초기 자원·난수·지도 결과는 정리 전 동일 시드 골든과 대조합니다.

건물의 논리 점유와 그림 높이는 분리합니다. 주민 점유는1×1이고 그림은 약1.5타일 높이입니다. 건물·나무는 점유보다 뒤쪽을 덮으며 발밑으로 깊이를 정렬합니다. 농업류는 밭·울타리·작물 중심이고 계절/방향 그림을 사용합니다.4방향 회전과 오두막2×3/3×2 점유를 유지합니다. 도로는 이웃 연결 마스크와 수변 교량 울타리를 사용합니다.

## 주민과 노동

성별 이름과48외형을 연결합니다.6가지 머리색×남녀×변형4개를 사용하며 걷기·프로필·업무복·방향별 공격을 유지합니다. 주민은 실제 건물에 들어가며 개인 시야를 밝힙니다. 합류 전·이탈 주민은 그리되 시야를 넓히지 않습니다. 허기·물·위생·안전·기분·장기 행복·질병·숙련·실제 근무시간을 별개로 관리합니다.

식량은 합류 주민 하루1개입니다. 농업과 상업은 식량 부족 중에도 근무할 수 있습니다. 일터별 능력치 가중치, 개인 능률E, 총능률F, 직종 숙련과 성장 문턱을 표시합니다. 군사·사냥꾼은 출퇴근 시 실제 일터를 거쳐 환복하고 주/야간 근무조를 사용합니다. 어업은 평상복 상태로 배에 탑승합니다.

개척지는 두 기간의 특별 이주에서 각2명이 오고, 이후 인구8명 하한 보충을 적용합니다. 상위 단계 이주는 빈집·식량·행복·급수·재난·대기일을 판정합니다. 개척지 특별 이주에는 빈집/평균 행복 조건을 적용하지 않습니다.

## 경제와 서비스

자원 표시 순서는 금화·마정석·식량·원목·목재·돌·약초·가죽·점토·벽돌·석탄·철광석·철괴·금광석·금괴입니다. 저장/API ID는 CONTENT_REGISTRY.md를 따릅니다. 일일 필수 소비보다 적은 자원은 붉게 표시합니다. 생산과 소비는 장부를 거치며 분수 자원과 수확 미수령을 보존합니다. 연간 수확은6일에 분산하고 저장고가 부족하면 유실시키지 않습니다.

거래 시설은 영지에1개이며 가판대·시장·교역소 단계별 거래 목록/재고/한도를 사용합니다. 기본 재입고4일, 능률에 따른 기간 조정과 재고 배율을 유지합니다. 기본 수량은30/120/390이며 최종5단위 반올림입니다. 재입고 배율은 E의0.25~7.5 범위에서 1+0.30×clamp((E−1)/6.5,0,1)−0.10×clamp((1−E)/0.75,0,1)입니다. 떠돌이 상인은 실제 출입하고85종 양의 혜택 교환 및24~36일 방문 계획을 사용합니다. nonce로 중복 교환을 막습니다.

급수, 의료3단계, 도서관/교육, 문화, 연구24종, 독립 사건 계획과 확률 예보, 등대/어선2종/2인 좌석/후미 그물을 유지합니다. 연구와 승급은 UI와 명령이 같은 조건을 읽습니다. 등급은 개척지→촌락→마을→도시→성채→왕성입니다.

## 생태와 전투

35동물과7가축, 지역별 생태·사냥 압력·피해/반격·사료·나이·번식을 사용합니다. 동물 전용 피격/사망 그림은 사용자 지시에 따라 제외합니다. 걷기·수영·새끼는4프레임입니다.

6세력/28종 적은 시간차·좌표 차이를 두고 실제 외곽에서 진입합니다. 접근 단계는 발견된 습격과 구분합니다. 최초 발견 또는 공격부터288틱(2일) 공격하고 즉시 퇴각하며, 전원이 시야 밖으로 빠져나가면 습격 종료를 보고합니다. 군사는 병영 자체 시야가 없어도 전역 공유 시야의 적에 출동합니다. 닫힌 성벽과 성문은 보호구역을 만들고 주민 안전·가까운 대피 지점에 반영합니다. 성문 제거도 도로 연결 단절 심사를 적용합니다.

## UI와 아트

모든 건물 선택 점유 테두리, 얇은 철거 빨간 테두리, 겹치지 않는 알림, 부족 일꾼 느낌표, 주민 욕구/시설 작업 말풍선, 세력 마크/적 이미지/수치, 숫자 스탯과 주민 프로필을 유지합니다. 개별 건설 카드에 해금 등급별 반투명 배경/테두리를 적용합니다. 분류 버튼의 색은 해금 표시로 사용하지 않습니다.

현재 에셋 목록은 game/assets/assets_manifest.json 한 벌입니다. 원본·프롬프트·라이선스·단계 연결은 art/art_manifest.json과 ASSETS.md를 따릅니다. 출력은 그림·오디오·폰트의 기존 내용을 바꾸지 않고 정본 경로로 이전합니다. 소스 포함형 패커 대신 단일 아트 도구와 정상 C 모듈을 사용합니다.

## 저장·검증·영구 정책

스키마13만 읽습니다. 구 저장 로더·이관·이전 경로 검색을 유지하지 않습니다. CRC32, 엄격한 필드/개수/ID 검증, 임시 월드, 원자 교체와 같은 스키마 .bak 복구를 사용합니다. 사용자 저장은 정리 대상이 아닙니다. 상세는 SAVE_FORMAT.md입니다.

구조 변경은 원장 작성→참조 이전→회귀/재생성→독립 빌드/설치 확인→미사용 제거 순서입니다. 기존 현재 기능 사례를 기능별로 이식하고, 저장 왕복1/100/1000회·지도100개 이상·144판 장기 대조·4해상도·성능·패키지를 확인합니다. 검증 산출은 build/reports에만 둡니다. 실제 통과/미달/미검증은 CLEANUP_AUDIT.md와 MISSING_FEATURES.md로 구분합니다.

학생 문서·플레이어 문구·코드 주석은 한국어, 식별자는 영어입니다. 현재 작업은 마일스톤 브랜치에서 커밋하고 사용자가 허용한 해당 작업 브랜치에 푸시합니다. main 푸시·병합·외부 메시지 전송은 하지 않습니다. 새 패치도 현재 모듈과 정본을 직접 갱신합니다. 과거 실행 코드·중복 문서·동등한 백업 아트를 현재 소스나 설치본에 축적하지 않습니다.
