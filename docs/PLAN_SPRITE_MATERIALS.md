# 스프라이트 알베도·법선 적용 계획

현재 373개 세계 텍스처를 파일과 실제 프레임 격자로 분류합니다. 건물 방향·성장·계절·주민 복장·동작·동물·배·부착물을 포함하며, UI와 절차 생성 지면, 자체 발광 효과는 용도를 따로 기록합니다.

## 구현 순서

1. 실제 화면 코드의 자르기 규약으로 제작 목록을 고정합니다. 원장의 전체 이미지 크기와 실제 64·96·128·256화소 프레임을 구분하고 수작업 예외를 명시합니다.
2. 기존 원화에서 결정적으로 알베도·법선을 굽습니다. 알파·크기·색상·윤곽을 보존하고, 프레임별 실루엣 거리장과 지붕·벽·수관·피부·바위·지면 프로필로 큰 표면 방향을 만듭니다. 밝기 변화는 작은 표면 세부에만 제한합니다. 추정한 원광의 큰 방향 명암을 제한된 비율로 완화하며 선화·짙은 재료색을 보호합니다.
3. 정수 연산과 정수 제곱근으로 플랫폼 간 출력을 고정합니다. 알베도는 원래 해상도, 법선은 실제 표시 세부에 맞춘 명시적 1·2·4분의 1 해상도로 저장합니다. 각 프레임을 독립 처리해 이웃 셀의 그림이 섞이지 않게 합니다.
4. 기존 원화는 UI·미리보기에 유지합니다. 실제 세계의 재료 쌍은 처음 사용할 때 읽고 재사용하며 종료 시 해제합니다. 기존 여섯 보정 표본과 절차 지면·자체 발광 효과의 경로는 목록에서 구분합니다. 반전·기울어진 식물·회전한 바닥 스프라이트의 법선 축을 검증합니다.
5. 양쪽 원장·제작 순서·근거·권리를 갱신합니다. 원본의 알파 보존, 법선 길이·방향, 프레임 경계 독립, 밝기 보정 한도, 원본 파일 보존, 전체 재생성·재현성을 검사합니다.
6. 원화·알베도·법선과 여러 조명의 비교 시트를 만들고 종류·방향·동작을 시각 검수합니다. 실제 게임 네 해상도·메뉴 왕복·GPU 자원 수명, Linux·MinGW·MSVC WERROR를 확인한 뒤 허용된 작업 브랜치에 반영합니다.

## 완료와 검수 상태

자동으로 굽고 게임에서 연결한 범위와 시각 검수를 마친 범위를 별도 집계합니다. 가려진 실제 입체 모양이나 모든 픽셀의 무조명 색을 원화 한 장에서 확정할 수는 없습니다. 자동 표면 추정과 제한된 명암 완화라는 제작 방식을 결과에 명시하고, 수동 법선 제작 완료로 표시하지 않습니다.

광원 개수·배치·그림자 상단 체적·게임 규칙·저장 형식은 이번 범위에 넣지 않습니다. 기존 픽셀 크기와 원화 실루엣을 유지합니다. 실행 기록과 자동 검사 산출은 `build/reports/sprite-materials`에 둡니다.
