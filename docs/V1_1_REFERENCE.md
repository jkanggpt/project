# 마법성채 키우기 — v1.1 변경 구현 명세 (2026-11-18)

> **용도:** 현행 C11/raylib 버전에 적용할 확정 변경점과 제안 밸런스 수치. v1.0의 나머지 건물 64종·자원 15종·전투/성장/제작 규칙은 유지합니다. 본 문서는 **구현 지시용 초안**이지 적용 완료 보고서가 아닙니다.
>
> **표기:** `[확정]`은 사용자가 직접 지정한 사항, `[제안값]`은 이번 명세에서 구체화를 위해 제시한 초기 수치로 실제 QA 후 조정할 수 있습니다.
>
> **의도된 기존 변경은 유지:** 시장 단계의 마정석 거래 제한, 학교/도서관/학술원의 지능 XP +2/+1/+3은 오류로 취급하거나 원복하지 않습니다.

## 1. 개척지 인구 안전망 및 일반 이주

### 1.1 개척지 [확정]

- 보통 난이도 시작 영구 주민 **4명** 유지. 기존 개척지 **특별 이주단 2회 × 2명**을 유지합니다(현재 배포본 기준 약 5~8일, 10~13일; 구체 도착일은 기존 로직 존중).
- **두 번째 특별 이주단 도착 후**부터 개척지에 남아 있는 동안 영구 주민 수가 **8명 미만**이면 **3게임일마다 정확히 1명**의 영구 주민이 추가로 옵니다. 사망 등으로 8명 아래로 내려가면 반복 적용되며, 8명 이상이면 도착하지 않습니다. 이미 도착한 특별 이주단은 다시 생성하지 않습니다.
- 보충 이주의 첫 심사는 두 번째 특별 이주 도착일 **3일 후**, 이후 도착 유무와 무관하게 3일 단위로 심사합니다. 예: 특별 이주 12일째 완료 → 15·18·21일째 심사. [제안값: 시점 정의]
- 개척지 보충 이주는 **빈집/식량/행복도/우물/날씨/질병** 등의 일반 이주 조건에 막히지 않도록 **보장 유입**합니다. 숙소가 없으면 노숙 상태로 출현하지만 영구 주민 수에 정상 포함됩니다. 성채 입구의 안전 지점에 생성합니다. [제안값: 막힘 방지]
- 개척지에서 영구 주민 수가 **8명 이하**인 동안 **불행·굶주림에 따른 자발적인 영지 이탈을 전면 금지**합니다. **사망(체력 0), 적/맹수 공격에 의한 사망은 그대로 가능**합니다. 계약 만료로 떠나는 계약직에는 이탈 방지 규칙을 적용하지 않습니다.
- 주민 수 9명 이상에서는 기존 이탈 조건을 적용하며, 이탈 후 8명이 되면 이후 추가 자발적 이탈을 막습니다. 조건 평가와 카운트에는 **계약직을 포함하지 않습니다**.
- 개척지에서 촌락 승급 시 이 보충 로직을 종료하며, 완료하지 않은 보충 이주 일정은 누적하거나 다음 등급으로 이월하지 않습니다.

### 1.2 촌락 이상 영구 이주 [확정/제안값]

- 촌락·마을·도시·성채·왕성 모두 이주 **성공 이후 재유입 최소 간격은 4게임일로 통일**합니다. **4일마다 무조건 한 번 시도하고 실패하면 다시 4일을 기다리는 구조가 아닙니다.** 마지막으로 영구 이주민을 받은 뒤 4일이 경과하면 매일 한 차례 조건을 재심사하며, **조건이 충족되는 즉시** 이주단이 도착합니다.
- 예: 20일째 이주 → **24일째부터** 매일 심사. 24~27일 조건 실패, 28일 조건 충족 시 **28일에 도착**, 다음 심사는 **32일째부터**. 실패일에는 쿨타임을 재설정하지 않습니다.
- 마지막 이주 시각은 개척지 특별·보충 이주까지 포함하는 **마지막 영구 이주 시점**으로 관리합니다. 승급 자체는 쿨타임을 초기화하지 않습니다. [제안값: 중복 유입 방지]
- 기존의 빈 영구 주거 자리, 우물 공급, 도로 접근, 식량 비축, 심각한 전염병 제한 및 겨울 인원 50%(올림), 재난 직후 5일 중지 규칙은 **유지**합니다. 이주 실패 시 UI와 QA 로그에 원인을 출력합니다.
- **영구 이주 평균 행복도 하한 [제안값, 기존 48/52/55/57/60에서 완화]:**

| 등급 | 이전 요구 행복도 | 변경 하한 | 이주단 규모(기존 유지) |
|---|---:|---:|---|
| 촌락 | 48 | **38** | 2~3명 |
| 마을 | 52 | **40** | 3~4명 |
| 도시 | 55 | **42** | 3~5명 |
| 성채 | 57 | **44** | 4~6명 |
| 왕성 | 60 | **46** | 4~7명 |

- 이주단은 주거 빈자리 수를 초과할 수 없고, 전원 도착 시 1번의 성공으로 계산합니다. 영구 인구 100명/왕성 3~4년 목표에 맞춰 장기 자동플레이로 검증합니다. **승급에 요구되는 평균 행복도 35/40/45/50/55는 이번 변경에서 수정하지 않습니다.**

## 2. 장기 행복도(Happiness)와 순간 기분(Mood) 분리

### 2.1 기본 상태와 계산 [확정: 분리 / 제안값: 계산식]

- 행복도 `happiness`: **0~100**, 생활수준을 반영하는 비교적 안정적인 장기 지표. **포만도·휴식·안전이 100인 상태**를 기준으로 온전한 보너스를 계산하되, 일상적인 식사·수면·출근 전후의 즉각적인 수치 변화를 직접 반영하지 않습니다.
- 기분 `mood`: **−200~+200**, 사건·여가·불안에 반응하는 별도 부호 있는 값. 평소 변동은 작고, 매우 나쁜 사건이 누적되면 행복도도 크게 하락할 수 있습니다. 기존 `mood` 필드가 행복도를 뜻했다면 별도 마이그레이션/이름 변경을 적용합니다.
- `포만도_장기평균`, `휴식_장기평균`, `안전_장기평균`은 각각 0~100이며, 하루의 실제 평균을 계산한 뒤 매일 06:00에 `장기평균 = 0.75×전일 장기평균 + 0.25×지난 하루 평균`으로 갱신합니다. 신규 주민은 첫날 실제 값으로 초기화합니다. **현재 포만도 35→100인 식사 이벤트 직후 행복도가 튀지 않도록** 합니다.
- `기본행복도 = clamp(난이도 기본값 + 포만 보정 + 휴식 보정 + 안전 보정 + 주거 + 우물 + 임금 + 세금 + 위생 + 의료 + 통근 + 보호구역 + 지속 생활환경, 0, 100)`.
- 난이도 기본값은 **보통 23 / 평화 31 / 혹독 15**로 유지합니다.
- 장기 욕구 보정 [제안값]: `포만 = clamp(12 - 0.15×(100−포만평균) - 0.5×max(0,40−포만평균), −25,+12)`; `휴식 = clamp(10 - 0.12×(100−휴식평균) - 0.35×max(0,30−휴식평균), −14,+10)`; `안전 = clamp(10 - 0.14×(100−안전평균), −4,+10)`.
- 기분이 행복도에 주는 영향: `기분보정 = sign(mood) × [0.03×|mood| + 30×(|mood|/200)^2]`. **최대 약 ±36**. 예: `mood=±20` → 약 ±0.9점; `±50` → ±3.4점; `±100` → ±10.5점; `±200` → ±36점.
- 최종 표시·이주·생산 효율용 행복도는 `clamp(round(기본행복도 + 기분보정),0,100)`. 일상 포만/수면은 장기평균 갱신만 적용하고 **기분을 식사마다 +/−시키지 않습니다**. 기분이 극단적으로 악화되면 그날에도 큰 행복도 하락이 가능해야 합니다.
- 세금에 따른 **기본행복도 보정**은 기존 1금 +5 / 2금 0 / 3금 −6 / 4금 −13 유지. 기존 문화시설의 "기분 +6" 같은 효과는 신설 `mood` 점수로 이관합니다. 예시 방문 보상은 주점 +12, 목욕탕 +10, 극장 +20, 교회 +14(시설별 2일 재방문 보상 쿨다운)로 조정합니다. [제안값]

### 2.2 기분 변화 사건 [제안값]

| 사건 | `mood` 변동 | 적용 방식 |
|---|---:|---|
| 일반적인 식사·수면·출퇴근 | **0** | 일시적 욕구 변화만 |
| 주점 방문 | +12 | 동일 시설 보상 2일에 1회 |
| 목욕탕 방문 | +10 | 2일에 1회 |
| 극장 방문 | +20 | 2일에 1회 |
| 교회 방문 | +14 | 2일에 1회 |
| 경미한 부상 | −8 | 피해 사건 1회, 반복 피해 2시간 쿨다운 |
| 중상(HP 30% 미만 최초 진입) | −25 | 위기 진입 1회 |
| 습격 중 직접 위협 | −15 | 동일 습격 1회 |
| 영구 주민 사망(영지 공동체) | −12 | 같은 날 여러 사망 시 합산, 일일 −60 상한 |
| 심각한 식량 부족(포만 20 미만 연속 12시간) | −8/일 | 1일 1회 |
| 임금 체불 | −6/일 | 1일 1회 |
| 정상 생활 중 평온한 경과 | 0점 쪽으로 2/일 | 하루 06:00, 사건 적용 뒤 감소 |

- 기분 이벤트 중복·반복 발동을 방지합니다. 주민 부상 때문에 한 프레임에 수십 번 −8이 발생하면 안 됩니다.
- 기존 특성의 행복도 ± 효과는 특별한 이유가 없으면 **장기 성향 보정**으로 유지합니다. `낙천가` 등은 기분 회복속도 +1/일 또는 기본행복도 +특성 점수 중 하나로 지정하고 **중복 적용하지 않습니다**. [제안값: 기존 특성 기본행복도 효과 유지]
- UI에는 `행복도 58/100`, `기분 −24/200`, `장기 포만/휴식/안전`, `기분 변동 원인`을 분리 표기합니다. 기존 저장 파일의 구 행복도 수치를 신 행복도에 이관하고 기분은 **0**으로 초기화합니다.

## 3. 기본 성채 → 영주관, 4×4, 승급 공사 [확정]

- 기존 기본 중앙 성채의 **표시 명칭을 '영주관'**으로 통일합니다. 건물의 **기본 점유 면적을 4×4(16타일)**로 변경합니다. 신규 시작 위치는 4×4 전체가 배치 가능한 지형을 우선 선정합니다. 단, **영지 등급명 '성채'는 그대로 유지**합니다.
- 외형은 영지 등급 `개척지 / 촌락 / 마을 / 도시 / 성채 / 왕성`에 따라 **총 6단계**입니다. **크기는 전 단계 공통 4×4**이며, 회전 4방향을 지원한다면 **기본 스프라이트 6×4방향 =24장**을 준비합니다(동일 방향을 공유하는 아트 처리도 가능). [제안값: 스프라이트 규격]
- 승급 조건 충족 뒤 사용자가 승급을 실행하면, **공물·비용을 즉시 차감**하고 `PROMOTING` 상태로 진입합니다. **24게임시간(1게임일, 현실 1배속 120초)** 동안 영주관에 비계·공사 먼지·진행률 0~100%를 표시합니다. **새 등급과 건물 해금은 공사 완료 시** 적용합니다.
- 공사 중 **주민 대피·도로 기준점·자원 보관 등 영주관의 필수 기능은 유지**하며, 동일 영주관에 추가 승급을 시작할 수 없습니다. 성벽/문/도로와 다른 건물의 충돌 상태는 공사 중 바뀌지 않습니다. [제안값: 플레이 단절 방지]
- 완료 시 영주관 스프라이트·건설 메뉴·연구 해금·등급 UI를 **동일 틱에 갱신**하고 완료 알림 1회 출력. 시뮬레이션 일시정지는 공사 시간에 포함하지 않습니다.
- 승급 시작 시 요구 조건을 충족한 것으로 확정하고, 공사 중 인구가 감소해도 승급이 자동 취소되지는 않도록 합니다. 영주관이 파괴될 경우 별도 파괴 규칙에 따라 공사를 중지합니다. [제안값]
- 저장 파일에 `promotion_target_rank`, `promotion_remaining_ticks`, `promotion_state` 저장. 12/24게임시간 지점 저장/불러오기 후 시간이 다시 24시간이 되면 안 됩니다. 과거 세이브의 영주관 공간 확장이 다른 건물을 침범한다면 **건물을 소리 없이 삭제하지 말고** 호환 처리하거나 구버전 로딩을 제한하고 이유를 표시합니다.

## 7. 자동 플레이 로그·검증·성능 [확정: 개선 요구 / 제안값: 목표와 형식]

### 7.1 장기 QA 계측

- 최소 `3난이도 × 48시드 × 200일`을 동일 조건으로 재실행하고, **각 일자 종료 시** 다음을 CSV로 기록합니다: `seed, difficulty, day, year, rank, promotion_state, permanent_pop, contract_pop, births_or_immigrants, deaths, departures, avg_happiness, avg_mood, food, gold, wood, coal, valid_roads, protected_area, protected_pop_pct, completed_research, current_raid, fps_or_cpu_ms`.
- 이주 판정 별도 이벤트 로그: `last_immigration_day, cooldown_remaining, eligible, rejected_reason[], group_size, arrival_type(special/refill/normal)`; 사망 후 개척지 복구 완료 일수 확인.
- **승급 실패 조건을 매일 개별 기록**: 인구 부족 인원, 행복도 부족 점수, 도로 부족 길이, 보호면적 부족 칸, 보호인구율 부족 비율, 연구 부족 개수, 공물/자원 부족 수량, 건물 필수요건. `no_progress_days`도 추적합니다.
- 통과 기준 [제안값]: **보통 난이도**에서 200일 기준 적어도 **24/48 시드가 왕성 도달**할 것을 초기 목표로 삼고, 평화 난이도는 **36/48**, 혹독은 **8/48 이상**을 기준으로 시험합니다. 이는 **봇 성능을 포함한 설계 목표**로 플레이어 난이도나 달성 보장을 의미하지 않으며, 실패 원인을 봇/시스템/밸런스로 분리합니다.
- 자동 플레이 AI가 성벽을 25→120→300→600칸으로 확장하고 주민의 보호 비율·연구·이주 조건을 달성하도록 의사결정 전략을 개선합니다. 단, 테스트 중 자원/주민 임의 생성·승급 조건 무시 금지.

- 종 수 증가로 인한 맵/동물/길찾기 부하 대응. 192×192 맵에서 **주민 150명·적 40명·야생동물 300마리** 기준: 워밍업 120프레임 제외 후 600프레임 측정하여 **평균 프레임 시간 ≤16.67ms, p95 ≤20ms, p99 ≤33.3ms**를 1차 목표로 합니다. [제안값; 장비별 프로파일 필수]
- 먼 지역 동물은 **일일 개체군 수치/저빈도 AI 갱신**, 화면·주민·경비 근처 동물만 이동·경로탐색·공격을 정밀 계산합니다. 멀리 있는 동물도 실제 사망·사료·개체수 등의 결정성을 유지합니다.
- 수영·공격 스프라이트는 **아틀라스 배치 및 배치 렌더링**, 사망 후 잔상은 **풀 또는 경량 리스트 재사용**, 짧은 체력바는 피해 입은 대상만 렌더링. 시야/도로/보호구역은 변화가 있을 때만 재계산하고 전체 맵을 매 프레임 순회하지 않습니다.
- `CTR`/프로파일로 `AI, pathfinding, visibility, render, sprite batch, simulation` 비용을 분리 측정하고 개선 전후 같은 환경에서 수치 비교합니다.
