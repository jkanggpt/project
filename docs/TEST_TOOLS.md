# 창작 도구

메인 화면의 **창작 도구**에서 검사할 영지를 만들거나 최근 테스트 저장을 불러옵니다. **최근 일반 저장을 복사해서 시험하기**로 실제 영지를 원본 변경 없이 시험할 수도 있습니다. 새 난이도·게임 모드를 추가하지 않고 일반 세계에 실행 중 검사 설정을 붙입니다. 이름·시드·기존 난이도를 고를 수 있습니다. 기존 그림과 렌더러를 그대로 사용합니다.

영지 안에서는 **F10**, 왼쪽 위의 **창작 도구 열기**, 일시정지 메뉴의 **창작 도구**로 다시 엽니다. 창이 열린 동안 시뮬레이션은 멈춥니다. 뒤쪽 HUD·지도 입력과 습격 경보가 창의 조작을 가리지 않습니다.

## 조절할 수 있는 것

| 창 | 조작 |
|---|---|
| 자원 | 금화·마정석을 포함한 15개 자원의 정확한 수량 지정, 자원 채우기, 계속 보충하기 |
| 시간·날씨 | 정지, 1·3·12·30·60배속, 실제 시뮬레이션 10분·1시간 진행, 날짜·시각 바로 지정, 새벽·아침·정오·저녁·밤·심야, 계절 이동, 자연 날씨 또는 맑음·비·눈·폭풍 고정 |
| 건설·진행 | 건설 비용 면제, 즉시 완공, 건물 등급·도로 연결 제한 해제, 진행 중인 모든 공사 완공, 전체 연구 완료, 여섯 영지 등급 직접 지정 |
| 주민·전투 | 주민 욕구·건강 유지, 주민 수 1~300명 지정, 주민 치료·건물 수리·패배 복구, 자연 습격 정지, 도적·마물·적대 영주의 습격 1~64명 생성, 진입 방향 지정, 현재 습격 종료 |
| 세계·저장 | 지도 전체 시야, 테스트 슬롯 저장·불러오기, 같은 설정으로 새 테스트 영지 생성 |

새 테스트 영지에는 금화 10,000과 마정석 100을 지급합니다. 비용 면제·즉시 완공·등급/도로 제한 해제·전체 시야·자연 습격 정지·주민 욕구/건강 유지를 켜서 시작합니다. 각 설정은 개별로 끌 수 있습니다. 자원 계속 보충과 날씨 고정은 기본으로 끕니다.

자원 지정은 현재 자원별 저장 한도를 지키며 범위 밖 입력은 적용하지 않습니다. 채우기·계속 보충하기는 저장 자원을 해당 한도까지, 화폐를 최대 100,000까지 채웁니다. 더 큰 금화 수량은 직접 지정할 수 있습니다. 비용 면제는 건설에만 적용합니다. 연구·거래·유지비를 포함한 다른 소비는 기존 규칙을 사용합니다.

날짜·시각 바로 이동은 **10분 단위로 앞으로만** 옮기며, 건너뛴 동안의 생산·소비·결산은 실행하지 않습니다. 앞선 시각 단추를 고르면 다음 날로, 이미 지난 계절 단추를 고르면 다음 해의 해당 계절로 이동합니다. 실제 진행을 검증할 때는 배속 또는 10분·1시간 진행 단추를 씁니다. HUD의 배속 표시에도 실제 배율을 반영합니다.

주민 수를 늘려도 주택·일터는 자동으로 만들지 않습니다. 욕구·건강 유지는 살아 있는 주민을 매 틱 회복시키며 전투 피해 자체를 무효화하지 않습니다. 건물 잠금 해제를 켜도 점유·문·지형·고유 시설 수 제한은 지킵니다. 전체 시야로 탐험한 기록은 해당 테스트 세계에 남습니다. 자연 습격 정지는 수동으로 만든 습격을 막지 않습니다.

## 일반 게임·저장과의 경계

- 일반 저장: 기존 저장 폴더의 `autosave.sav`, `slot1.sav`~`slot3.sav`.
- 테스트 저장: 그 폴더 안 `test-tools/`의 같은 슬롯 이름. 자동 저장도 이 폴더만 사용합니다.
- 메인 화면의 일반 이어하기·불러오기는 테스트 폴더를 읽지 않습니다. 테스트 이어하기와 예비 파일 복구도 테스트 폴더를 끝까지 유지합니다.
- 일반 저장 복사는 원본을 읽기만 하고, 복사한 영지의 이후 저장·자동 저장은 테스트 폴더에만 씁니다.
- 검사 설정은 저장 파일·상태 해시에 넣지 않습니다. 저장 형식·난이도 열거형·기존 공개 구조체를 바꾸지 않습니다. 추가 API는 `core/include/castle_test_tools.h`에 둡니다.
- 테스트 저장을 도구로 불러오면 저장한 자원·건물·주민·날짜는 유지하고 검사 설정만 기본값으로 다시 켭니다. 일반 새 게임·불러오기·튜토리얼 진입에는 검사 설정이 남지 않습니다.
- 튜토리얼 단추는 계속 `game_tutorial_start(app)`를 호출합니다.

## 검증

`tests/test_tools.c`는 비활성 세계의 명령 거절과 상태 해시 일치, 자원 경계값·실패 시 원상 유지, 무료/즉시 건설과 점유 검사, 연구·등급 변경, 시각 경계값, 날씨 고정, 주민 증감, 수동 습격과 종료, 저장 왕복 후 검사 설정 제거를 확인합니다. 실제 `GameSession`에서 주민 4↔30명과 저장/새 세계 전환을 다섯 번 반복합니다.

그래픽 반복 검사는 일반 저장의 상태 해시를 기억하고 테스트 생성 → 자원·시간·날씨·주민·습격 변경 → 테스트 저장·불러오기 → 손상된 원본의 예비 파일 복구 → 일반 불러오기 → 튜토리얼 → 제목을 반복합니다. 매 회 GPU 캐시·자원 개수를 대조하고 종료 후 남은 GPU 자원이 없는지 확인합니다. 기본 출력 폴더는 자동 검사 전용이며, 명시한 `--save-dir` 안에서도 `tools-check/` 하위 폴더만 사용합니다.

```sh
cmake --preset linux-release -DCASTLE_WERROR=ON -DCASTLE_GPU_TESTS=ON
cmake --build --preset linux-release
ctest --preset linux-release --output-on-failure
build/linux-release/bin/castle_game --test-tools-check 5 --no-audio --width 800 --height 600
```

화면 자동 촬영은 기존 `title|tutorial|game`을 유지하며 `tools_setup|tools|tools_time|tools_build|tools_people|tools_world`를 추가합니다. 예:

```sh
build/linux-release/bin/castle_game --screenshot build/reports/tools.png --screen tools --width 800 --height 600 --no-audio
```

Windows 전체 검사는 CI의 기존 MSVC 작업에서 `cmake --preset windows-msvc -DCASTLE_WERROR=ON`, 전체 빌드, `ctest --preset windows-msvc`, 설치·패키지를 실행합니다. 검사 코드는 Windows에서도 빌드·실행하며 GPU 창 반복 검사는 `CASTLE_GPU_TESTS=ON`인 환경에서 추가로 등록합니다.

확인한 결과:

- Linux 릴리스 `CASTLE_WERROR=ON`: 292/292 통과. 그림을 수정하지 않아 로컬 전체 반복에서 아트 재생성·재현성 두 검사는 제외했으며, 기존 Windows 전체 CI는 이 검사도 실행합니다.
- ASan·UBSan·LeakSanitizer: 새 코어/실행 계층 검사 4/4 통과. 그래픽 전환 5회·120프레임에서 일반 슬롯 해시 보존·테스트 저장 복구·일반 저장 복사·튜토리얼 전환 확인, 응용 프로그램 누수/오류 없음. 알려진 Mesa 드라이버 종료 시 할당만 기존 `libGLX_mesa.so.0` 억제 규칙으로 분리했습니다.
- 다섯 회 모두 GPU 객체 67개, 재료 쌍 11개·59,887,616바이트로 일정하며 종료 뒤 남은 GPU 자원 0. 마지막 한글·공백 경로 검사와 플레이 화면 도구 단추의 지도 클릭 차단도 통과했습니다.
- 제목과 창작 도구: 800×600·1024×768·1440×900·1920×1080 촬영. 800×600에서 설정 창과 다섯 탭을 모두 확인했고 기존 게임·튜토리얼 촬영도 통과했습니다.
- 정본 감사: 1,825파일·런타임 자산 1,128개·제작 입력 338개, 오류 0. 아트·매니페스트·저장 스키마·튜토리얼 구현·CI 파일은 수정하지 않았습니다.
