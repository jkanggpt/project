# 기존 픽셀 원화 조명 비교

첫 기하 표본은 실제 게임의 화풍과 달랐고 큰 그림자가 종이처럼 보였습니다. 현재 비교는 기존 게임의 2D 스프라이트를 직접 사용합니다. 오두막, 참나무, 갈색 머리 주민, 잔디, 돌길, 바위의 원본 선화와 실루엣을 유지합니다. 화면은 원화가 그려진 2D 평면이며 입체 모델을 표시하지 않습니다.

## 원화와 조명 자료

`art/sources/lighting_pixels/originals.png`는 기존 실행 자산을 정확한 셀에서 추출한 비교 시트입니다. 확대에는 가까운 이웃 필터만 사용합니다. 추출 경로·영역·배율은 `art/recipes/pixel_lighting.json`에 있습니다.

image_gen의 두 출력은 명암 완화와 세부 법선의 지침입니다. 생성한 새 그림의 색 픽셀로 원본을 교체하지 않습니다. 명암 완화 결과는 원본 RGB에 같은 색상 계열의 국소 평균 밝기 보정만 곱합니다. 보정 범위를 제한하고 채널 포화를 막아 원본의 색 비율과 세부 픽셀 대비를 유지합니다. 출력 알파는 원본과 완전히 같습니다. 원본의 미세한 회화 명암까지 모두 제거한 물리 반사율 자료로 주장하지 않습니다.

법선은 지침을 원본 픽셀 격자로 표본화한 뒤 지면·지붕·벽·인물의 표면 축으로 변환합니다. 바닥은 월드 +Z를 향하고 앞 벽은 +Y를 향합니다. 지붕의 기와 턱, 모르타르, 나무껍질·잎, 천 주름과 바위 모서리의 작은 방향 차이를 남깁니다. AI 지침은 실측 자료가 아니며 내부 세부 정합에는 수동 검수가 필요합니다.

| 출력 | 구성 |
|---|---|
| `pixel_albedo.png` | 원본 색·선화에 제한한 밝기 보정 적용 |
| `pixel_normals.png` | RGB = 월드 +X, +Y, +Z, 원본 알파 유지 |
| `pixel_surface.png` | RG = 높이 정수·소수, B = 등불·창문 발광 구분, A = 재질 번호 1~6 |

세 출력은 960×640, 3열×2행입니다. 제작 입력 3개와 실행 출력 3개를 두 매니페스트에 등록했습니다. GPU 풀·연기 마스크를 포함한 현재 전체 입력은 335개, 실행 자산은 419개이며 생성 요청 전문·SHA256·권리는 provenance.json과 CREDITS.md에 연결했습니다.

## 표현

비교 지도는 원본 스프라이트만 가까운 이웃 필터로 겹친 고정 2D 장면입니다. 색·법선·높이 자료를 같은 픽셀 위치에 둡니다. 별도의 큰 도형으로 그림을 다시 그리지 않습니다.

건물 2채, 주민 2명, 나무와 바위에 큰 그림자가 있습니다. 주민·나무·바위에는 타원체 차폐 영역을 사용하고 나무는 수관과 줄기 영역을 합칩니다. 건물에는 직육면체 벽, 경사진 지붕과 굴뚝을 별도로 둡니다. 화면에 보이는 것은 계속 원래의 2D 스프라이트이며 차폐 영역은 그리지 않습니다. 원화 알파를 길게 늘리지 않습니다. 그림자 경계는 8단계 음영과 작은 디더로 표현합니다.

### 건물의 모서리와 지붕

건물 밑면은 화면의 발밑 선을 앞쪽으로 잡고 깊이를 화면 위쪽으로 둡니다. 벽은 직사각형 밑면의 상자이며 지붕은 가로 용마루를 가진 삼각기둥입니다. 굴뚝은 높은 작은 상자입니다. 큰 건물의 벽 너비·깊이·높이는 108·36·80, 지붕 용마루와 굴뚝 꼭대기 높이는 130·148입니다. 작은 건물은 벽 64·22·48, 용마루 78, 굴뚝 꼭대기 94입니다. 단위는 시험 지도의 논리 픽셀입니다. 원화에서 보이는 발밑·처마·지붕 선을 기준으로 맞춘 근사치입니다.

빛을 향한 광선과 각 볼록 입체의 평면을 교차 검사합니다. 벽·지붕·굴뚝의 그림자를 합치므로 상자의 직선과 모서리가 남고 용마루나 굴뚝은 더 긴 부분을 만듭니다. 건물 전체를 둥근 영역 하나로 대체할 때 생기던 타원형 외곽을 제거했습니다. 평면을 ±1.25픽셀 확장·축소해 경계의 중간 음영을 구합니다. 발밑의 주변광 음영도 건물의 직사각형 밑면을 따릅니다.

지면 높이가 0인 태양 그림자는 꼭짓점 `P`를 `P.xy - P.z × sun.xy / sun.z`로 투영한 외곽과 같습니다. 점광원 `L`이 모든 꼭짓점보다 높으면 `L.xy + (P.xy - L.xy) × L.z / (L.z - P.z)`로 비교할 수 있습니다. 검증은 이 꼭짓점 투영으로 독립적인 볼록 다각형을 만든 뒤 실제 광선 교차 결과와 비교합니다. 실제 광선 계산은 낮은 점광원과 수신 높이도 포함하므로 다른 물체 표면까지 차폐할 수 있습니다.

수신 픽셀의 월드 위치는 `(화면 X, 화면 Y + 높이 × 0.9, 높이)`로 복원합니다. 여기서 태양이나 점광원으로 향하는 광선이 차폐 영역을 지나는지 검사합니다. 낮은 태양은 긴 그림자를 만들고 이동광은 반대 방향으로 그림자를 옮깁니다. 지면뿐 아니라 다른 스프라이트의 높은 표면도 그림자를 받습니다. 법선은 기와·돌·천 같은 미세 표면의 명암을 맡고, 큰 그림자는 높이와 차폐 영역이 맡습니다.

그림자는 해당 광원의 직접광과 반사광만 줄입니다. 주변광과 다른 광원은 남기고 발밑의 작은 접지 음영은 주변광에 적용합니다. 겹친 차폐 영역은 가장 강한 음영을 선택해 불필요하게 검게 누적하지 않습니다. 임시 `owners.png`는 수신 픽셀의 물체 번호를 보관해 자기 차폐 영역을 제외합니다. 건물 등불도 소속 건물 영역을 제외하며 이동광이 영역 내부로 들어가면 그 영역을 건너뜁니다.

이는 크기·높이를 수동으로 맞춘 차폐 근사입니다. 문·창문 구멍, 작은 지붕창, 잎 사이 구멍의 정확한 차폐나 자체 그림자를 재현하지 않습니다. 원화·명암 완화·법선·높이·재질의 기존 장면 버퍼 5개는 건물 변경 전과 SHA256이 모두 같습니다. 소유 번호와 차폐 영역은 시험 장면을 내보낼 때만 생성하는 자료이며 새 아트 자산을 추가하지 않았습니다.

표면 조명도 제한한 밝기 단계와 작은 하이라이트를 씁니다. `미세 표면`을 0으로 내리면 세부 법선의 영향이 줄어들고, 값을 올리면 같은 원화의 기와·돌·잎 표면이 움직이는 빛에 더 강하게 반응합니다. 낮의 등불과 창문 발광은 약하게 해 원본 색이 과하게 날아가지 않게 했습니다.

## 조작

| 조작 | 확인할 내용 |
|---|---|
| 비교 → 기존 원화 | 손대지 않은 원본 픽셀 |
| 비교 → 명암 완화 | 원본 선화·색 관계를 유지한 제한적 명암 보정 |
| 비교 → 재조명 / 표면 노멀 | 조명 결과 / 실제 사용한 법선 |
| 질감 조명 | 낮은 각도로 표면을 보는 이동광 설정 |
| 확대 → 기와 2배 | 보간 없이 지붕의 픽셀 표면 확대 |
| 미세 표면 | 원화는 유지하며 세부 법선 강도만 변경 |
| 지도 드래그 | 이동광 배치. 확대 상태에서도 같은 원화 위치에 대응 |
| 낮 / 저녁, 태양 방향·고도 | 태양 반대 방향의 큰 그림자, 낮은 고도의 긴 그림자 |
| 등불 / 창문 / 그림자 | 발광·국소 조명·큰 그림자와 접지 음영 비교 |

장면과 인물은 고정되어 있습니다. 이 화면은 아트와 조명 반응을 비교하는 소프트웨어 시각 실험이며, 실제 게임의 렌더러나 저장·규칙·튜토리얼을 교체하지 않습니다. 원격 Desktop 메뉴가 없는 클라이언트에서도 대화 안에서 조작할 수 있습니다.

## 재현과 검증

```sh
cmake --preset linux-release -DCASTLE_WERROR=ON
cmake --build --preset linux-release
./build/linux-release/bin/castle_pixel_lighting --check .
./build/linux-release/bin/castle_pixel_lighting --scene . build/reports/lighting-prototype/pixel-scene
python3 tools/lighting_lab/pixel_preview.py build/reports/lighting-prototype/pixel-scene /workspace/pixel-lighting-preview/house-shadows.html
ctest --preset linux-release -R '^(assets_|lighting_|pixel_lighting_)' --output-on-failure
```

- GCC Release의 전체 빌드가 `CASTLE_WERROR=ON`으로 통과했습니다. 공통 조명 검증에서 전체 CTest 280개를 통과했고, 건물 차폐 변경 후에는 관련 조명·자료 검사 4개를 다시 통과했습니다.
- `assets_runtime`, `assets_regenerate`, `assets_reproducible`, 기존 조명 자료 2개 검사, `pixel_lighting_data`가 통과했습니다.
- Node.js가 있으면 `pixel_lighting_shadows`도 CTest에 등록됩니다. 태양 방향 반전, 낮은 고도의 긴 그림자, 높은 수신 표면, 자기 물체 제외, 점광원 이동·소속 건물 제외, 부드러운 경계와 길이가 없는 광선을 검사합니다. 건물 검사는 상자 모서리, 용마루·굴뚝의 긴 부분과 광원 뒤 물체 제외를 포함합니다. 벽·지붕의 독립적인 꼭짓점 투영과 광선 교차는 17,656개 수신 위치에서 일치했습니다.
- 6종 원화의 알파는 출력 알파와 정확히 같고, 색 비율은 채널당 반올림 오차 안에서 유지됩니다. 법선 길이·재질 구분·바닥의 +Z 방향·세부 방향 분산을 검사했습니다.
- 비교 화면의 `기존 원화`와 `명암 완화` 모드는 입력 장면의 RGB와 정확히 일치합니다.
- 기와 영역의 세부 법선을 켰을 때 평균 RGB 변화는 약 5.36/255, 이동광을 반대편으로 옮겼을 때는 약 24.37/255였습니다. 같은 원화의 표면이 빛에 반응함을 확인하는 값이며 물리 조도 단위가 아닙니다.
- 태양 방향 225°·고도 40°인 기준 장면에서 지면 21,064픽셀의 RGB 합이 그림자를 끈 경우보다 10% 이상 줄었고, 가장 어두운 지면도 약 60.2%의 밝기를 유지했습니다. 다른 스프라이트의 1,377픽셀도 5% 이상 줄었습니다. 이 값은 장면 비교이며 물리 조도 단위가 아닙니다.
- 물체별 차폐 영역만 따로 켜서 6개 물체 모두 지면에 그림자를 만드는지도 검사했습니다. 주민 두 명의 개별 그림자는 각각 314픽셀과 269픽셀의 밝기를 5% 이상 줄였습니다.
- 그림자를 끄면 낮·점광원·야간 설정 3종의 결과가 이전에 승인한 질감 조명과 바이트 단위로 같습니다. 원화 비교와 명암 완화 비교도 입력 장면과 정확히 같습니다.
- 건물 차폐 영역을 제외한 비교에서는 낮·높은 태양·이동광 설정의 작은 물체 그림자와 표면 조명도 이전 결과와 바이트 단위로 같습니다.
- 실제 대화 미리보기에서 낮과 저녁의 큰 그림자, 그림자 전환과 이동광을 확인했습니다. 결과는 소프트웨어 미리보기 성능이며 실제 GPU 성능 검증으로 일반화하지 않습니다.

브라우저 비교 출력은 약 0.83MB이며 외부 API 호출 없이 원화 자료와 계산을 화면 안에 포함합니다. 이후 같은 원화 자료를 공용 OpenGL 4.3 GPU 렌더러와 실제 게임에 연결했습니다. 새 실행 방법·움직임·검사 결과와 MSVC/노트북의 미확인 항목은 [GPU_SCENERY.md](GPU_SCENERY.md)에 기록합니다. 원격 푸시나 PR 생성은 하지 않았습니다.
