# C 코드 따라 읽기 (C_WALKTHROUGH)

선생님 질의응답을 준비하기 위한 설명서입니다. 모듈마다 **무엇을 하는지, 핵심 구조체, 데이터의 메모리 수명, 까다로운 부분**을 적었습니다.
마지막에 예상 질문 20개와 짧은 답이 있습니다. (지금: 마일스톤 2 기준 — 주민·건물·경제까지)

읽는 순서 추천: `castle_core.h` → `world.h/.c` → `entity.h/.c` → `placement.c` → `villager_ai.c` → `jobs.c` → `save.c` → `api.c` → 나머지.

---

## 공개 헤더 `core/include/castle_core.h`

- **하는 일**: Godot 과 CLI 가 볼 수 있는 유일한 헤더. 결과 코드, 열거형, 뷰 구조체, 함수 선언.
- **핵심**: `CoreWorld` 는 `typedef struct CoreWorld CoreWorld;` 로 **이름만** 알려 줍니다(불투명 타입). 밖에서는 안의 필드를 볼 수 없고 포인터로만 다룹니다.
- **뷰 구조체**(`CoreSummaryView` 등)는 `int32_t` 와 고정 크기 `char` 배열만 씁니다. 그래야 C# 이 같은 모양의 구조체로 그대로 받을 수 있습니다(크기·순서가 컴파일러마다 같음).
- **`CORE_API`**: Windows DLL 에서 함수를 밖으로 내보내는 `__declspec(dllexport)` 를 감추는 매크로.

## `world.h` / `world.c` — 월드

- **하는 일**: 게임 상태 전체를 담는 `struct CoreWorld` 를 만들고, 없애고, 시간을 진행합니다.
- **구조체**: `World` 는 `Clock`, `Rng`, `ResourceBank`, `Ledger`, `Grid`, `EventQueue`, `Defs` 를 **값으로 포함**하고, 주민·건물은 `Villager **villagers`, `Building **buildings` **포인터 배열**로 소유합니다. 전역 변수 없이 상태가 모두 여기 있으므로 월드를 둘 만들어도 서로 섞이지 않습니다(테스트가 실제로 그렇게 함).
- **메모리 수명**:
  1. `world_alloc` 이 `mem_calloc` 으로 월드를 0 으로 채워 할당하고, 이벤트 큐를 초기화합니다.
  2. `world_create` 가 지도 격자를 할당(`grid_alloc`)하고 지형을 만듭니다(`grid_generate`).
  3. 중간에 하나라도 실패하면 `world_destroy` 로 **지금까지 할당한 것을 모두** 해제하고 오류 코드를 돌려줍니다.
  4. `world_destroy` 는 격자 → 이벤트 큐 → 월드 순서로 해제합니다. NULL 이어도 안전합니다.
- **까다로운 부분**:
  - `world_name_is_valid`: 성채 이름은 플레이어가 입력한 UTF-8 문자열입니다. 잘린 글자, 너무 긴 표현(overlong), 서로게이트, 줄바꿈 같은 제어 문자를 거부합니다. 줄바꿈을 막는 이유는 세이브 파일이 "한 줄에 값 하나" 형식이기 때문입니다.
  - `world_state_hash`: 저장되는 모든 값을 FNV-1a 로 섞은 64비트 값. 저장 → 불러오기 후 같아야 하므로 "빠뜨리고 저장한 필드"를 잡아냅니다. 정수는 한 바이트씩 넣어 CPU 의 바이트 순서와 상관없이 같은 값이 나오게 했습니다.
  - `world_step`: 한 틱 = 10분. 자정이면 `DAY_STARTED`, 계절 첫날이면 `SEASON_CHANGED`, 21:00 에 `NIGHT_FELL`, 05:00 에 `DAWN` 이벤트를 넣습니다. 그다음 건설을 한 틱 진행하고(`placement_tick`), 주민마다 `vil_tick` 을 부르고, 06:00 에는 하루 결산(`daily`: 장부 넘기기 → 임금·세금 → 이주 → 일자리 다시 배치)을 합니다.
  - **주민 목록을 뒤에서부터 도는 이유**: `vil_tick` 안에서 주민이 죽거나 떠나면 `swap-remove`(마지막 원소를 빈자리로 옮김)로 목록에서 빠집니다. 앞에서부터 돌면 옮겨 온 주민을 건너뛰지만, 뒤에서부터 돌면 옮겨 온 주민은 이미 처리한 주민이라 안전합니다.

## `clock.h` / `clock.c` — 게임 속 시간

- **하는 일**: 총 틱 수 하나(`Clock.tick`)에서 날짜, 시각, 계절, 연도를 계산합니다.
- **왜 이렇게**: 날짜·시각·계절을 따로 저장하면 서로 어긋날 수 있습니다. 값이 하나뿐이면 어긋날 수가 없습니다.
- **까다로운 부분**: 밤은 자정을 넘어가므로(21:00~05:00) `clock_is_night_minute` 은 두 구간을 `||` 로 봅니다.

## `rng.h` / `rng.c` — 난수 (PCG32)

- **하는 일**: 같은 시드면 언제나 같은 수열을 내는 난수 생성기.
- **왜 `rand()` 가 아닌가**: `rand()` 는 전역 상태를 쓰고, 운영체제마다 알고리즘이 달라 Windows 와 Linux 에서 다른 지도가 나옵니다. PCG32 는 상태(`state`, `inc`)를 월드 안에 두고 세이브에도 저장하므로, 불러온 뒤에도 같은 미래가 이어집니다.
- **까다로운 부분**: `rng_range` 는 `r % span` 의 치우침(작은 수가 조금 더 자주 나옴)을 없애려고, 나누어떨어지지 않는 구간의 값은 다시 뽑습니다.

## `grid.h` / `grid.c` — 지도와 지형 생성

- **하는 일**: 96×96 지형 격자와 이동 비용 격자를 가지고, 시드로 지형을 만듭니다.
- **구조체**: `Grid { width, height, uint8_t *terrain, uint8_t *cost, cost_rev }`. 2차원 지도를 **1차원 배열**에 `index = y * width + x` 로 담습니다. 한 번에 할당·해제할 수 있고 C# 으로 통째로 복사하기 쉽습니다.
- **메모리 수명**: `grid_alloc` 에서 `calloc` 두 번 → `grid_free` 에서 해제. 하나만 성공하고 하나가 실패하면 둘 다 해제하고 0 으로 돌려놓습니다.
- **생성 순서** (`grid_generate`):
  1. 노이즈 세 장(숲, 바위, 물)을 만들고 각각 **상위 몇 %** 칸을 칠합니다(`paint_top_percent`). 퍼센트로 정하기 때문에 시드가 달라도 숲이 하나도 없는 지도는 나오지 않습니다.
  2. 마정석 광맥 덩어리를 흩뿌립니다(`scatter_mana`).
  3. 성채 자리를 비웁니다(`clear_keep_area`).
  4. **연결성**(`ensure_connectivity`): 성채에서 너비 우선 탐색(BFS)을 해서, 네 변 중 닿지 않는 변이 있으면 땅길을 냅니다. 그래도 닿지 않는 땅(호수에 갇힌 섬)은 물로 바꿉니다. 나중에 적은 가장자리에서 오고 주민은 가장자리로 떠나므로 반드시 필요합니다.
  5. **공정한 시작**(`ensure_fair_start`): 성채 반지름 14칸 안에 숲 30, 바위 10, 광맥 3칸이 없으면 덩어리를 찍어 채웁니다. 규칙은 `FAIR_RULES[]` 표에 있습니다.
- **까다로운 부분**:
  - 노이즈를 **정수(고정소수점)로만** 계산합니다. 실수 계산은 컴파일러·CPU 에 따라 마지막 비트가 달라질 수 있어, 같은 시드가 다른 지도를 만들 위험이 있기 때문입니다.
  - 노이즈 층마다 격자를 조금씩 밀어 둡니다(`fractal_noise`). 그러지 않으면 모든 층의 격자선이 겹쳐 지형 가장자리가 반듯한 직선이 됩니다.
  - BFS 대기열은 칸 수만큼 `malloc` 합니다. 칸마다 많아야 한 번 들어가므로 넘칠 수 없습니다.

## `economy.h` / `economy.c` — 자원 은행과 장부

- **하는 일**: 금화, 마정석, 식량, 목재, 석재, 약초 6가지 자원과 저장 한도, 그리고 **장부**(`Ledger`: 자원 × 항목(생산, 소비, 임금, 세금, 건설, 철거 환불 …) × 오늘/어제).
- **규칙**: 금화·마정석은 화폐라서 한도가 없고, 물건 4가지는 성채(300)와 창고(200씩)가 정하는 한도를 넘지 못합니다.
- **`eco_change(bank, ledger, 자원, 양, 항목)`**: 자원을 바꾸고 **실제로 바뀐 양**을 장부에 적습니다(한도에 막혀 버려진 양은 적지 않음). 모든 자원 변화가 이 함수를 거치므로 HUD 의 "어제 하루 변화"가 정확합니다.
- **까다로운 부분**: `eco_bank_add` 는 `int64_t` 로 더한 뒤 0 과 한도 사이로 자릅니다(int32 넘침 방지). `eco_bank_spend` 는 **전부 낼 수 있을 때만** 뺍니다(일부만 빠지는 일이 없음).

## `events.h` / `events.c` — 피드백 이벤트 큐

- **하는 일**: "밤이 되었습니다" 같은 알림·소리용 이벤트를 쌓아 두었다가 Godot 이 꺼내 갑니다.
- **구조체**: `Event` 는 `type` 에 따라 공용체 `as` 의 다른 칸(`day`, `season`, `warning`)을 씁니다(**태그 붙은 공용체**). 이벤트마다 필요한 값이 달라도 크기는 하나로 같습니다.
- **메모리 수명**: `events_init` 에서 32칸 → 꽉 차면 `grow` 가 `realloc` 으로 두 배 → 최대 4096칸. 그 이상이면 가장 오래된 것을 버리고 개수를 셉니다. 꺼낼 때 "N개를 버렸다"는 경고 이벤트를 먼저 줍니다.
- **까다로운 부분**: 원형 버퍼를 `realloc` 으로 키우면, 끝에서 앞으로 감겨 있던 부분을 새로 생긴 뒤쪽 공간으로 옮겨야 순서가 이어집니다(`grow` 의 `memcpy`).
- **왜 버려도 되나**: Godot 은 상태를 이벤트가 아니라 매 틱 스냅숏으로 맞춥니다. 이벤트는 보여 주기용이라 놓쳐도 게임이 어긋나지 않습니다.

## `save.h` / `save.c` — 저장과 불러오기

- **형식**: 사람이 읽을 수 있는 텍스트. 첫 줄 `MAGICCASTLE_SAVE 1`, 그 뒤 `[meta]`, `[clock]`, `[rng]`, `[resources]`, `[map]`, `[end]`. 지도는 한 칸 한 글자(`.` 풀밭, `T` 숲, `^` 바위, `~` 물, `*` 광맥).
- **쓰기** (`save_write`): ① 불변 조건을 어긴 월드는 저장하지 않음(멀쩡한 예전 세이브를 덮지 않게) ② `<경로>.tmp` 에 씀 ③ 예전 세이브를 `<경로>.bak` 으로 복사 ④ `.tmp` 를 본 파일로 **한 번에 바꿔치기**. 쓰는 도중 꺼져도 예전 파일이나 새 파일 중 하나는 온전합니다.
- **읽기** (`save_read`): 한 줄씩 읽어(`read_line`, 버퍼를 `realloc` 으로 키움) `[섹션]` 이름에 맞는 해석 함수로 보냅니다(**함수 포인터 표 `SECTIONS[]`**). 모든 숫자는 범위를 검사하고, 같은 키가 두 번 나오거나 모르는 키가 있으면 거부합니다. 끝에 `[end]` 가 없으면 잘린 파일입니다. 마지막으로 불변 조건 검사기까지 통과해야 성공입니다.
- **메모리 수명**: 읽는 동안 새 월드를 만들고, **실패하면 반쯤 만든 월드를 통째로 해제**합니다. 호출한 쪽의 기존 월드는 건드리지 않으므로, 불러오기에 실패해도 하던 게임은 그대로입니다.
- **까다로운 부분**:
  - 바이너리 모드(`"wb"`, `"rb"`)로 열어 OS 마다 줄바꿈이 바뀌지 않게 하고, 읽을 때는 `\r\n` 도 받아 줍니다(메모장으로 열었다 저장한 경우).
  - 비용 격자는 지형에서 계산되는 값이라 저장하지 않고 불러온 뒤 다시 계산합니다.
  - 줄 길이 상한(4096)으로, 망가진 파일이 메모리를 끝없이 쓰게 만들 수 없습니다.

## `defs.h` / `defs.c` / `defs_builtin.c` — 건물·특성·이름 정의

- **하는 일**: 건물 14종의 수치(크기, 비용, 일꾼 칸, 생산량, 임금 …), 성격 특성 10개, 주민 이름 목록을 `game/data/` 의 글 파일에서 읽습니다.
- **구조체**: `BuildingDef`(건물 하나), `TraitDef`, `NameEntry`, 그리고 이것들을 모은 `Defs`. 특성·이름 목록은 몇 줄일지 모르므로 `grow_array` 가 `realloc` 으로 늘립니다.
- **함수 포인터 표 두 개**: `SECTION_PARSERS[]` 는 `[building farm]` 같은 섹션 머리말의 종류 → (시작 함수, 필드 함수) 짝. `BUILDING_FIELDS[]` 는 `cost_wood = 20` 의 키 이름 → 구조체 안의 위치(`offsetof`)와 허용 범위. 그래서 필드를 하나 더하려면 표에 한 줄만 더합니다.
- **오류 처리**: 한 줄이라도 틀리면(모르는 키, 범위 밖 값, 숫자 아님) **그 파일 전체를 내장 기본값으로** 두고, 파일 번호와 줄 번호를 경고로 남깁니다. 새 게임을 만들 때 경고가 이벤트로 나와 Godot 알림·CLI 에 보입니다.
- **메모리 수명**: `Defs` 는 `core_defs_create` 로 만들고 `core_defs_destroy` 로 해제합니다. 월드는 만들 때 **복사본**을 가지므로, 정의 묶음을 먼저 해제해도 게임은 계속됩니다.

## `entity.h` / `entity.c` — 주민과 건물, 그리고 연결

- **구조체**: `Villager` 는 `Stats`(힘·지능·손재주·체력), `Needs`(배부름·기운·안전·집·건강)를 **포함**하고 `Building *home`, `Building *workplace`, `Building *target` 을 **참조**합니다. `Building` 은 `Villager **workers`, `Villager **residents` 동적 배열로 주민을 **참조**합니다.
- **연결 함수가 양쪽을 같이 바꿈**: `entity_link_worker(building, villager)` 는 건물 배열에 넣고(`insert_sorted`, id 순) 주민의 `workplace` 를 정합니다. `entity_unlink_worker(villager)` 는 반대로 둘 다 지웁니다. 다른 코드는 필드를 직접 바꾸지 않습니다.
- **지울 때 순서** (`entity_remove_building`): ① 이 건물을 가리키는 모든 주민의 포인터를 NULL 로 → ② 건물의 배열 해제 → ③ 월드 목록에서 빼기(`swap-remove`) → ④ 건물 해제. 이 순서라서 해제된 메모리를 가리키는 포인터(dangling pointer)가 남지 않습니다. 주민을 지울 때도 같은 원리(`entity_remove_villager`).
- **id**: 월드의 `next_villager_id`, `next_building_id` 가 1씩 늘고 저장됩니다. 지운 id 를 다시 쓰지 않으므로, Godot 이 늦게 보낸 보고가 다른 주민에게 잘못 가는 일이 없습니다.

## `placement.h` / `placement.c` — 배치, 건설, 철거, 도로

- **하는 일**: "여기 지을 수 있나?"(`placement_check`), 짓기(`placement_place`), 줄 놓기(`placement_line`, 도로·성벽), 철거(`placement_demolish`, 비용 절반 환불), 건설 진행(`placement_tick`).
- **같은 검사 함수**를 Godot 미리보기(`core_can_place`)와 실제 짓기가 함께 씁니다. 결과는 이유 코드(`CORE_PLACE_OCCUPIED`, `CANNOT_AFFORD`, `BLOCKS_PATH` …) 하나입니다.
- **까다로운 부분 — 길이 끊기는지**: 건물로 길을 막아 집이나 일터에 못 가게 되면 주민이 굶습니다. 그래서 짓기 전에 "성채 문에서 너비 우선 탐색(BFS)으로 닿는 문과 지도 가장자리"를 지금과 지은 뒤로 비교합니다(`check_paths`). 매번 지도 전체를 두 번 채우면 느려서, 먼저 **테두리 검사**(`ring_is_connected`)를 합니다: 발자국을 한 칸 둘러싼 테두리에서 걸을 수 있는 칸들이 한 줄로 이어져 있으면, 발자국을 지나던 길은 테두리를 따라 돌아가면 되므로 끊길 수 없습니다.
- **격자 층**: `occupant`(어느 건물이 차지했나), `door_count`(문 앞 칸), `block`, `road` 를 고친 뒤 `grid_rebuild_costs` 가 비용 격자를 다시 계산하고 `cost_rev` 를 올립니다.

## `villager_ai.h` / `villager_ai.c` — 주민의 하루

- **상태 기계**: `STATE_TABLE[state]` 함수 포인터 표. 상태마다 "지금 무엇을 할지"를 정하는 함수가 있습니다(`on_idle`, `on_sleep`, `on_go_work`, `on_working`, `on_eat`, `on_leaving` …). 공통 판단은 `decide`: 밤이면 집에서 잠, 배고프면 가장 가까운 저장 건물로, 근무 시간이면 일터로, 아니면 쉼.
- **의도와 `intent_rev`**: 주민이 어디로 갈지 바꿀 때 `vil_set_intent` 가 목표와 상태를 정하고 `intent_rev` 를 1 올립니다. Godot 은 그 rev 와 함께 도착을 보고하고, `vil_arrived` 는 rev 가 다르면 `CORE_IGNORED` 로 무시합니다. 걷는 사이에 마음이 바뀐 경우를 안전하게 처리하는 방법입니다.
- **안전장치**: 하루(144틱) 동안 도착 보고가 없으면 길이 없는 것으로 보고 `fall_back`(그 자리에서 3시간 기다림 + "길이 막혔습니다" 알림, 하루 한 번).
- **욕구와 기분**: `update_needs` 가 배부름·기운을 줄이고, `vil_mood_terms` 가 기분을 항목별(기본, 배고픔, 피로, 안전, 집, 성격, 임금, 슬픔)로 더해 목표 기분을 만듭니다. 실제 기분은 한 시간에 1 씩 목표를 따라갑니다. 항목별 값은 Godot 검사창의 기분 툴팁에 그대로 나옵니다.
- **굶주림**: 배부름이 0 이면 한 시간에 건강 1 이 줄고, 50 이 되면 죽기 전에 마을을 떠납니다.

## `jobs.h` / `jobs.c` — 일자리, 생산, 임금

- **`JOB_TABLE[건물 종류]`** 함수 포인터 표: `work_farm`(계절 %), `work_gatherer`(약초 + 식량 조금), `work_extract`(벌목장·채석장·광산: 주변 지형 칸 수로 생산성). 일 없는 건물은 `NULL`.
- **생산량은 천분율로 모읍니다**: 한 틱 생산이 0.08 식량처럼 작아서, 건물마다 `work_milli` 에 1000 분의 1 단위로 쌓았다가 1000 이 넘을 때 1 씩 창고에 넣습니다(정수만 써서 결정적).
- **배치**: `jobs_auto_assign` 은 놀고 있는 주민 중 그 일에 맞는 능력치가 높은 사람을 빈 일자리에 넣습니다(건물마다 "자동 배치"를 끌 수 있음). 플레이어가 직접 넣거나 뺀 주민은 `MANUAL` 표시가 붙어 자동 배치가 건드리지 않습니다.
- **임금과 세금**: 06:00 에 일꾼마다 건물의 `wage` 만큼 금화를 주고, 집 있는 주민마다 세금 2 를 받습니다. 금화가 모자라면 못 받은 주민의 기분이 떨어집니다.

## `population.h` / `population.c` — 첫 주민, 이주, 떠남, 죽음

- `population_create`: 이름(정의 파일의 목록에서 겹치지 않게), 나이, 능력치, 성격 2개를 난수로 정합니다.
- `population_daily`: 빈 집이 있고, 평균 기분 55 이상, 겨울이 아니고, 식량이 주민 × 5 이상이면 지도 가장자리에서 이주민 1~3 명이 걸어 들어옵니다.
- `population_begin_leaving`: 일터·집 연결을 끊고 가장자리로 걷게 합니다. 도착하면 `population_remove_departed` 가 목록에서 지웁니다.
- `population_kill`: 죽음 이벤트, 마을 전체에 슬픔(기분 −10, 최대 −30), 목록에서 지우기.

## `validate.h` / `validate.c` — 불변 조건 검사기

- **하는 일**: "항상 참이어야 하는 사실"을 모두 확인하고 어긴 개수를 돌려줍니다. 예: 자원 ≥ 0, 물건 ≤ 한도, 지형 값이 범위 안, 비용 격자가 지형·도로·건물과 일치, 난수 `inc` 가 홀수.
- **주민·건물 (`check_entities`)**: id 가 겹치지 않고 다음 id 보다 작음, 주민이 가리키는 일터의 `workers` 배열에 그 주민이 정확히 한 번 있음(반대 방향도), 일꾼 수 ≤ 칸 수, 점유 격자가 건물 발자국과 일치, 건설 진행도가 범위 안, 욕구·기분이 0~100.
- **쓰는 곳**: 테스트, CLI 소크 테스트(매 틱), Godot 스모크 테스트(매 프레임), 불러오기 마지막 단계, 저장 직전.
- **함수 포인터**: 위반을 찾을 때마다 부르는 `ValidateReportFn` 콜백을 받을 수 있습니다(테스트가 무엇이 틀렸는지 출력).

## `platform.h` / `platform.c` — 운영체제 차이 감추기

- **문제**: Windows 의 사용자 폴더 이름에 한글이 있으면, Godot 의 `user://` 경로도 한글을 포함합니다. 그런데 Windows 의 `fopen` 은 UTF-8 경로를 이해하지 못합니다. 또 Windows 의 `rename` 은 대상 파일이 있으면 실패합니다.
- **해결**: Windows 에서는 경로를 UTF-16 으로 바꿔 `_wfopen`, `MoveFileExW(MOVEFILE_REPLACE_EXISTING)`, `CopyFileW` 를 씁니다. 다른 OS 에서는 표준 함수를 그대로 씁니다.
- **까다로운 부분**: UTF-16 변환 결과는 보통 스택 배열(`MAX_PATH`)에 담고 아주 긴 경로만 힙에 할당합니다. 메모리가 부족할 때도 보통 경로는 열 수 있습니다.
- **확인**: Linux 에서는 Windows 쪽을 돌릴 수 없으므로 MinGW 교차 컴파일과 GitHub Actions 의 Windows 작업이 한글 경로 저장/불러오기 테스트를 돌립니다.

## `mem.h` / `mem.c` — 할당 감싸개

- **하는 일**: `mem_malloc`, `mem_calloc`, `mem_realloc`, `mem_free` 는 안에서 그냥 `malloc`, `calloc`, `realloc`, `free` 를 부릅니다.
- **왜 감싸나**: 테스트 빌드(`CASTLE_TESTING`)에서만 "k 번째 할당부터 실패"를 일부러 일으켜, NULL 처리 코드가 정말 동작하는지(오류 코드를 돌려주고, 새는 메모리가 없는지) 확인합니다. 게임 DLL 에는 이 기능이 들어가지 않습니다.

## `api.c` — 공개 API 구현

- **하는 일**: 접착제. 인자 검사 → 모듈 함수 호출 → 뷰 구조체로 복사.
- **원칙**: 바깥에서 무엇을 넘기든 죽지 않고 오류 코드를 돌려줍니다(NULL 포인터, 범위 밖 틱 수, 작은 버퍼 …).
- `_Static_assert` 로 공개 헤더의 상수와 구조체 크기를 컴파일할 때 확인합니다.

## 예상 질문 20개

1. **왜 포인터 배열을 썼나요?** (주민·건물 목록 `Villager **villagers`)
   주민·건물을 하나씩 따로 할당하고(`entity_add_villager`), 목록에는 그 주소만 담습니다. 목록이 `realloc` 으로 커져서 배열이 옮겨져도 주민 자체는 옮겨지지 않으므로, 건물이 가진 `Villager *` 포인터가 깨지지 않습니다. 구조체 배열(`Villager *villagers`)로 했다면 `realloc` 할 때마다 모든 `home`, `workplace`, `workers[]` 포인터가 깨집니다.

2. **저장 파일에 포인터 대신 무엇을 저장하나요?**
   id(정수)를 저장합니다. 포인터는 메모리 주소라서 다음 실행에서는 의미가 없습니다. 주민 한 명은 `[villagers]` 섹션의 숫자 한 줄인데, 집·일터·목표 칸에 건물 id(없으면 0)를 쓰고, 다 읽은 뒤 `save.c:relink` 가 id 로 건물을 찾아 포인터와 건물 쪽 배열을 다시 이어 줍니다. 없는 id 가 있으면 `CORE_ERR_FORMAT` 입니다.

3. **`malloc` 이 NULL 을 돌려주면 어떻게 되나요?**
   그 함수는 이미 할당한 것을 해제하고 `CORE_ERR_OUT_OF_MEMORY` 를 돌려줍니다. 기존 게임 상태는 바뀌지 않습니다. 테스트가 1번째, 2번째 … 할당을 차례로 실패시켜 모든 경로를 확인합니다(`world_out_of_memory_is_clean`).

4. **`realloc` 결과를 왜 바로 원래 포인터에 넣지 않나요?**
   `p = realloc(p, n)` 이 실패하면 NULL 이 들어가 원래 블록 주소를 잃어버립니다(메모리 누수). 임시 변수에 받고 성공했을 때만 바꿉니다(`events.c:grow`, `save.c:read_line`).

5. **함수 포인터는 어디에, 왜 썼나요?**
   주민 상태(`STATE_TABLE[]`), 직업별 생산(`JOB_TABLE[]`), 정의 파일 섹션(`SECTION_PARSERS[]`), 세이브 섹션(`SECTIONS[]`), CLI 메뉴(`COMMANDS[]`), 이벤트 문장(`EVENT_FORMATTERS[]`), 봇(`BOTS[]`). `if/else` 나 `switch` 를 길게 늘어놓는 대신 "번호(이름) → 함수" 표를 두면, 새 상태·직업은 함수 하나와 표 한 줄만 더하면 되고 고르는 코드(`STATE_TABLE[villager->state](world, villager);`)는 바뀌지 않습니다.

6. **공용체(union)는 왜 썼나요?**
   이벤트마다 필요한 값이 다릅니다(날짜 하나, 계절과 연도, 경고 코드와 개수). 공용체는 이 칸들이 같은 메모리를 나눠 쓰게 해서 이벤트 하나의 크기를 작게 유지합니다. 어느 칸이 유효한지는 `type`(태그)으로 압니다(`events_to_view` 의 `switch`).

7. **2차원 지도를 왜 1차원 배열에 담나요?**
   크기가 실행 중에 정해지므로 `calloc(width * height)` 한 번으로 할당·해제할 수 있고, C# 에 통째로 복사하기도 쉽습니다. 칸 `(x, y)` 는 `y * width + x` 번째입니다.

8. **같은 시드면 왜 항상 같은 지도가 나오나요?**
   난수가 시드로 초기화되는 PCG32 이고, 노이즈를 정수로만 계산하기 때문입니다. 실수 계산은 컴파일러마다 마지막 비트가 다를 수 있어서 피했습니다. 테스트 `grid_generation_is_deterministic` 이 확인합니다.

9. **잘못된 입력은 어떻게 처리하나요?**
   `read_int` 가 숫자가 아니면 "숫자를 입력하세요", 범위 밖이면 "0부터 7 사이의 숫자를 입력하세요" 라고 말하고 다시 묻습니다. 입력이 끝나면(EOF) 무한 반복하지 않고 빠져나옵니다.

10. **파일을 못 열면 어떻게 되나요?**
    `fopen` 이 NULL 이면 `CORE_ERR_FILE_OPEN` 을 돌려주고, CLI 는 "파일을 열 수 없습니다. 경로를 확인하세요." 를 출력한 뒤 메뉴로 돌아갑니다. 하던 게임은 그대로입니다.

11. **저장하다 프로그램이 꺼지면 세이브가 망가지나요?**
    아니요. 임시 파일에 다 쓴 다음 한 번에 이름을 바꾸므로, 예전 세이브나 새 세이브 중 하나는 늘 온전합니다. 예전 세이브는 `.bak` 으로도 남습니다.

12. **세이브 파일을 손으로 고쳐서 이상한 값을 넣으면요?**
    모든 값의 범위를 검사하고, 끝에 불변 조건 검사기를 돌립니다. 하나라도 틀리면 `CORE_ERR_FORMAT` 과 문제의 줄 번호를 돌려줍니다. 망가진 파일 수백 개를 자동으로 만들어 넣어 보는 테스트도 있습니다(`load_garbled_files`).

13. **Godot(C#)과 C 는 어떻게 데이터를 주고받나요?**
    C# 이 DLL 의 함수를 P/Invoke 로 부릅니다. 월드는 불투명 포인터로만 들고 있고, 데이터는 C# 이 준비한 버퍼(뷰 구조체, byte 배열)에 C 가 복사해 줍니다. 시작할 때 구조체 크기를 서로 비교해 다르면 실행하지 않습니다.

14. **메모리 누수가 없는지 어떻게 아나요?**
    Linux 에서 AddressSanitizer + LeakSanitizer 를 켜고 모든 테스트와 400일 × 20시드 소크 테스트를 돌립니다(GitHub Actions 가 매번). 프로그램이 끝날 때 해제되지 않은 블록이 하나라도 있으면 실패합니다.

15. **전역 변수가 없나요?**
    게임 상태는 모두 `World` 안에 있습니다. 전역은 바뀌지 않는 `const` 표(시작 자원, 지형 비용, 함수 포인터 표 등)뿐입니다. 예외는 테스트 빌드에만 들어가는 할당 실패 주입 카운터(`mem.c`, `CASTLE_TESTING`)입니다.

16. **주민과 건물이 서로를 가리키는데, 어긋나지 않게 어떻게 하나요?**
    연결과 해제를 `entity_link_worker` / `entity_unlink_worker` 같은 함수로만 해서 늘 양쪽을 함께 바꿉니다. 그리고 불변 조건 검사기가 매 틱 양쪽을 대조합니다(소크 테스트 115만 틱에서 위반 0).

17. **건물을 철거하면 그 건물을 가리키던 주민의 포인터는요?**
    `entity_remove_building` 이 해제하기 **전에** 모든 주민을 돌며 `workplace`, `home`, `target` 이 그 건물이면 NULL 로 바꿉니다. 그다음 자동 배치가 다른 일터·집을 찾아 줍니다. 테스트 `demolish_refunds_and_unlinks`.

18. **`intentRev` 는 왜 필요한가요?**
    Godot 은 주민이 걷는 동안 몇 프레임 늦게 도착을 알립니다. 그사이 C 가 "배고프니 창고로 가"로 의도를 바꿨다면, 예전 목표(일터)에 도착했다는 보고는 틀린 정보입니다. 의도마다 번호를 붙이고 번호가 다른 보고는 무시해서 이 문제를 막습니다. 테스트 `villager_handshake_stale_rev`.

19. **정의 파일을 학생이 고치다 틀리면 게임이 죽나요?**
    아니요. 틀린 줄이 있으면 그 파일은 내장 기본값을 쓰고, "buildings.def 12번째 줄" 같은 경고를 게임 알림과 CLI 에 보여 줍니다. 테스트 `defs_errors_keep_defaults`.

20. **Godot 이 길찾기를 하는데 C 는 길이 막힌 줄 어떻게 아나요?**
    두 겹입니다. ① 짓기 전에 C 가 BFS 로 길이 끊기지 않는지 검사해 막는 배치를 거부합니다. ② 그래도 Godot 이 길을 못 찾으면 `core_villager_unreachable` 을 부르고, Godot 이 아무 보고도 안 하면 C 가 하루 뒤 스스로 포기합니다. 어느 쪽이든 주민은 잠시 기다렸다가 다시 판단합니다.
