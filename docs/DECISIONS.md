- 첨부 차이 명세와 학생의 추가 요청을 우선하며 C11/raylib를 유지합니다. 정의·해석과 검증을 각각 별도 문서에 기록합니다.

- 근무·서비스·생산의 효율과 실제 출근 시간을 분리합니다. 자동플레이에는 추가 자원·시야·등급을 주지 않습니다.

- 원화는 내장 image_gen, 재패킹·연결 마스크·잘림 보정은 C 도구를 사용합니다. 원화15장과 전문 프롬프트를 보존합니다.
- 성장·성능 목표 미달은 기능 검사 통과와 구분해 공개하고, 학생의 기존 로컬 커밋 선택을 따라 푸시하지 않습니다.

## 통합 확장 v1.0 (2026-11-17)

- 사용자가 제공한 통합 확장 HTML을 현재 게임 규칙의 기준으로 채택했습니다. 원문 64건설+시작 성채를 65종으로 구분하고 최신 밭/실내/회전 요구를 우선했습니다. 상세 충돌 해석은 `docs/expansion/IMPLEMENTATION.md`에 보관합니다.
- 확장 규칙을 `ruleset=1`로 분리해 기존 C 회귀 검사를 유지합니다. 실제 그래픽 새 게임은 항상 확장 규칙입니다. Godot와 .NET을 재도입하지 않습니다.
- 저장 형식은 개발 중 v6에서 수목의 재생 대기를 남은 밀리일수로 바꾸며 v7로 올렸습니다. 이전 파일은 삭제하지 않고 버전을 확인해 거절합니다. 공개 뷰 레이아웃은 ABI9입니다.
- 건물별 4방향 PNG를 모두 생성했습니다. 주민 외형 8종은 직업과 무관하며 기존 방향 걷기를 유지합니다. 입구는 논리 회전과 함께 이동하고, 그림은 점유 칸보다 높게 그립니다.
- 내부 방의 별도 지도를 만들지 않고 실내 상태와 5분 출입 전환을 사용합니다. 실내 주민은 공격 대상에서 제외합니다.
- 사료는 모든 개체에 먼저 지급한 뒤 생산·도축·번식합니다. 큰 야생동물 사냥은 식량량 기준 노동 예산을 쌓아 처리합니다.
- 자동 운영 결과와 실제 플레이 품질을 구분합니다. 144시드 검사는 오류·저장과 성장 수치를 기록하고, 왕성 목표와 차이가 있으면 그대로 보고합니다. 수치나 시작 자원을 몰래 늘려 봇을 통과시키지 않습니다.
- 학생이 로컬 커밋으로 마무리하도록 명시했으므로 이번에도 푸시·GitHub 인증을 하지 않습니다. 기존 untracked AGENTS.md는 수정·커밋하지 않습니다.

## 마일스톤 1 (2026-11-05)

### 진행 방식
- **작업 브랜치는 세션이 지정한 `claude/wizardly-allen-7ou35f`** — 클라우드 세션이 이 브랜치에만 푸시하도록 지정되어 있어서, SPEC 의 `m1-foundations` 대신 이 이름을 썼습니다. 다음 마일스톤도 세션이 지정한 이름을 따르고, PR 제목에 마일스톤을 적습니다.

### 시간
- **1배속에서 한 틱(게임 속 10분) = 0.5초, 하루 = 72초** — 왕성 목표가 50일쯤(SPEC §8)이므로 1배속 60분, 3배속 20분 정도로 한 판이 끝납니다. 값은 C(`clock.h` `CLOCK_REAL_MS_PER_TICK`)에 있고 Godot 은 `core_get_config` 로 읽습니다.
- **밤 21:00~05:00, 새 게임은 1일 06:00 에 시작** — 주민이 잠잘 시간(M2)과 마물이 나오는 밤(M4)의 기준. 낮밤 색도 같은 값을 씁니다.
- **매일 자정의 "N일째 시작" 알림은 보여 주지 않음** — 너무 잦아서 새벽 알림("N일째 아침이 밝아 옵니다")으로 대신합니다. 이벤트 자체는 C 가 계속 냅니다.

### 지도
- **96×96, 성채 중심 (48, 48), 성채 3×3, 둘레 반지름 3칸은 풀밭으로 비움, 반지름 9칸 안에는 호수 없음**.
- **지형 비율: 숲 26%, 바위 9%, 물 8%, 마정석 광맥 덩어리 5~7개** — "노이즈 상위 N%" 로 칠해서 시드마다 비율이 거의 같습니다.
- **바위 지대는 지나갈 수 있지만 느림** (이동 비용: 풀밭 10, 숲 15, 바위 30, 광맥 10, 물 0=막힘). 바위가 길을 막으면 갇힌 지역이 많이 생기기 때문입니다. 채석장은 "바위 옆"(SPEC)에 지으므로 바위 칸 자체를 걸을 수 있어도 됩니다.
- **노이즈는 정수 고정소수점으로만** — 실수 계산의 플랫폼 차이로 같은 시드가 Windows/Linux 에서 다른 지도를 만드는 일을 막습니다.
- **연결성 보장: 성채에서 네 변 모두 걸어서 닿아야 하고, 갇힌 땅은 물로 바꿈** — 적은 가장자리에서 오고(M4), 떠나는 주민은 가장자리로 걸어갑니다(M2).
- **공정한 시작: 성채 반지름 14칸 안에 숲 ≥ 30, 바위 ≥ 10, 광맥 ≥ 3** — 모자라면 성채에서 7~12칸 떨어진 곳에 덩어리를 찍습니다. 3000개 시드로 확인했습니다.

### 자원
- **금화·마정석은 화폐라 저장 한도 없음, 식량·목재·석재·약초는 한도 있음 (성채 200)** — 어느 자원에 한도가 있는지는 규칙이므로 C 가 뷰의 `resource_capacity[]` 로 알려 줍니다 (0 = 한도 없음).
- **난이도별 시작 자원** (금화, 마정석, 식량, 목재, 석재, 약초): 평화 300/10/80/80/40/10, 보통 200/5/60/60/30/5, 혹독 150/3/40/40/20/3. 시뮬레이터로 M2~M7 에서 다시 맞춥니다.

### C 코어
- **라이브러리 세 벌**: `castle_core`(공유, Godot 용), `castle_core_static`(CLI 용, 실행 파일 하나로 시연하기 쉬움), `castle_core_testing`(테스트 용, 내부 헤더 공개 + 할당 실패 주입).
- **새니타이저는 정적 라이브러리·CLI·테스트에만** — ASan 이 들어간 공유 라이브러리는 Godot 이 로드할 수 없고, Ubuntu 의 clang 은 공유 라이브러리 ASan 링크에 런타임 패키지가 더 필요합니다.
- **모든 할당은 `mem_*` 감싸개로** — 테스트 빌드에서만 "k 번째 할당부터 실패"를 주입합니다. 이 카운터는 테스트 빌드에만 있는 유일한 전역 상태입니다.
- **MSVC 는 C 런타임 정적 링크(`/MT`), MinGW 는 `-static-libgcc`** — `castle_core.dll` 하나만 복사하면 되게.
- **소스는 UTF-8, MSVC 에 `/utf-8`** — 한국어 Windows(코드 페이지 949)에서 한글 주석·문자열이 깨지지 않게.
- **시드는 0 이상의 int32** — 뷰 구조체를 모두 `int32_t` 로 맞추기 위해.
- **망가진 월드는 저장을 거부** — 불변 조건을 어긴 상태를 저장하면 멀쩡한 예전 세이브를 덮어쓰게 되므로.
- **저장은 `.tmp` 에 쓰고 → 예전 파일을 `.bak` 으로 복사 → 바꿔치기** — 복사 방식이라 바꿔치기 직전까지 본 파일이 늘 있습니다.
- **비용 격자와 이벤트는 저장하지 않음** — 비용 격자는 지형에서 다시 계산되고, 이벤트는 보여 주기용입니다.
- **이벤트 큐 최대 4096개, 넘치면 가장 오래된 것을 버리고 경고 이벤트로 알림**.
- **CLI 는 Windows 콘솔에서 `ReadConsoleW` 로 읽어 UTF-8 로 변환** — 일부 Windows 에서 `CP_UTF8` + `fgets` 로 한글이 사라지는 문제를 피합니다.

### Godot
- **UI 배율은 정수(1~4), 테마 값을 곱해서 적용** — Galmuri11 은 12px 의 정수배에서만 또렷합니다. CanvasLayer 를 키우는 방식은 툴팁 팝업이 같이 커지지 않아서 테마 방식을 골랐습니다. 기본값은 창 크기로 정합니다 (1280×720 → 2, 1920×1080 → 3). 설정 메뉴(M6)에서 바꿀 수 있게 할 예정입니다.
- **창 늘이기(stretch) 끔, 카메라 확대는 정수 배율(1~6)** — 픽셀 아트가 고르지 않게 늘어나지 않도록.
- **입력 동작은 코드(`InputActions.cs`)로 등록하고 물리 키 코드를 씀** — 한글 자판/IME 가 켜져 있어도 WASD 가 동작하게.
- **지형 그림: `tools/make_art.py` 가 Kenney Tiny Town 타일과 절차적 타일(물, 바위, 광맥)로 `terrain.png` 를 만들고 커밋** — Tiny Town 에는 물·바위 지대·광맥 타일이 없습니다. 더 나은 그림이 생기면 PNG 만 바꾸면 됩니다.
- **성채는 Tiny Town 성벽·문 타일로 만든 3×3 임시 그림** — M2 에서 건물 장면으로 바뀝니다.
- **Kenney `Tiles/`, `Tiled/` 폴더는 `.gdignore` 로 Godot 가져오기에서 뺌** — 같은 그림이 `Tilemap/` 시트에 있습니다. 나머지 에셋의 `.import` 파일은 커밋합니다(uid 가 컴퓨터마다 달라지지 않게).
- **오류 감지 로거(`ErrorCounter`)는 스모크·스크린숏 모드에서만** 붙입니다. 스크립트는 출력의 `ERROR`/`WARNING` 줄도 따로 검사합니다.
- **C# 은 `ExportDebug`/`ExportRelease` 빌드에서 경고를 오류로** — Godot 의 빌드 구성은 Debug/ExportDebug/ExportRelease 입니다.

## 마일스톤 2 (2026-11-05)

### 정의 파일
- **`game/data/*.def`, `names.txt` 는 Godot 이 `FileAccess` 로 읽어 내용을 `core_defs_load_text` 로 넘깁니다** — 내보낸 게임에서는 `res://` 가 `.pck` 안에 있어서 C 가 파일 경로로 열 수 없기 때문입니다. CLI 는 `core_defs_load_file` 로 직접 읽습니다(`--data` 폴더, 기본 `game/data`).
- **정의 파일의 기준은 C 의 내장 기본값** (`defs_builtin.c`). `castle_cli --dump-defs game/data` 가 파일을 다시 만듭니다. 파일에 틀린 줄이 있으면 **그 파일 전체를** 기본값으로 두고 파일·줄 번호로 경고합니다 (반만 적용되면 더 헷갈리므로).
- 건물 정의는 이름(`[building farm]`)으로 찾고, 종류 번호는 C 의 `CORE_BLD_*` 순서로 고정합니다. 정의 파일로 **수치는 바꿀 수 있지만 새 건물 종류는 못 만듭니다** (그림과 작업 함수가 필요하므로).

### 배치와 길
- **길을 끊는 배치는 거부** (`BLOCKS_PATH`, `UNREACHABLE`): 성채 문에서 걸어서 닿던 건물 문과 지도 가장자리(이주민이 오는 곳)에 계속 닿아야 하고, 새 건물의 문에도 닿아야 합니다. 봇 시뮬레이션에서 건물이 문을 둘러싸 "창고 옆에서 굶는" 일이 생겨서 넣었습니다.
- **빠른 길 검사**: 발자국 테두리의 걸을 수 있는 칸이 한 덩어리면 끊길 수 없으므로 지도 전체를 채우지 않습니다. 소크 테스트가 약 11배 빨라졌고 결과는 같습니다 (시뮬레이터 CSV 비교).
- **새 건물 자리에 서 있던 주민은 가장 가까운 빈칸으로 옮김** (`relocate_villagers`).
- **문 앞 칸**: 건물마다 한 칸, 아래 → 오른쪽 → 왼쪽 → 위 순으로 첫 빈칸. 다른 건물은 그 칸을 덮을 수 없습니다.
- 비용 격자: 풀밭 10, 도로 5(2배 빠름), 숲 더 느림, 물·건물 0(막힘), 성벽 254, 성문 253.
- 숲 위에 지으면 나무를 베어 풀밭으로 바꿉니다 (벌목장 생산량에 영향).

### 경제 수치 (처음 정한 값, 시뮬레이터로 확인)
- 하루 결산은 06:00: 장부를 넘기고, 임금(일꾼마다 건물 정의의 `wage`)과 세금(집 있는 주민 한 명당 금화 2)을 처리하고, 이주민을 받습니다.
- 일은 07:00~18:00. 생산은 `WORKING` 상태의 틱마다 `rate/1000 × 생산성 × 기분 보정 × 능력치 보정` 을 천분율로 쌓습니다.
- 저장 한도: 성채 300, 창고 200씩. 금화·마정석은 한도 없음.
- 배고픔: 깨어 있으면 틱마다 0.667, 자면 절반. 35 아래면 가장 가까운 저장 건물로 먹으러 가서 식량 1 로 70 을 채웁니다 → 한 사람이 하루 약 1.1 식량.
- 농장 한 곳(일꾼 2)은 하루 약 9 식량 = 주민 7~8 명분.
- **겨울 농장은 50%** (마일스톤 2). SPEC 의 "겨울에는 농장이 멈춤"은 마일스톤 3 의 계절 압박(겨울 경고, 비축 안내, 난방 나무)과 함께 넣습니다. 0% 로 두었더니 스모크 자동 조종 마을(주민 24명, 농장 3곳)이 첫 겨울에 무너졌고, 그것을 막을 안내가 아직 없었습니다.
- **굶주림은 죽기 전에 떠남**: 배고픔이 0 이면 한 시간에 건강 1 이 줄고, 50 이 되면(약 이틀) 마을을 떠납니다. 굶어 죽는 일은 길이 막혀 떠나지 못할 때만 생깁니다.
- 기분이 25 아래로 이틀이면 떠납니다. 죽음은 슬픔(마을 전체 기분 −10, 최대 −30)을 남기고 하루에 조금씩 옅어집니다.
- **이주**: 빈 집이 있고, 평균 기분 55 이상, 겨울이 아니고, 식량이 주민 × 5 이상이면 하루 1~3 명.
- 시작 주민: 쉬움 7, 보통 6, 어려움 5.

- 비용·점수: 1단계 금화 60~80 + 마정석 5~10 · 25점, 2단계 100 + 8~12 · 35점, 3단계 150 + 10~15 · 45점, 4단계 200 + 15~20 · 55점. 갈래 안에서는 위의 것을 먼저 끝내야 함, 한 번에 하나.
- 마탑(요새부터, 금화 80·마정석 10·목재 20·석재 30, 마법사 2칸): 마법사 한 명이 근무 틱마다 0.12점 × 근무 효율 × (100 + 마법 특성)%. 마법사 한 명이면 1단계 연구가 대략 4~6일.
- **효과는 정의를 고치는 방식**: 원래 정의에서 끝낸 연구를 번호 순서로 다시 적용(`research_reapply`). 곱하기 효과가 겹쳐도 순서와 불러오기에 상관없이 같은 값.
- 연구 파일이 기본보다 짧아도(학생이 연구를 줄여도) 게임을 이길 수 있게, 등급의 연구 수 조건은 정의된 연구 수까지만 셈.

- **정의**: 연구 비용을 금화에서 마정석 쪽으로 (1단계 40금·15마정석, 2단계 60·25, 3단계 100·40, 4단계 140·60. 마력 감지는 30·15). 요새 공물 금화 80 → 50. 성 공물 150금·50마정석, 왕성 250금·100마정석.
- **혹독 시작 마정석** 3 → 8.
- **봇**: 마을이 되면 첫 광산, 다음 등급의 방어 점수가 모자라면 감시탑, 요새가 되면 첫 마탑을 겨울 준비와 상관없이 지음 — 단 먹을 것이 주민 × 6 이상일 때만 (숲이 적은 지도에서 목재를 써 버려 굶는 것을 막음). 연구 금화 여유 80 → 40.
- **해 보고 되돌린 것**: 집을 금화가 있을 때만 미리 짓기(이주민 = 세금이라 오히려 늦어짐), 농부를 광산으로 옮기기(굶는 판), 목재가 바닥이면 농부를 벌목장으로(평화에서 굶는 판), 가을 이주 규칙 새로 만들기(이미 마일스톤 3 에 있었음 → 테스트만 더함).
- **남은 것**: 평화가 보통보다 덜 이김(10 vs 12) — 진 판·멈춘 판의 원인이 제각각(숲이 적은 지도, 겨울 직전 급성장, 성 공물의 마정석)이라 봇의 한계로 보고 그대로 둠. 사람은 시장에서 사고 일꾼을 옮길 수 있으므로 플레이 테스트로 확인할 것.

### 성능 (SPEC §5: 주민 150명에서 C 틱 1 ms 미만, 주민 150명 + 적 40명에서 60 fps)
- **측정 도구**: `core_debug_stress` (디버그 전용 `debug.c`: 집·농장·창고를 공짜로 바로 짓고 주민을 늘림, 적 N명의 마물 습격), CLI `--bench`, Godot `--stress`(학생 노트북에서 FPS 보기)와 `--stress-probe`(클라우드에서 프레임 시간 재기).
- **C 틱** (릴리스 빌드, 클라우드 VM): 주민 150명 평균 **0.010 ms**(가장 느린 틱 0.05 ms), 적 40명과 0.009 ms, 300명 0.018 ms — 목표의 1/100. ASan 디버그 빌드 0.078 ms. 주민 수에 거의 정비례.
- **Godot 프레임** (헤드리스 = 그리기 제외, 3배속, 600프레임): 평균 **7.0 ms**, 99% 10 ms. 16.7 ms 를 넘는 프레임은 적 40명이 나타나는 한 프레임(약 60 ms: 적 노드 40개를 만들고 처음 쓰는 코드를 준비). Xvfb 는 그림을 CPU 로 그려(llvmpipe) 평균 21 ms — 실제 노트북의 GPU 로는 학생이 `--stress` 로 확인.
- **고친 것**: 아침 7시에 주민 150명이 한꺼번에 일터로 갈 때 길찾기 150번이 한 프레임에 몰려 30 ms 씩 끊김 → 길찾기는 한 프레임에 4 ms 까지(`Pathfinder.HasBudget`), 남은 주민은 다음 프레임에 출발 (C 는 도착 보고를 기다릴 뿐이라 한두 프레임은 보이지 않음). 적의 길찾기도 같은 예산.
- 큰 마을이 하루 먹을 식량을 담을 곳이 없어 200명부터 하루 만에 굶어 떠나던 측정 마을 → 주민 스물다섯에 창고 하나.

### 다듬기
- **건설 겹쳐 그리기**: 작업 반경(점선), 생산성에 세는 지형 칸(노란 테두리), 문 칸(파란 네모). 어떤 지형을 세는지는 C 가 정의 뷰에 담아 줌(`count_terrain`, ABI 8) — 배치 규칙을 C# 에 베끼지 않으려고.
- **Godot 의 지형 복사본 새로 고침**: 건물·도로가 숲을 베면 C 는 풀밭으로 바꾸는데 Godot 은 처음 지형 그대로였음 → 철거한 자리에 나무가 남아 보이고 겹쳐 그리기가 베인 숲을 셈. 비용 격자가 바뀔 때 바뀐 칸만 다시 그림. 스크린숏에서 발견.
- **일꾼 없는 일터**: 오른쪽 위 붉은 "!" (깜빡임, 그 건물만 매 프레임 다시 그림), 검사창에 까닭.
- **소리** (Kenney CC0): 단추 딸깍(모든 단추: 장면 트리에 단추가 생길 때마다 연결, UI 버스), 건물 완성, 승급·연구·목표·승리 팡파르, 거절, 건물 놓기. **반짝임**: 승급·승리 성채 위 금색, 연구 마탑 위 보라색, 건물 완성 흙먼지.
- **도움말** (F1, 일시정지 메뉴): 조작, 겹쳐 그리기, 계절, 습격, 승패, 저장을 한 화면에.
- **적 위에 마우스**: 이름과 체력 (적은 검사창이 없어서).
- **음악**: 여전히 없음 (CC0 곡을 찾지 못함). Music 버스와 음량 막대만.

## C 실행판 전환 (2026-11-14)

- **학생 요청을 우선해 Godot/C#을 C11 + raylib 5.5로 교체** — 코어뿐 아니라 화면·입력·이동·전투·메뉴·설정도 C로 설명할 수 있게 합니다.
- **정적 코어 직접 연결** — P/Invoke·.NET·DLL 탐색 없이 실행 파일로 배포합니다. 선택적 공유 라이브러리와 ABI 8은 유지합니다.
- **실시간 C 실행 계층을 화면과 분리** — session/path/combat/storage는 창 없이 CTest와 Sanitizer로 검사합니다.
- **4방향 A*와 C 투사체 풀** — 도로 비용·성문·벽 공격을 유지하면서 엔진 노드·물리를 제거합니다.
- **기존 C 봇을 공용 함수로 공개** — CLI는 간이 전투, 새 스모크 검사는 실제 C 이동·전투를 쓰며 같은 건설·경제 봇 명령을 사용합니다.
- **raylib 소스 버전·SHA 고정** — 외부 코드는 빌드 캐시에만 두고 출처를 CREDITS에 기록합니다.
- **Python 밸런스 집계를 C로 교체**, 그림 자동 재생성은 제외하고 기존 PNG 유지. CMake/YAML/PowerShell은 빌드 설정 언어로 유지합니다.
- **Windows UTF-8 경로와 인자 변환** — 한글 경로 리소스는 메모리로 로드하고 명령줄도 UTF-16에서 변환합니다.
- **한글 경로를 처리하지 못하는 MinGW/Ninja는 임시 드라이브로 빌드** — 사용자 소스 이동 없이 스크립트가 연결을 만들고 해제합니다.
- **실행 중인 게임을 덮지 않는 검증 출력 옵션** — CASTLE_GAME_OUTPUT_DIR로 검증용 실행 파일을 별도 폴더에 빌드할 수 있습니다.

## 새 픽셀아트와 높이 (2026-11-16)

- 학생 첨부의 상세한 중세 판타지 픽셀아트를 참고해 내장 image_gen으로 모든 현재 사용 그림을 새로 제작했습니다. 첨부 원본은 배포하지 않습니다.
- 주민은 8직업×4프레임, 적은 6종×4프레임이며 주민 그림을 ID 대신 현재 직업으로 선택합니다.
- 점유 규칙·이동 좌표·세이브는 유지하고 그림만 발밑 중앙에 정렬합니다. 1타일 주민은 24픽셀 높이, 건물은 원본 비율과 추가 높이를 유지합니다.
- 숲·돌·광맥을 지면에서 분리해 높은 소품으로 그립니다. 나무·건물·주민·적을 함께 발밑 y로 정렬해 뒤를 가립니다.
- 절차적 도형으로 그림을 대신하지 않고 새 PNG를 사용하며, C 도구는 자르기·알파 정리·패킹만 수행합니다. 서비스 없이 재패킹할 수 있도록 원본 6장과 정확한 프롬프트를 보관합니다.
- 새 그림의 프로젝트 보유 권리는 CC0 1.0으로 헌정합니다. 글꼴·효과음은 기존 OFL/CC0를 유지합니다.

## 45도 구도와 주민 정체성 (2026-11-16 후속 요청)

- 학생의 농장 게임 참고 화면에 맞춰 건물 15종·공사장·수목과 광석을 약 45도 내려다보기로 다시 생성했습니다. 큰 지붕 면이 뒤로 뻗고 돌·그루터기의 윗면도 보입니다. 원본 비율·발밑 정렬·기존 점유 칸은 유지합니다.
- 주민은 직업 유니폼 대신 갈색·금발·검은·붉은 머리 남녀 8외형입니다. ID에 고정해 일터를 바꿔도 다른 사람으로 보이지 않게 합니다. 코어 난수·세이브 버전을 추가하지 않습니다.
- 외형마다 정면·오른쪽·뒷면 4프레임을 생성했습니다. 왼쪽은 오른쪽을 좌우 반전해 총 4방향으로 표시합니다. 그림은 실제 이동 벡터와 거리에 따라 바뀌며 멈추면 마지막 방향의 중립 자세를 유지합니다.
- 새 주민 시트는 12열×8행(셀 96×96)입니다. 각 프레임 내용·발밑과 방향별 걷기 변화 여부를 C 도구로 확인합니다. 게임과 같은 선택 함수를 사용하는 주민 비교 촬영을 추가했습니다.
- CMake의 그림 복사를 별도 의존 타깃으로 바꿔 C 코드가 바뀌지 않은 에셋 재패킹도 실행 폴더에 반영합니다.
