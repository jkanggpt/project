### 2.2 1단계에서 남은 것과 바뀐 것

**그대로 이어진 생각** (설계 원칙)
- 게임 규칙과 상태는 C 코어만 가진다. 화면은 코어의 공개 API로 상태를 읽고 명령을 요청할 뿐 규칙을 갖지 않는다.
- 불투명 핸들(`CoreWorld*`)과 복사 가능한 평면 뷰(`Core...View`)로 주고받는다. 내부 포인터를 밖에 넘기지 않는다.
- 고정 틱(10게임분), 같은 시드면 같은 결과(상태 해시로 비교).
- 함수 포인터 표(정의 파서, 세이브 섹션, 콘솔 메뉴), 원자적 저장과 `.bak` 예비 파일, 콘솔판의 `--simulate`(봇)·`--soak`(장시간 불변 조건 검사).

**바뀐 것**
- 화면: Godot(C#) → raylib(C). `game/`의 Godot 프로젝트는 지워졌습니다.
- 규모: 지도·건물·자원·주민 규칙이 크게 늘었습니다 (건물 16 → 73, 자원 6 → 15, 등급 5 → 6 등).
- 등급 이름: 촌락→마을→요새→성→왕성 (5단계) → **개척지→촌락→마을→도시→성채→왕성** (6단계).
- 세이브: 형식 5 → 13. **옛 세이브는 읽지 않습니다** (일부러 막음).
- 문서: 1단계의 기록 문서(결정 기록, QA 체크리스트, 마일스톤별 설명)는 구조 정리 때 저장소에서 빠졌습니다. 내용은 Git 기록에 남아 있습니다.

## 3. 어떻게 돌아가나 — 기술 구조

### 3.1 큰 그림

```
            ┌──────────── castle_game (raylib 그래픽) ─────────────┐
            │  game/src/ui      패널·툴팁·건설 카드               │
            │  game/src/render  지도·스프라이트·깊이 정렬·효과   │
            │  game/src/assets  매니페스트로 그림·소리 불러오기   │
            └───────────────┬───────────────────────────────────┘
                            │                ┌── castle_cli (콘솔판·봇·소크)
                            ▼                ▼
                  game/src/runtime  GameSession (실제 이동·전투·배·체크포인트)
                            │  game_session_step(분)
                            ▼
                  core (castle_core 라이브러리)  ← 공개 헤더 core/include 두 개
                  규칙·상태·저장의 유일한 주인
```

- **코어 (`core/`)**: 세계 상태와 규칙 전부. 고정 10게임분 틱(하루 144틱).
- **GameSession (`game/src/runtime`)**: 주민·적·배를 실제 길 위에서 움직이고 화살·공격을 처리합니다. 최대 2게임분씩 나눠 진행하고, 결과를 코어 API로 보고합니다. 저장하기 직전에 자기 상태를 코어에 넘깁니다(체크포인트).
- **그래픽판과 콘솔판이 같은 GameSession을 씁니다.** 그래서 콘솔에서 돌린 봇 결과가 그래픽판과 같은 규칙입니다.
- 1배속 = 실제 1초에 12게임분 → 하루 120초. 2·3배속, 일시정지.

| (특수) | 1 | 영주관 — 처음부터 있음, 등급마다 그림이 바뀜(6단계) |

- 배치 검사(물·겹침·통행), **4방향 회전**(R), 도로·성벽은 끌어서 줄로, 철거(X)는 도로 연결이 끊기면 거절.
- 도로는 이웃과 이어지는 그림, 물가 다리 난간. 촌락부터는 건물 입구를 영주관 도로망에 이어야 함.
- 건설 카드에 비용과 해금 등급별 테두리, 일꾼이 없는 일터에 빨간 느낌표.
- 건물 그림은 실제 점유 칸보다 높게 그려지고 발밑 기준으로 앞뒤가 정렬됨.
- 정확한 비용·크기·일꾼 수는 `docs/CONTENT_REGISTRY.md`.

### 4.3 주민
- 이름 324개(남녀 각 162), 외형 48종(머리색 6 × 남녀 × 변형 4), 걷기·프로필·작업복·방향별 공격 그림.
- 주민이 실제로 건물에 들어가고, 주민 주변만 시야가 밝아짐(안개).
- 욕구와 상태를 따로 관리: 허기, 물, 위생, 안전, 기분, 장기 행복, 질병, 숙련, 실제 근무 시간. 머리 위 말풍선 아이콘.
- 일터별 능력치 가중치 → 개인 능률 E와 총 능률 F, 직종 숙련과 성장 문턱 표시.
- 주간·야간 **근무조**, 군인·사냥꾼은 출퇴근 때 일터에서 옷을 갈아입음, 어부는 배에 탐.
- 식량은 주민 한 명당 하루 1개.
- 이주: 개척지에서는 5~8일, 10~13일에 2명씩 조건 없이 옴 → 이후 인구 8명 하한 보충 → 상위 등급에서는 빈집·식량·행복·급수·재난·대기일을 따짐. 떠남, 추방도 있음.
- **고용**: 12일 선불 계약 일꾼(이동 시간 포함). 승급 인구와 세금 계산에서는 빠짐.
- **세금**: 주민 1명당 하루 1~4금화 중 선택(승급 창).
- 주민 목록(V): 정렬, 누르면 그 주민에게 이동. 주민 프로필과 숫자 능력치.

### 4.4 경제
- **자원 15종**: 금화, 마정석, 식량, 원목, 목재, 돌, 약초, 가죽, 점토, 벽돌, 석탄, 철광석, 철괴, 금광석, 금괴. 하루 필요량보다 적으면 빨갛게 표시.
- 모든 생산·소비는 장부를 거침(장부 창). 소수점 단위 자원과 아직 거두지 않은 수확을 보존.
- 농업: 경작지·농장·관개농장은 봄·여름의 노동을 모아 가을 첫날(25일) 08시에 한 번 수확(여러 날에 나눠 들어옴, 창고가 모자라도 버리지 않음). 텃밭은 매일, 겨울엔 절반.

- 가공 사슬: 원목 → 목재(제재소), 점토 → 벽돌(가마), 철광석·금광석 → 철괴·금괴(제련소).

- **떠돌이 상인**: 24~36일마다 실제로 걸어서 방문, 물물교환 85종(모두 이득인 교환), 같은 교환을 두 번 처리하지 않음(nonce).

### 4.7 위협과 전투

### 4.10 저장
- 자동 저장 1칸 + 슬롯 3칸. 매일 자동 저장.
- 덮어쓸 때 이전 파일을 `.bak`으로 남기고, 본 파일이 망가지면 불러오기 창이 예비 파일을 제안.
- 쓰기 순서: `.tmp`에 쓰기 → CRC 기록 → 닫기 → 원본을 `.bak`으로 → 원자 교체. 실패해도 원본은 그대로.
- 읽을 때 섹션·개수·ID·범위·CRC를 모두 검사하고, 임시 세계를 다 만든 뒤에만 교체. 다른 형식(0~12, 14 이상)은 "지원하지 않는 이전 저장 형식입니다"로 거절.
- 저장 후 다시 불러와 500틱 더 진행해도 결과가 같음을 검사. 자세한 형식은 `docs/SAVE_FORMAT.md`.

| README·여러 문서에서 숫자 앞 띄어쓰기가 빠짐 (예: "같은160×160 세계,73종") | `README.md`, `PROGRESS.md`, `docs/*.md` | 문서 정리 |

### 6.2 기록된 한계 (`docs/MISSING_FEATURES.md`)
- **성장 목표 미달**: 봇 144판(난이도별 48판 × 최대 200일)에서 **도시에 오른 판 0개**. 생존: 평화 44/48, 보통 36/48, 혹독 1/48. 위의 짧은 표본에서도 보통 100일에 촌락이 최고였습니다. 사람이 하면 다를 수 있지만, 지금 숫자로는 왕성 승리가 매우 멉니다.
- **생태**: 지역 생물량이 한도를 넘은 관측 2번. 원인 미확정.
- **성능**: 큰 영지에서 60 FPS 미달 (평균 약 28 ms/프레임).
- **검증 안 된 것**: 사람이 30분 이상 이어서 하기, 도시까지 간 30판, 어선 32척과 회전 건물을 한꺼번에 둔 최대 부하.
- 공개 헤더의 `requires` 필드 이름 때문에 C++20에서는 헤더를 쓸 수 없음 (C11·C++11은 확인됨).

### 6.3 일부러 만들지 않았거나 아직 없는 것
- **음악** (효과음 8개만 있음).
- **동물 피격·사망 그림** (사용자 지시로 제외, 이동·수영·새끼만).
- **옛 세이브 변환** (형식 13만 읽음 — 일부러 막음).
- **Linux·macOS 배포본** (Windows ZIP만). Linux는 소스에서 빌드하면 실행됩니다.
- **수동 QA 체크리스트와 결정 기록 문서**: 1단계의 `docs/QA.md`, `docs/DECISIONS.md`는 구조 정리 때 빠졌습니다. 사람이 해 본 플레이 테스트 기록을 남길 곳이 지금은 없습니다.
- **코드 라이선스**: 프로그램 코드의 공개 라이선스가 정해져 있지 않음 (`CREDITS.md`). 그림·소리·글꼴의 권리는 정리되어 있음.
- 적·군인 전용 검사창, 저장 슬롯 이름 붙이기·지우기 (1단계부터 남은 빈 곳).
