## 1. 게임 세계 기본 규칙 — 유지

- 영지 등급: **개척지 → 촌락 → 마을 → 도시 → 성채 → 왕성**, 최종 목표 약 **게임 속 3~4년**.
- 월드: **192×192 = 36,864 타일**. 하루 144틱(10게임분/틱), 현실 1배속 하루 120초, 계절당 12일, 연간 48일.
- 건물: 기획 확정 **64종**, 원래 건설비·면적·최대 노동자·레시피 유지. **영주관은 별도 시작 중앙 건물로 4×4**.
- 자원: **금화, 마정석, 식량, 약초, 원목, 목재, 돌, 점토, 벽돌, 철광석, 석탄, 철괴, 금광석, 금괴, 가죽** 총 15종 유지. 물류시설이 여러 곳이어도 실제 자원은 **전역 자원 은행 1개**에서 관리합니다.
- 연료 우선순위: **석탄(2FU/개) → 원목(1FU/개) → 목재(1FU/개)**. 남는 연료단위는 공용 잔량으로 보존. 가공 소비와 생산 수치는 분리 기재하며 기존 v1.0 표를 변경하지 않습니다.
- 생산 원칙: 농장은 봄·여름의 **실제 유효 노동시간 누계로 가을 한 번 수확**, 파종 없음; 과수원 완공 후 24일 생산 없음; 임업 성목별 공유 채취한도; 광업 돌·석탄을 포함한 전 광물 자동 가치비례 채굴; 채집 자동 확률 획득; 제련소만 철/금 모드 선택; 어업은 수역 공동 일일 한도.
- 방어: 습격 사전 예고 없음. **적을 실제로 발견하면 알림과 병영 자동 출동**, 보호구역 대피·도로/성문 연결보호 유지. 건설은 돌/암석 타일 허용, 촌락 이상 일반 건물은 영주관 연결도로에 출입구 인접.

## 2. 자발적 이탈과 영구 이주 — 모든 등급 8인 하한

### 2.1 자발적 이탈 금지 [확정]

- **전 영지 등급**에서 `영구 거주민 수 ≤ 8`이면 **어떤 자발적 이탈도 시작하거나 완료하지 못합니다.** 불행, 굶주림/낮은 만족, 임금 체불, 위생 악화, 두려움 등에 따른 *마을을 떠나겠다는 의사 결정*은 모두 차단합니다.
- 영구 주민 **9명일 때 최대 한 명만 자발적으로 떠나 8명이 될 수 있고**, 그 후 자발적 이탈은 금지됩니다. 이미 떠나기로 정하고 이동 중인 사람이 여러 명이더라도 결과가 8명 미만이 되어서는 안 됩니다.
- 보호 인원은 **영구 주민만** 집계합니다. 계약직의 계약 종료·귀향은 자발적 이탈로 취급하지 않습니다.
- **사망, 전투 피해, 질병, 굶주림에 의한 체력 0, 적의 습격** 등은 이 보호 규칙과 무관하게 발생할 수 있습니다. 인구가 실제로 8명 미만으로 내려갈 수 있지만 **그 후의 자발적 이탈은 전부 정지**합니다. 이탈 보호는 무적·식량 보충·사망 방지를 뜻하지 않습니다.
- [제안] 예약 이탈(`pending_departure`)을 포함해 `현재 영구 인원 − 예약된 자발적 이탈자 수 ≥ 8`을 **이탈 결정 직전과 맵 가장자리 실제 제거 직전** 모두 검증합니다. 전투 사망으로 숫자가 줄면 진행 중이던 자발적 이탈을 취소하고 주민을 정상 상태로 복귀시킵니다.
- [제안] 경고 UI는 인구가 8명 이하여도 불행·굶주림을 정상 표시하되 `인구 보호 규칙으로 자발적 이탈만 보류 중`으로 설명합니다. 문제가 해결됐다고 표시하지 않습니다.

### 2.2 개척지 이주 [v1.1 유지, 확정]

- 보통 난이도 **시작 영구 주민 4명**.
- 특별 이주단 **2명씩 2회** 유지(현행 구현의 약 **5~8일 / 10~13일**, 기존 도착·보류 로직 유지). 특별 이주단 도착 여부를 저장합니다. 예외 이주는 일반 4일 쿨타임을 사용하지 않습니다.
- 두 번째 특별 이주단이 도착한 뒤, **개척지에 남아 있는 동안 영구 인구 <8**이면 **3일마다 1명**씩 보충합니다. 횟수 제한은 없습니다.
- [제안] 두 번째 특별 이주단 수령일을 `d`라 할 때 첫 보충 판정은 `d+3`, 다음은 `d+6` …입니다. 판정일에 8명 이상이면 유입 없이 넘어가고, 다음 정기 판정일까지 대기합니다.
- 보충 이주는 빈집·식량·행복·우물·재난 등의 일반 이주 조건을 무시하는 **보장 이주**입니다. 숙소 부족 시 노숙할 수 있습니다. 영주관 근처 도달 가능한 안전한 빈 칸에서 출현합니다.
- 개척지에서 촌락 승급 공사를 **시작할 때가 아니라 완료해 등급이 실제로 바뀔 때**부터 개척지 보충 이주가 정지됩니다. [제안: 하루 공사 중 빈틈 방지]

### 2.3 촌락 이상 일반 이주 [v1.1 유지, 확정]

- 촌락·마을·도시·성채·왕성의 **영구 이주 성공 후 최소 쿨타임은 일률적으로 4일**입니다.
- `오늘 날짜 ≥ 마지막 영구 이주 성공일 + 4`인 경우 **매일 06:00 한 번** 모든 조건을 심사합니다. **조건 미충족은 쿨타임을 재설정하지 않습니다.** 조건이 충족되는 첫 심사에 바로 도착합니다.
- 예: 20일 수령 → 24일 06:00부터 심사 → 24~27일 실패 → 28일 성공, 다음 가장 빠른 도착은 32일.
- 특별·보충 이주도 `마지막 영구 이주 날짜`를 갱신합니다. 승급 공사 시작·완료는 쿨타임 초기화 요인이 아닙니다.
- 영구 이주 조건: 빈 영구 주거 공간, 우물 공급, 도로 접근, 충분한 식량, 심각한 역병 없음, 최근 대형 재난 후 5일 대기, 영지 평균 행복도 기준 통과. **겨울 이주 인원은 50%로 축소(올림)**. 기존 등급별 이주단 규모 유지.

| 등급 | 이주 요구 평균 행복도 **[v1.1 제안]** | 이주단 규모 | 최소 성공 간격 |
|---|---:|---:|---:|
| 개척지 | 특별/보충 별도 규칙 | 2명×2회, 이후 부족 시 1명 | 특별 일정 / 보충 3일 |
| 촌락 | 38 | 2~3명 | 4일 |
| 마을 | 40 | 3~4명 | 4일 |
| 도시 | 42 | 3~5명 | 4일 |
| 성채 | 44 | 4~6명 | 4일 |
| 왕성 | 46 | 4~7명 | 4일 |

- 이주단이 수용 가능한 빈집 인원보다 크면 빈집 수만큼 입주합니다. 빈집 0이면 일반 이주는 실패하며 사유를 기록합니다.
- [제안] 매일 조건 심사 전에 지난날 사망·이탈·주거 철거·재난 정보를 적용해 중복 출현을 방지합니다. 필요 시 결과는 `WAIT_COOLDOWN`, `BLOCKED_CONDITIONS`, `READY_NEXT_CHECK`, `ARRIVING`, `SPECIAL_PENDING`, `REFILL_WAIT` 중 하나로 관리합니다.
- **승급 평균 행복도 기준은 기존의 35/40/45/50/55 그대로** 유지합니다. 이주와 승급의 행복도 조건을 혼동하지 않습니다.

## 3. 주민 탭 — 영구 이주 상태 가시화 [확정]

**주민 탭 상단에 `영구 이주` 요약 패널을 추가합니다.** 개별 주민 카드/관리 기능을 밀어내지 않도록 간결하게 표현합니다.

| 표시 항목 | 예시 | 판정 방식 |
|---|---|---|
| 현재 영구 인구 | `영구 주민 15명` | 계약직 제외 |
| 이주 상태 | `이주 대기 · 행복도 부족` | 가장 직접적인 원인 1개 + 전체 원인 툴팁 |
| 마지막 일반/특별 이주 | `22일` | 실제 도착 기준 |
| 다음 쿨타임 해제 | `26일 06:00` | 마지막 성공+4일, 보충은 별도+3일 |
| 다음 심사 | `26일 06:00` 또는 `내일 06:00` | 쿨타임·심사 시계 반영 |
| 평균 행복도 | `41 / 필요 42` | **행복도** 사용, 기분 별도 |
| 주거 빈자리 | `빈자리 3칸` | 영구 주거 배정 기준 |
| 식량 | `165 / 요구 182` | 현행 인구·계절 기반 비축 요건 |
| 기타 상태 | `우물 충족 / 도로 충족 / 역병 없음` | 개별 필터 |
| 예상 이주 규모 | `3~5명(겨울 2~3명)` | 조건을 모두 만족할 경우만 유효 |

- 최우선 거절 사유 우선순위 [제안]: `쿨타임 > 집 부족 > 물 부족 > 도로 미연결 > 식량 부족 > 역병/재난 > 행복도 부족`. **나머지 사유도 툴팁에서 모두** 확인할 수 있습니다. 조건을 여러 개 못 맞췄는데 1개만 표시하지 않습니다.
- **개척지**에는 일반 이주 패널 대신 특별 이주 진행(`1/2회 도착`)과 보충 이주(`현재 7명 / 8명, 다음 보충 18일`)를 보여줍니다. **보충은 일반 조건 미충족으로 `불가`로 보이지 않아야 합니다.**
- 4일 쿨타임이 풀렸지만 지금 조건이 부족하면 `재심사 가능 · 조건 부족`, 충족하면 `조건 충족 · 다음 06:00 심사 때 도착 가능`으로 표기합니다. 이미 오늘 06:00을 지났다면 `지금 즉시 도착`이라고 오해시키지 않습니다.
- `기분`은 −200~200으로 별도 표시하며 **이주 조건 판단에 직접 사용하지 않습니다**. 기분의 행복도 보정은 행복도 수치에 반영된 뒤 간접적으로 영향을 줍니다.
- 도착 이벤트·사유·쿨타임은 핵심 시뮬레이션 공통 질의 API로 제공하여 UI와 CLI/QA의 판단이 달라지지 않게 합니다.

## 4. 행복도·기분 분리 — v1.1 규칙 유지

- **행복도** `happiness`는 **0~100**, 거주환경의 장기 지표입니다. **기분** `mood`는 **−200~+200**, 일시적 사건과 감정 변화 지표입니다. 기존에 `mood`가 행복도를 뜻하던 데이터는 이관합니다.
- 포만·휴식·안전 욕구의 일중 순간 변화는 행복도에 곧바로 반영하지 않습니다. 각 욕구에 대해 24시간 평균을 수집해 **매일 06:00에** `장기평균_new = 0.75×장기평균_old + 0.25×직전24h평균`을 적용합니다. 신규 주민은 현재 실제 욕구로 초기화합니다.
- 보통/평화/혹독 난이도 기본 행복도는 **23 / 31 / 15**입니다.
- 행복도 기본 계산에 주거, 우물, 임금, 세금, 위생, 의료, 통근, 보호구역, 지속 생활환경을 포함합니다.
- 장기 포만 보정: `clamp(12 − 0.15×(100−포만평균) − 0.5×max(0,40−포만평균), −25, +12)`.
- 장기 휴식 보정: `clamp(10 − 0.12×(100−휴식평균) − 0.35×max(0,30−휴식평균), −14, +10)`.
- 장기 안전 보정: `clamp(10 − 0.14×(100−안전평균), −4, +10)`.
- 기분→행복도: `ΔH(m) = sign(m)×[0.03×|m| + 30×(|m|/200)^2]`. 기분 0→0, ±20→약±0.9, ±50→약±3.4, ±100→약±10.5, ±200→±36. 최종 행복도 = `clamp(round(기본행복도+ΔH),0,100)`.
- 세율 1/2/3/4금에 따른 장기 행복도 보정은 **+5 / 0 / −6 / −13**. 세금 설정 가능 범위 1~4, 기본 2. 세율 4는 중과세. **일상적인 식사·수면·출퇴근 시 기분은 0 변화**.

| 기분 사건 | 변화량 및 제한 |
|---|---|
| 주점 이용 | +12, 2일 재보상 쿨다운 |
| 목욕탕 이용 | +10, 2일 재보상 쿨다운 |
| 극장 이용 | +20, 2일 재보상 쿨다운 |
| 교회 이용 | +14, 2일 재보상 쿨다운 |
| 가벼운 부상 | −8, 부상 이벤트 2시간 쿨다운 |
| 중상(HP가 30% 미만에 처음 진입) | −25, 같은 중상 진입 중복 불가 |
| 직접 적에게 위협받음 | −15, 동일 습격에서 1회 |
| 영구 주민 사망으로 공동체에 충격 | 생존 주민 각 −12, 하루 누적 하락 최대 −60 |
| 포만도 20 미만 12시간 지속 | −8/일, 하루 한 번 |
| 임금 체불 | −6/일, 하루 한 번 |
| 평온한 하루 | `mood`를 0 방향으로 2/일 회복 |

- 기분 사건의 중복 적용 방지, 주민 특성 효과 중복 금지, 장기 행복도에 의한 이주·생산·자발 이탈 판정 유지. 해당 주민의 연속적인 열악한 생활은 결국 행복도를 실제로 낮춰야 합니다.
- 일상 스케줄 기본값: **00~06 수면, 06~08 준비/식사, 08~17 노동/교육, 17~21 여가/문화·위생시설, 21~24 귀가/취침**. 경비·의료 등은 예외 근무. 실제 이용한 시설만 기분 보너스 지급.
- UI는 행복도 `61/100`, 기분 `−18/200`, 세 가지 장기 욕구 및 행복/기분의 변화 원인을 따로 보여줍니다.

## 6. 저장고·창고·물류창고의 추가 역할 [확정: 원거리 왕복 단축]

### 6.1 저장량과 전역 재고 유지

| 시설 | 해금/크기 | 기존 저장 효과(변경 없음) | **v1.1.1 추가 기능** |
|---|---|---|---|
| 영주관 | 시작 / **4×4** | 기존 전역 자원 은행의 기본 거점·기본 상한 | 모든 자원 취급 가능한 기본 수령/귀환·식사 거점 |
| 저장고 | 촌락 / **2×2** | 식량 저장 한도 **+650** | **식량 수령·식사·식량 업무 중계** |
| 창고 | 마을 / **3×2** | 식량 +500, 각 비식량 자원 +250 | **모든 자원 수령·반납·식사·업무 중계** |
| 물류창고 | 도시 / **4×3** | 식량 +2,000, 각 비식량 자원 +750; 기존 도로 물류 보너스 | **모든 자원 수령·반납·식사·업무 중계** |

- **창고별 재고 수량·지역 창고 간 운송·운반 도구·마차는 추가하지 않습니다.** 장소마다 재고가 분리되지 않고, 창고에 도착한 주민의 자원 처리도 **같은 전역 은행**을 원자적으로 증감합니다.
- 생산물 수령·반납이 일어날 때 플레이어가 보는 자원량과 생산 장부는 한 번만 바뀝니다. 창고를 여러 개 설치해도 생산물을 복제하거나 자동 추가 생산하지 않습니다.
- 창고의 기존 고정 유지비·건설비·용량·물류창고의 거리 15 이내 생산물 가용률 +20%p 보너스는 **그대로 유지**합니다. 새 근로자 배치를 요구하지 않습니다.

### 6.2 언제 창고를 목적지로 사용하는가

1. **식사할 때:** 주민은 실제 도보 시간으로 도달 가능한 **가장 가까운 식량 취급 거점**(영주관·저장고·창고·물류창고)으로 이동합니다. 식량 1회 소비 및 포만 회복 수치는 기존대로 유지합니다.
2. **업무상 자원 수령·반납이나 집결 거점이 필요할 때:** 사용하려는 자원을 취급하는 **가장 가까운 운영 거점**으로 이동합니다. 예컨대 생산시설 인근의 창고가 영주관보다 가까우면 그곳을 이용합니다.
3. **업무 종료 후:** 원래 AI가 영주관에 모이도록 예정되어 있던 `귀환·집결` 행동은 **근처 적합한 저장시설로 대체**할 수 있습니다. 다만 집이 있으면 **퇴근 후 바로 집/생활시설로 이동**하는 경로를 우선하여 의미 없는 창고 경유를 강제하지 않습니다.
4. **업무 시작 전:** 실제 자원을 수령해야 하는 업무에서만 중간 창고 방문을 허용합니다. **원료를 운반하지 않는 생산 작업은 집→직장 직행**이 기본이며 영주관이나 창고를 의무적으로 경유하지 않습니다.
5. **부상·공격·습격 발생 시:** 저장 거점보다 정상 보호구역·치료소 등 안전/치료 목적지 우선. 저장고가 성벽 밖에 있고 위험하면 집결지로 사용하지 않습니다.

### 6.3 최단 시간 기준·연결·예외 [제안]

- 시설 후보는 **완공·기능 정상·도로 경유 접근 가능·현재 위험하지 않음**을 만족해야 합니다. 저장고는 음식 외 자원 취급 불가. **기존에 도로 연결을 끊는 철거 금지 규칙을 유지**합니다.
- **직선거리 대신 실제 길찾기 비용을 사용**하여 `예상 소요시간(현재 위치→거점 [+ 실제 필요 시 거점→업무 목적지])`이 최소인 거점을 선택합니다. 동률: 거점 ID가 작은 곳 우선.
- [제안] 거리 이득이 **5% 미만**이면 현재 거점을 유지하는 히스테리시스를 적용해 주민이 우왕좌왕하지 않게 합니다. 경로가 막히면 다른 거점을 다시 검색하고, 모든 거점이 막히면 기존 영주관 기본 로직 또는 안전 대기를 수행합니다.
- [제안] 거점 목적지·길찾기 캐시는 **도로/성문/건물 변화, 위협 발생, 실제 도착·실패** 때만 갱신합니다. 매 프레임 전 지도 전체 거점 탐색 금지.
- **통근·이동시간 절감이 실제 생산에 기여**합니다. 한 주민이 작업시간에 2시간 덜 이동하면, 최대 2시간 더 실제 일할 수 있어 농업 유효 노동시간이나 일반 생산이 늘어납니다. **추가 가상의 +생산% 버프는 부여하지 않습니다.** 물류창고의 종전 +20%p 효과는 별도 유지.
- **용량이 가득 찼어도 전역 재고에 해당 자원이 존재하면** 기존 저장시설을 수령 거점으로 사용할 수 있습니다. 저장 용량 상한은 생산·보관에만 적용하고, 물리적 개별 재고가 없는 현재 구조에서 `그 창고엔 식량이 없음` 같은 허위 오류를 내지 않습니다.

**수치 예시 [제안]:** 주민의 도로 반영 걸음속도가 2타일/초이고 식사 장소까지 30타일이면 편도 15초, 새 저장고까지 8타일이면 편도 4초입니다. 동일한 식사 이벤트에서 편도 11초, 왕복 기준 최대 22초를 줄일 수 있습니다. 예시의 2타일/초는 실제 코드의 확정 주민 속도를 뜻하지 않습니다.

| 흙길 | **1.50배** | 66.67 |
| 돌길 | **2.00배** | 50 |
| 교량 | **1.25배** | 80 |

- 도로가 설치된 타일에서는 원래 초원·늪·설원 등의 **지형 이동 페널티를 중복 적용하지 않습니다**. 예: 늪 흙길도 기본속도×1.5, 늪 돌길도 ×2.0.
- 교량은 물 위를 통과하는 도로로, **기본속도×1.25**를 적용합니다. 물에서 따로 `1.65배 패널티`를 곱하지 않습니다.
- 대각 이동을 허용하는 경로탐색은 **대각 거리 ×√2**를 적용합니다. 경로 탐색의 최소 1칸 비용은 돌길의 **50**으로 두어 과대 휴리스틱으로 잘못된 길을 선택하지 않게 합니다.
- 아군·야생동물의 길찾기는 동일한 비용 체계를 공유하되, 수영 가능 동물은 직접 물 횡단 경로를 추가할 수 있습니다. **성벽/성문·적의 통행 규칙은 이번 속도 변경과 독립**입니다.

## 8. 10종 생물군계 월드 생성 및 수역 온도 [확정: 수역 도입, 제안: 판정 수치]

### 8.1 월드 지형

- 월드 192×192, 10종 생물군계 생성 목표 비율은 §7.1과 같습니다. **숲/타이가**는 기존 혼합림/침엽수림의 명칭 변경, **늪·사바나**는 별개 신규 바이옴입니다.
- 늪은 습지보다 **어두운 초록·진한 갈색·낮은 채도**, 깊은 수로·작은 물웅덩이를 더 많이 배치합니다. 시각 효과와 별개로 `swamp` 태그가 있어야 개구리·뱀·악어 가중치를 정상 적용할 수 있습니다.
- 인접 전이대: `타이가↔설원`, `사바나↔초원/사막`, `늪↔습지/호수`를 우선. 정해진 맵 시드를 반복해도 동일 배치가 나와야 합니다. **바위 타일 위 건설 허용, 유적 생성 제외** 유지.

### 8.2 수역 ID와 온도 구분

- 물 타일을 **상하좌우 4방향 연결요소**로 묶어 각 수역에 안정적인 `water_body_id`를 부여합니다. 크기 `A`는 해당 수역의 물 타일 수입니다. 교량은 물 타일의 **밑바탕 수역 ID를 유지**합니다. 교량 건설만으로 하나의 호수를 둘로 분리하지 않습니다.
- 각 수역은 **차가운 수역(COLD) / 따뜻한 수역(WARM)** 중 하나입니다. **월드 생성 시 한 번 결정**하고, 겨울이 와도 생물군계·수역 온도 분류가 뒤집히지 않습니다. 계절별 어업 보정과 수역 온도는 다른 개념입니다.
- [제안: 판정] 해당 물타일 경계에서 **육지로 거리 2타일 이내**인 칸을 한 번씩만 모아 `cold_ratio=(2×설원칸+1×타이가칸)/(2×조사 육지칸수)`로 계산합니다. **`cold_ratio ≥ 0.30`이면 COLD**, 아니면 WARM. 육지 후보가 전혀 없으면 가장 가까운 육지 1개 바이옴으로 판단하고 그것도 없다면 WARM으로 처리합니다. 산술식 분모가 0인 경우 방어 처리 필수.
- 호수 전체를 하나의 온도로 분류하되 경계 인근 서식 조건을 추가합니다. **펭귄은 COLD + 설원 가까이**, **물개는 COLD + 설원/타이가 가까이**, **악어는 WARM + 늪/습지 가까이**, **개구리는 주로 온난한 습지/늪·수역 인근**에서 생성합니다. 오리는 둘 다 가능합니다.
- [제안] 가까움 판정은 스폰 후보 타일 기준 **8타일 이내**에 적절한 육지 바이옴이 있는지 확인합니다. 수역 온도만 맞는다고 사막 호수 중앙에 펭귄을 생성하지 않습니다.

### 8.3 기존 어업 수역 공유 한도 — 변경 없음

- 수역 `A`타일의 일일 기본 어획 한도: **`C(A)=clamp(3+0.12×A, 8, 70)` 식량/일**. 봄·가을 ×1.00, 여름 ×1.10, 겨울 ×0.75의 계절 보정은 기존 유지.
- 낚시터는 반경 5 내 물타일 접근, 건물 기본 최대 식량 5/일. 항구는 접한 **연결 수역 전체**, 기본 최대 15/일. 같은 수역을 이용하는 시설은 **동일 일일 한도**를 비례 배분합니다.
- 예: 200타일 호수는 봄 기준 공동 한도 27/일. 항구 2개의 요청이 15+15이면 각 **13.5/일** 생산. 겨울은 수역 한도 27×0.75=20.25를 기준으로 재배분합니다.
- **수온 구분은 이번 버전에서 어획량 상한·물고기 개체 재고를 변경하지 않습니다.** 수역의 COLD/WARM은 동물 생성과 시각 정보에만 적용합니다. 어종 개별 소모 없음.
- 수역 UI [제안]: 마우스를 올리면 `차가운 수역 · 200칸 · 오늘 공동 어획 한도 27`처럼 표기, 비탐험 영역에서는 정보를 숨깁니다.

## 10. 서식 지역별 생물량 예산과 야생동물 총량 [확정: 도입, 제안: 수치]

### 10.1 '바이옴별 5마리'의 구현 단위

- **생물군계 종류 전체(초원 전체 등)에 5마리**가 아니라, 지도의 **서로 떨어진 구역/연속된 주요 생물군계 구획을 묶은 하나의 `서식 지역(habitat_region)`당 평균 약 5마리**를 목표로 합니다. 그렇지 않으면 바이옴 10종×5마리=50마리로 기존보다 동물이 크게 감소하여 `전체 수 소폭 증가` 조건과 모순됩니다.
- [제안] 월드 생성 후 생물군계 연결요소를 추출하고 큰 구역은 분할, 지나치게 작은 구역은 인접한 곳과 묶어 **전 지도 약 28~32개 서식 지역(기준 30개)**을 만듭니다. 각 지역은 `주요 바이옴`과 `지배적 서식조건`, `area_tiles`, `wild_count`, `used_biomass`, `capacity_biomass`, `target_count`를 가집니다. 최소한 모든 육지·수역 생태 구획이 어느 지역에 속해야 합니다.
- **초기 활성 야생동물 목표 약 150마리 [제안]**(v1.1 목표 140보다 약 7% 증가), **전역 활성 야생동물 최대 180마리 [제안]**. 가축과 적은 이 상한에서 제외합니다. 30개 지역×평균 5마리≈150마리. 실제 서식 적합 구역이 부족하면 억지로 초과 생성하지 않습니다.
- 한 지역의 동물 수는 **기본 목표 5마리**, [제안] 국지적 허용 범위 **3~7마리**, 절대 지역 상한 **7마리**입니다. 종류마다 생물량이 달라 5마리를 정확히 맞추지 못해도 자연스러운 변동으로 취급합니다.

### 10.2 생물량(Biomass) 값과 총한도

- 동물 한 마리의 생물량은 §9.1 표의 **1~6** 정수입니다. **1: 개구리·토끼·조류·뱀 등 소형, 2~3: 중형, 4~5: 대형/맹수, 6: 코뿔소**입니다.
- [제안] 지역별 생물량 상한은 `B_cap = clamp(round(5 × μ_region), 8, 22)`, 여기서 `μ_region = 그 지역 스폰 후보 동물의 확률가중 평균 생물량(필터 적용 후)`입니다. 지역당 작게는 8, 많아도 **22**이므로 지나치게 큰 수치를 사용하지 않습니다. 실제 게임에서 한 구역의 가용 공간이 극히 작으면 `B_cap = min(B_cap, max(3, floor(구역 타일수 / 40)))` 보정을 추가해 작은 늪 20타일에 대형 동물이 5마리씩 생기는 일을 막습니다.
- **생물량 사용량** = 그 지역의 **살아 있는 야생동물 생물량 합계**. 종 1마리를 추가할 때 `used + species_biomass ≤ cap`이어야 합니다. 크기가 큰 종은 예산을 많이 차지하므로 같은 지역에서 많이 출현하지 않습니다.
- **예시 A:** 초원 지역 생물량 상한 **12**일 때 토끼 3마리(3) + 사슴 2마리(6) + 꿩 1마리(1) = 생물량 10, 6마리. 버팔로(5) 추가는 상한 초과이므로 불허.
- **예시 B:** 사바나 지역 생물량 상한 **19**일 때 사자 1마리(4) + 버팔로 1마리(5) + 타조 2마리(6) + 하이에나 2마리(4) = **19, 총 6마리**. 코뿔소(6)는 다른 개체가 죽거나 지역을 떠나 여유가 생긴 뒤에만 출현.

### 10.3 생성·이동·사냥 후 회복 알고리즘

1. 매 시드 생성 시 **지역 구획을 확정**하고 `지역 목표 개체 수 ≈5`, `지역 생물량 상한`을 계산합니다. **초기 개체 150마리는 지역 예산을 지키며 생성**하되 150이라는 숫자를 달성하려고 동물을 강제 주입하지 않습니다.
2. [제안] 게임 날짜가 바뀌는 **매일 06:00**, 부족한 지역부터 **전 지도 합계 최대 20회** 스폰을 시도합니다. 각 시도의 생성 성공 확률은 **기본 45%**, 지역이 목표 개체수의 절반 미만이면 **70%**, 개체수 7 또는 생물량 상한 초과 시 **0%**입니다.
3. 종은 §9.2의 바이옴별 확률표로 1회 선택하고, 수온·서식지·잔여 생물량·맹수 지역 상한에 맞지 않으면 **최대 5회 재추첨**합니다. 실패하면 그 시도는 실패로 기록하며 동물을 생성하지 않습니다. 스폰 위치는 비가시·안전한 미점유 타일, 시설·벽 내부와 겹치지 않게 합니다.
4. 동물이 사망·사냥·지역 이동으로 사라지면 **이전 지역의 사용 생물량이 즉시 감소**합니다. 지역 간 이동은 **목적지의 개체수/생물량 한도 여유가 있을 때만** 허용하고, 원래 지역은 빠져나간 순간 예산을 반환합니다. 단순 애니메이션 위치 변경은 지역 이전으로 집계하지 않습니다.
5. [제안] 사냥 압력: 해당 지역에서 최근 12일간 5마리 이상 사냥/처치되면 다음 6일간 **스폰 성공률×0.70**. 과도한 연속 사냥으로 동물이 무한히 생기는 현상을 방지합니다. 기간 경과 후 회복합니다.
6. 활성 야생동물이 전역 180마리에 도달하면 어떤 지역도 신규 스폰하지 않습니다. 가축의 수는 각 목축시설의 6/16마리 정원으로 별도 관리합니다.
7. **확률표와 생물량 예산은 동시에 적용**합니다. 표는 `무슨 동물인가`, 생물량은 `그 지역에 얼마나 더 살 수 있는가`를 결정합니다.

**중요한 수치 구분:** `서식 지역 평균 5마리`는 **동물 개체 수**, `지역 상한 8~22`는 **생물량 합계**, `전역 150/180`은 **야생 개체 수**입니다. 서로 다른 단위입니다.

- **동일 시점 구매가와 판매가에 같은 시장 변동률**을 적용합니다. 기본 매입/매도 스프레드는 그대로 유지합니다.
- 종별 변동률 `R = clamp(S_계절 + E_사건 + P_순거래량, −0.12, +0.12)`.
- **최종 구매/판매 금액** = 기본 단가 × 거래수량 × `(1+R)`을 계산한 뒤 **총액 기준으로 금화 정수 반올림**. 가격 표시에는 소수 두 자리의 `금/개` 예상값을 보여줄 수 있습니다. 저가 품목도 여러 개 거래하면 가격 변화가 의미 있게 나타납니다.
- [제안] **왕립 교역 연구의 판매가 +10%**는 변동률 계산 후 **판매 금액에 한 번만 곱하고**, 중복 적용하지 않습니다. 구매에는 연구 보너스가 없습니다. 항상 실제 판매 단가가 구매 단가보다 낮게 유지되도록 검사합니다.

**계절 변동률(%) [제안] — 자원의 거래가 기준, 아래 외 품목은 0%**

| 자원군 | 봄 | 여름 | 가을 | 겨울 |
|---|---:|---:|---:|---:|
| 식량 | **+2** | **−1** | **−4** | **+5** |
| 약초 | **−2** | **−2** | **+1** | **+3** |
| 원목·목재 | **0** | **−1** | **+1** | **+3** |
| 석탄 | **−1** | **−1** | **0** | **+4** |
| 돌·점토·벽돌·철광석·철괴·금광석·금괴·마정석·가죽 | **0** | **0** | **0** | **0** |

**사건 보정(%) [제안] — 현재 운영 중인 사건만 적용**

| 시장 사건 | 해당 품목 | 발생 중 보정 | 지속 | 중첩 |
|---|---|---:|---|---|
| 흉작·광역 식량 부족 | 식량 | **+6** | 기존 재난 지속기간, 최대 6일 | 동일 종류 중첩 없음 |
| 풍작·식량 공급 과잉 | 식량 | **−5** | 해당 사건 종료까지 최대 6일 | 동일 종류 중첩 없음 |
| 혹한·연료 수요 급증 | 원목·목재·석탄 | **+4** | 해당 혹한 지속기간 최대 6일 | 동일 종류 중첩 없음 |
| 광산 붕괴·금속 공급 부족 | 철광석·철괴 | **+5** | 해당 사건 지속기간 최대 6일 | 동일 종류 중첩 없음 |
| 교역 호황 | 금광석·금괴·가죽 | **+3** | 해당 사건 지속기간 최대 6일 | 동일 종류 중첩 없음 |

- `시장 사건`은 **실제 게임에 있는 재난/사건이 활성화되었을 때만** 가격을 변경합니다. 위 표의 사건이 아직 구현되어 있지 않다면 새로운 이벤트를 억지로 자동 발생시키지 않고 **0%**로 처리합니다. 향후 이벤트 추가가 가능하도록 가격 보정 인터페이스만 마련합니다.
- 사건이 여러 개 중복될 수 있으면 **같은 자원에 대해 총 사건 보정은 −6%~+7%**로 제한한 후 전체 ±12% 상한도 적용합니다.

**구매·판매 누적에 따른 품목별 수요 압력 [제안]**

- 자원 `r`마다 `pressure_r`을 **−5%~+5%**로 저장합니다. **사용자가 구매 10개당 +1%p, 판매 10개당 −1%p** 증가합니다. 거래 수량이 10의 배수가 아니면 소수 부분을 남기고 다음 거래에 누적합니다. 일중 여러 번 거래해도 누적 거래량이 같으면 결과가 같도록 합니다.
- **매일 06:00 가격압력은 0% 방향으로 1%p 완화**합니다. 값이 절댓값 1%p 미만이면 0으로 만듭니다. [제안] 상품 재고 6일 보충은 이 압력 초기화와 별개입니다.
- 한 거래에서 대량 거래하는 것과 나눠 거래하는 것 사이에 시세 차익이 생기지 않도록 **수량을 1개씩 순차 산정하거나 동등한 누적 구간 합산**을 적용합니다. 결제·재고·압력 갱신은 한 거래로 원자적으로 처리합니다.
- 가격 변동은 영지의 실제 세계시장(모든 거래시설 공용) 기준입니다. 여러 시장을 건설해 가격압력을 복제하거나 리셋할 수 없습니다.

### 13.3 변동 예시·상한

- **겨울 식량:** 기본 구매 2금 × 계절 +5% = **2.10금/개**. 20개를 단독 구매할 때 압력 변화 전 단순 견적은 **약 42금**(실제 확정 결제는 건별 내부 압력 반영에 따라 소폭 차이). 기본 판매 1금은 같은 시점 단순 견적 **1.05금/개**.
- **철괴 구매 누적 50개:** 계절·사건 보정이 없다면 구매량 압력 **+5%p 상한**. 이후 추가 구매 수요가 있어도 압력은 +5%p 유지, 다음 날 06:00에는 +4%p로 완화됩니다.
- **최종 변동 한도:** 계절+사건+순거래량을 모두 합해 **기본가 대비 최소 −12%, 최대 +12%**. 시장이 수십 배 요동치지 않습니다. 왕립 교역 연구의 판매 보너스는 별도 **+10%**입니다.
- 가격 UI에는 `현재 구매가 / 현재 판매가`, `기준가 대비 ±%`, `이유(겨울+5%, 교역 수요+2% ...)`, `예상 총액`, `재고`, `남은 일일 거래량`을 표시합니다.

## 14. 주민·동물·저장시설 이동 최적화 및 성능 [제안]

1. **지형/도로 경로 비용 통일:** 실제 이동 시간과 A* 길찾기 비용은 §7의 동일 배율을 사용합니다. 단순 타일 개수로만 이동시간을 예상하면 늪·산악·교량에서 잘못된 창고를 고를 수 있습니다.
2. **주민 집결 캐시:** 가장 가까운 업무용 저장시설 결과를 `current_target, path_revision, safety_revision`으로 캐싱합니다. 도로·성문·보호구역 변경/시설 파괴/재건축 시만 갱신합니다. 창고를 선택하는 판단 자체가 새 통근 손실을 만들지 않는지 체크합니다.
3. **야생동물 지역 캐시:** 지역 ID와 생물량 사용량은 상태 변동 때만 갱신합니다. 동물 1마리 움직일 때마다 월드 전체 36,864칸을 다시 순회하지 않습니다.
4. **원거리 개체 저빈도 업데이트:** 화면·주민·경비 근처의 동물은 행동과 전투를 정상 해상도로 계산하고, 먼 지역은 1초/일 단위 이벤트 등으로 요약. 단, 원거리 사냥·번식·사망·생물량 감소의 결과가 달라지지 않도록 RNG 상태 관리.
5. **단일 측면 애니메이션:** 기존 스프라이트 4방향 아틀라스 요구를 없애고 1방향+`flipX`로 메모리·드로우콜·제작 비용 절감.
6. **대표 가축 렌더링:** 가축 실제 재고 최대 16마리여도 방목장 렌더 프록시는 최대 8개. 가축 프록시마다 A* 또는 야생 AI를 실행하지 않습니다.
7. **거래 압력 업데이트:** 자원별 정수 basis point/고정소수점으로 계산해 플랫폼별 결과를 동일하게 유지합니다. `가격 계산→돈·재고 검사→전액 결제→시장 압력 반영` 순서 보장.
8. **게임 시간과 시각 연출 분리:** 사망 이펙트 1초는 렌더 잔상만 유지하고 살아 있는 동물 수·생물량에서는 사망 순간 제외합니다. 일시정지 중에는 시뮬레이션과 이펙트 시간 정책을 통일합니다.

## 17. 적용 순서 및 완료 조건

1. **데이터/저장 버전 정비:** 4×4 영주관 비회전, 10바이옴, 수역 온도, 24종 동물, 생물량, 주민 기분/장기 행복과 이주 상태 필드 정비.
2. **인구 보호·이주·주민 탭:** 전 등급 영구 인구 8명 자발 이탈 하한 → 개척지 보충/일반 4일 쿨타임 → 실패 사유 통합 API/UI/로그.
3. **이동·저장시설:** 지형별 완화 이동비용·고정 도로 속도 → 영주관/저장고/창고/물류창고 공용 거점 → 길찾기·실근무시간 검증.
4. **월드·생태:** 늪/사바나/개명 → 수역 ID·수온 → 20종 야생 + 4종 사육, 지역 평균5마리·지역 생물량·전역 180 상한 → 자연 스폰에서 가축 제거, 포획 제거.
5. **애니메이션·전투:** 동물 옆모습/flipX만 사용, 수영5·공격9 측면 클립 → 피격 틴트/체력바/사망 기울기.
6. **경제:** 기준 가격 보존, ±12% 계절·사건·품목 거래 압력 및 거래 UI, 거래/재고/재정 장부 테스트.
7. **검증·성능:** 단위·통합/세이브 회귀 → 동일 144시드×200일 → 수동 플레이 → 정상 부하 180과 디버그 과부하 300 분리 측정 → QA 결과와 실제 코드 동기화.

### 최종 충돌 해결 메모

- **영주관 회전 불가**가 v1.1의 4방향 영주관 아트 요구보다 우선.
- **버팔로 명칭과 비수영**, **뱀 비수영**이 v1.1의 물소·7종 수영보다 우선.
- **동물의 단일 측면 스프라이트**가 v1.1의 4방향 동물 아트 요구보다 우선.
- **가축 4종 야생 출현 금지 및 포획 삭제**가 v1.1 일부 바이옴의 소·양·돼지 출현 확률보다 우선.
- **지역별 생물량 + 150/180 야생 총량**이 v1.1의 초기 140/전역 최대300보다 우선.
- **저장시설 거점화는 전역 자원 은행을 분산 재고로 바꾸는 변경이 아님**.
- **시장 가격은 기준가를 그대로 유지하면서 최대±12%로 소폭 변화**, 거래 가능 품목과 연구 보너스는 기존 의도된 설정 보존.
- 수역 차가움/따뜻함은 **동물 서식 속성**이며 어업의 공동 한도·계절 산출은 그대로입니다.
- **모든 영지 등급에서 자발적 이탈만 8명 하한**이며, 사망과 계약직 귀향은 제외합니다.
