# 그래픽 마무리 이미지 인계

이번 단계는 **이미지 생성과 인계 자료 작성만** 수행했습니다. 기존 구현 작업은 중단 상태로 보존했으며 새 그림을 게임 실행 경로에 연결하거나 전체 빌드·테스트를 통과한 것으로 표시하지 않습니다.

별도 코딩 세션에는 [전체 전달 요청](GRAPHICS_FINISH_CONTINUATION_PROMPT.md)을 복사하세요. 원본 요청·참조 경로·SHA256·실제 크기·선택 상태는 `art/recipes/graphics_finish_image_generation.json`에 있습니다.

## 채택하지 않은 출력

- `carried_lights_source.png`, `stationary_fires_source.png`: 여백이 부족한 최초 출력입니다. 생성 근거를 위해 보존하며 실제 패킹은 `padded` 시트를 우선 사용합니다.
- `actor_neutral_color_guide.png`: 원래 상인의 그림체·비율을 지나치게 재해석하여 **배제**했습니다. 기존 `game/assets/units/merchant.png`와 기존 표면 지침을 사용하세요. 새 생성 호출은 필요하지 않습니다.

## 후속 처리에서 지켜야 할 점

1. 생성 도구의 실제 출력 크기는 요청한 크기와 다릅니다. 원장의 실제 크기를 사용하고 셀 경계는 `round(index * width / columns)` 형태로 정하세요. 고정 128화소 원본 셀로 가정하지 않습니다.
2. 원본 그림에는 반투명 테두리·미세한 분리 화소와 프레임 간 고체 부분의 작은 차이가 남을 수 있습니다. 코딩 단계에서 알파·팔레트·기준점·안전 여백을 정리하고 정수 패킹을 검증하세요. 이 단계에서 픽셀 최종본으로 인증하지 않았습니다.
3. 색·표면 참고는 원화의 정확한 실루엣을 대체하지 않습니다. 원래 그림과 알파를 보존하고, 새 이미지는 보정 방향과 마스크 작성에 참고하세요. 법선은 정규화·축·단위 길이·좌우 반전 검사, 높이는 실제 기하 높이 검사가 필요합니다. 회색 원화 밝기를 그대로 높이로 사용하지 마세요.
4. 클라우드 참고 그림은 높은 해상도의 색·형태 방향입니다. 최종 효과는 게임과 같은 논리 화소로 GPU에서 생성하며, 시야 밖과 추가 한 칸을 완전히 가리는 불투명 바탕이 필요합니다.
5. 기존 원화와 표면 규약, 새 휴대/고정 불 원본이 있으므로 추가 AI 그림 생성 없이 구현을 계속할 수 있습니다. 기술 지도 굽기·원화 보정·패킹·절차 효과 구현은 별도 코딩 세션의 작업입니다.

## 중단한 코드 작업 복원

Claude 등 작업 공간을 공유하지 않는 도구에는 별도 `graphics-finish-claude-handoff.zip`을 사용하면 됩니다. 이 묶음의 `repository-overlay/`에는 코드 체크포인트와 새 이미지·문서·원장을 이미 올바른 순서로 합쳤습니다. 로컬 저장소의 변경을 확인한 뒤 이 폴더 내용을 저장소 루트에 적용합니다. 별도 tar 복원을 다시 할 필요가 없습니다. 묶음 맨 위의 `CLAUDE_START_HERE.md`와 `PROMPT_FOR_CLAUDE.md`는 원래 대화나 클라우드 경로 없이 사용할 수 있는 시작 안내와 전체 요청입니다.

- 분기: `codex/main-screen`, PR: https://github.com/jkanggpt/project/pull/6, 기반: `codex/structure-cleanup`.
- 마지막 검증된 커밋: `53bf361837b34c7c98195d172d77662521483f69`.
- 기존 작업 공간에는 미커밋 구현 변경을 그대로 남겼습니다. 새 그림 생성 때문에 프로그램 소스를 수정하지 않았습니다.
- `build/reports/graphics-finish/image-only/code-checkpoint.tar.gz`에는 이미지 작업 시작 시점의 수정·신규 파일 44개가 있습니다. 정확한 파일 목록과 SHA256은 옆 `code-checkpoint.json`에 있습니다. 삭제 목록이나 `.git` 자료는 포함하지 않습니다.
- 새 체크아웃에서는 위 커밋을 기반으로 올바른 작업 분기를 선택한 뒤 체크포인트를 저장소 루트에 풀고, 이미지 인계 묶음의 아트·문서·원장을 그 위에 덮으세요. 기존 작업 공간이라면 체크포인트를 다시 풀지 말고 현재 diff를 계속 사용하세요. 사용자나 다른 세션의 새 변경을 덮지 않도록 먼저 확인합니다.
- 마지막 통합 빌드 기록에는 `CoreBoatView`의 없는 `id` 필드 참조 오류가 있습니다. 표면 지도 발행·브리지·실제 게임 검토 모드도 미완료일 수 있습니다. 파일 존재를 완료·검증 근거로 사용하지 마세요.
- 이 중단 코드는 원격 PR에 푸시하지 않았습니다. 새 코딩 세션은 복원·통합·검증 뒤에 허용된 분기로만 커밋·푸시해야 합니다.

## 권리와 파이프라인

새 원본은 내장 `image_gen`으로 생성했습니다. 편집 참조는 기존 프로젝트 그림뿐이며 다른 서비스의 그림이나 셰이더 코드를 복제하지 않았습니다. 생성·파생 아트에 대해 프로젝트가 보유하는 권리는 기존 `game/assets/licenses/generated-art.txt`의 CC0 1.0 정책을 따릅니다.

이번 원본은 아트 입력으로 등록합니다. 런타임 원장의 프레임·해시·크기 등록, 제작 단계 연결, 재생성·재현성 검사는 코딩 단계의 패킹 결과에 대해 수행해야 합니다. 참고 이미지나 배제 출력을 게임 필수 텍스처로 등록하지 마세요.
