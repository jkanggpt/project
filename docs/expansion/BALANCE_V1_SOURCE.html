4. 생산·소비 규칙 — 예외 없는 상세 명세

4.1 가을 일괄 수확: 파종·종자 소비 없음

경작지, 농장, 관개농장은 매년 봄·여름 24일(1~24일) 동안 누적한 실제 유효 노동시간으로 그해 수확량을 결정합니다. 파종 행동·파종률·파종비·종자 식량 지출은 전부 삭제합니다. 가을 첫날(그해 25일 08:00)에 해당 연도의 수확량을 한 번에 산정합니다. 가을에는 해당 작기의 노동이 더 이상 누적되지 않습니다.

  • 기준 유효 인시 H0 = 근로정원 × 9시간 × 24일. 경작지 432, 농장 648, 관개농장 1,080 유효 인시.
  • 한 주민의 매 근무시간 기여는 실제 근무시간 × 그 시점 실제 노동효율입니다. 행복·건강·5능력치·분야 숙련·특성·관련 연구 및 재해가 효율에 반영됩니다. 직업 배정만 하고 실근무하지 않았다면 0시간입니다.
  • 명목 수확 Q0 = 경작지 식량 360, 농장 600, 관개농장 1,300.
  • 최종 수확량 floor(Q0 × clamp(H_eff / H0, 0, 2.5) × 가뭄계수 × 풍차계수); 기준 일반 노동자(효율1.0) 전원이 24일간 빠짐없이 하루9시간 근무하고 가뭄 없고 풍차 없을 때 정확히 Q0가 수확됩니다. 능력치·숙련도가 우수하면 Q0를 초과할 수 있습니다.
  • 가뭄계수: 경작지·농장 0.55, 관개농장 0.90, 가뭄 없음 1.0. 풍차 반경10 건물의 산출 ×1.40(다수 풍차 중첩 없음). 풍차 효과는 수확 순간 적용합니다.
  • 가뭄과 풍차는 유효 노동시간에 넣지 않고 수확 순간에만 한 번 적용합니다(중복 보정 방지). 봄/여름 중간에 건설된 농장은 완성된 시점부터 실근무시간만 누적합니다. 25일 이후 새로 완공된 농장은 다음 해 작기에 합류합니다. 건물 철거 시 해당 연도 누적 노동은 소멸합니다.
  • 식량 저장 공간이 수확량보다 작으면 가을 첫날 한 번에 수확은 확정하되 초과분은 해당 농장에 미반입 수확물로 최대 4일 보관합니다. 저장 공간 확보 시 자동 반입하며, 4일 뒤 남은 미반입분은 부패·소실됩니다. 별도의 추가 수확 노동은 요구하지 않습니다.
  • 텃밭은 주기 생산이고, 온실은 사계절 생산입니다. 과수원은 완공 후 24일간 생산 0; 25일째부터 여름·가을에는 식량 12/일을 주기적으로 생산하고 봄·겨울에는 생산하지 않습니다. 최초 조성 후 1년 미수확 규칙은 폐지합니다.

4.5 어업: 수역 단위 공동 한도, 자동 공정 배분

물 타일이 4방향으로 연결된 각 덩어리를 수역 ID로 관리합니다. 어류 개체 재고는 감소하지 않습니다. 대신 수역 ID별 하루 전체 식량 생산량 한도가 존재합니다.

  • 수역 규모 A=해당 ID 물 타일 수, 기본한도 C(A)=clamp(3+0.12×A, 8, 70) 식량/일.
  • 계절 보정은 봄·가을 ×1.00, 여름 ×1.10, 겨울 ×0.75. 예: 50칸 수역 → 기본9/일, 200칸 →27/일, 400칸 →51/일.
  • 낚시터는 건물에서 반경5 내 연결 수역 물타일 수 A5를 세고 희망 어획 D낚시 = min(5, 0.25×A5) × 실제 노동효율. 항구는 건물에 직접 접한 수역 전체 A를 쓰고 D항구=min(15, 3+0.12×A) × 실제 노동효율.
  • 동일 수역을 이용하는 모든 시설의 희망 어획을 합산해 D합계로 두고, 공유 배율 r=min(1, 수역 당일 한도 / D합계)를 적용합니다. 시설 실제 생산량 = D시설×r. 따라서 같은 수역에 항구를 여러 개 건설해도 공동 한도를 초과하지 못합니다. 특정 시설이 먼저 점유해 독식하는 순서 의존성도 없습니다.
  • 예: A=200칸인 호수에서 항구 2개가 각각 15를 요청하면 합계30, 공동한도27이므로 양쪽 13.5식량/일. 항구 한 개와 낚시터 두 개(각5)면 총요청25로 한도27 이하여서 15+5+5=25 생산합니다.
  • 낚시터가 여러 수역을 접하면 반경5에 포함된 물타일이 가장 많은 수역을 자동 선정합니다(동률일 때 수역 ID 순). 항구도 인접한 수역 중 가장 면적이 큰 하나를 자동 선정합니다. 수역 선택 UI 없음. 수역 한도는 매일 자정 초기화합니다.
  • 해당 수역이 얼거나 접근 불가능하면 당일 어획0. 계절 보정 이후 최종 산출량은 시설 자체 한도와 노동효율을 우회하지 않습니다.

6. 도로·배치·시야·보호구역·전투 자동화

6.1 건설 위치와 연결 도로 보호

  • 도로망은 상하좌우 4방향으로 연결합니다. 초기 성채 출입구와 닿는 도로를 주도로망으로 판정합니다. 도로·교량·성벽·문과 개척지 건물은 도로 인접 조건의 예외이고, 촌락 이상 일반 건물은 출입구 앞 한 칸이 주도로망이어야 건설할 수 있습니다. 건물 회전(90°)과 출입구 방향 표시를 지원합니다.
  • 도로 철거 보호(사용자 확정): 도로 타일 제거·철거·다른 시설로 덮어쓰기 전에 연결 컴포넌트를 다시 계산합니다. 현재 도로망에 연결된 완공 건물 한 곳이라도 성채 연결을 잃는다면 그 행위를 허용하지 않습니다. 단순 경고나 생산 페널티가 아니라 명령 자체를 거부합니다.
  • 예: 주택으로 이어진 유일한 흙길 1칸을 철거하려 하면 연결된 건물 1곳의 도로가 끊어져 철거할 수 없습니다.라고 표시합니다. 새 우회 도로를 먼저 건설해 연속 경로를 확보하면 기존 길을 철거할 수 있습니다.
  • 흙길→돌길 교체는 원자적(한 틱 안에 연결 유지)으로 처리해 도로 연결이 끊기지 않습니다. 교량도 물 타일 도로로 취급합니다. 적은 도로 자체를 파괴하는 표적 우선순위를 가지지 않고, 도로의 일반적 내구도·자연 붕괴도 이번 범위에서 적용하지 않습니다.
  • 돌/암석 타일 위에는 모든 일반 건물을 정상 배치 가능합니다. 암석은 건설 장애물이 아닙니다. 해당 타일의 지하 광상 매장량은 별도 계층에 보존되어 주변 광산이 채굴할 수 있습니다. 물 타일 위 일반 건물 배치는 계속 금지합니다.

6.3 성벽 보호구역

성벽/성문은 외부와 내부를 가르는 막힌 경계로 판정합니다. 맵 외곽에서 flood fill을 수행할 때 벽·정상 성문은 통과 불가, 실제 주민 이동에서는 성문 통과 가능. 파괴된 문·벽체로 누수가 발생하면 보호구역 면적과 보호 인구가 다시 계산됩니다. 주민은 위험 시 가까운 정상 보호구역으로 대피하고, 보호구역 거주 주민은 안전 욕구 +12. 승급에서는 보호 면적과 보호받는 영구 주민 비율을 함께 요구합니다. 계산은 도로·벽의 변화 때만 수행하며 매 프레임 재계산하지 않습니다.

6.4 안개, 탐색, 적 감지와 병영 자동 출동

  • 시야는 미탐험 / 탐험했으나 현재 안 보임 / 현재 가시 세 단계입니다. 과거 발견한 지형·광상은 기억하지만 가시 범위 밖의 적·야생동물은 표시하지 않습니다.
  • 현재 시야 범위: 성채8, 연결도로1, 정상 운영 일반 건물2, 초소6, 망루10, 감시탑12, 쇠뇌탑·포탑9, 마도포탑14, 수렵기지8.
  • 습격 발생 시각 사전 카운트다운 없음. 적이 위 시야 또는 주민 시야에 들어온 순간 발견 경보를 띄웁니다. 주민이 적을 뒤늦게 발견했다면 경보도 늦게 발생합니다.
  • 병영 경비병은 플레이어가 출동 명령을 내리지 않습니다. 적이 발견되면 자동으로 가까운·위협도가 높은 가시 적군을 목표로 지정하고 경로를 따라 이동합니다. 여러 병영이 있다면 거리와 적 위협도를 기준으로 출동 인력을 분산합니다. 사거리 밖 추적 시 최종 발견 지점까지 이동 후 정상 순찰/귀환 상태가 됩니다.
  • 첫 대규모 습격은 보통 난이도 18일 이전 발생하지 않으며, 초반 두 차례는 적 3~5명 범위에서 시험합니다. 감시탑 1명 근무 필수, 무인 상태 공격0·시야2.

9.2 계약직 고용

  • 계약기간 정확히 12일; 가용 노동시간에서 입·출국 이동시간 소모.
  • 숙소·식량·우물이 필요. 계약직은 능력치·특성·숙련도를 가진 실제 주민 객체이지만 영구 인구/영구 주민 이주율에는 미포함.
  • 고용 즉시 12일분을 선불 결제하며 계약 기간 중 정규직 임금·세금 중복 계산을 하지 않습니다.
  • 고용료: ceil(12×해당 직업 기본일급×1.5×고용품질계수+5), 품질계수는 clamp(1+0.30×(직업효율−1)+0.20×숙련단계, 0.8, 2.6).
  • 고용후보 목록 갱신은 노점·시장·교역소 모두 고정 3일마다 00:00입니다(첫 등장 1일째, 이후 4·7·10일째). 개별 지원자의 능력치와 가격은 해당 갱신 기간에 고정되며 수동 재추첨 버튼 없음.
  • 후보 수는 노점3·시장8·교역소15. 영지 동시 고용 상한은 가장 높은 운영 시장 기준 1·3·8명. 고용 가능 후보는 해당 창구 운영 시에만 표시됩니다.
  • 계약 만료 시 귀향하고 재고용되면 이전 능력치·숙련도는 유지합니다. 계약 갱신도 12일치 신규 선불입니다.

9.3 시작 보통 난이도 초기상태

영구 주민 4명, 시작 성채·우물1개, 금화 160, 식량 125, 원목 65, 돌 12, 약초 5, 마정석 5, 나머지 0. 식량 소비 1.2/명/일이므로 생산이 완전히 없어도 초기 식량만으로 약 26일을 버틸 수 있습니다(4명×1.2=4.8/일, 부패 제외). 초반은 텃밭·채집장·낚시터 등으로 식량을 보충해야 합니다. 개척지에서는 노점이 아직 없어 계약직을 고용할 수 없으므로 개척지 특별 이주단을 2번(회당 2명, 총 4명) 보장해 4명→8명까지 도달 가능하게 합니다. 두 차례 모두 식량·숙소·우물·기분 요건은 만족해야 하며, 미충족 시 다음 날 다시 심사해 누락된 회차를 소멸시키지 않습니다. 두 이주가 완료되기 전에는 개척지의 일반 이주 타이머로 전환하지 않습니다.

13. 구현·데이터 이전 규칙

  • C 공개 API: 6자원→15자원, 16건물→64건물, 5등급→6등급, 4능력치→5능력치. 건물 해금 비트셋을 32비트에서 64비트 이상으로 확장합니다. CORE_ABI_VERSION과 Godot C# ExpectedAbiVersion을 함께 올립니다.
  • 저장: 작기별 농장 누적 유효 노동시간, 과수원 완공일, 각 나무 잔여 원목과 당일 채취 한도, 광물 광상별 매장량, 수역 ID/하루 어획 장부, 가축·동물, 세율, 계약직과 갱신일, 주민 초기 능력치·현재치·XP·숙련도, 의료 자격, 도로망/탐험 이력 등을 저장합니다.
  • 도로 구조: 삭제 전 연결 건물 보존 여부를 검사. 경로 교체는 원자적으로 처리하고, 불가능한 철거는 아예 입력 거절. 도로 자체는 적의 파괴 대상이 아님. 길찾기 경로 캐시는 추가·교체 시 갱신합니다.
  • 경제 장부: 개별 시설별로 입력 자원 소비, 산출 자원 생산, 비소모 보너스, 고정 금화 유지비, 임금, 연료 FU를 분리 기록합니다. 하나의 수치를 소비와 생산에 동시에 표현하지 않습니다.
  • 작기 연도: 봄1~여름24일간 노동을 모아 가을25일 한 번에 계산. 파종 상태·수동 노동 재배치·추가 가을 수확 근무를 만들지 않습니다.
  • 마법 공방: 연구 점수는 단순 보너스가 아니라 연구 시스템에 누적되는 산출이고, 반경 생산 보너스는 별도 능력입니다. 마정석이 부족하면 둘 다 정지합니다.
