# 통합 확장 v1.0 검사 기록

## 환경과 방법

- Windows, CMake4.3.2, MSVC19.29 / MinGW GCC16.1 Release, 자체 코드 경고를 오류로 처리합니다.
- C11/raylib 실행판으로 검사하며 Godot·.NET SDK는 사용하지 않습니다.
- `castle_expansion_balance --days 200 --seeds 48`로 평화·보통·혹독, 각 시드1~48을 실행합니다.
- 공개 배치·거래·배정·승급 API와 실제 C 경로·출입·전투를 사용하며 자원·인구·연구를 추가 지급하지 않습니다.
- 일별 CSV, 매일 전체 상태 검증, 습격이 없는 최종 상태의 저장 왕복 해시를 확인합니다. 패배한 판은 그 날짜에 멈춥니다.
- 144시드 실행이 모두 종료 코드0으로 끝났습니다. 상태/저장 오류는0건입니다. 활성 습격이 없는 129판에서 저장/로드 해시가 일치했고, 나머지15판은 게임의 습격 중 저장 금지에 따라 저장 검사를 건너뛰었습니다.

왕성 도달은 **0/144**이며 160~190일 목표를 충족했다고 주장하지 않습니다. 모든 봇의 보호구역 설계가 다음 승급을 확보하지 못했습니다.
원본 CSV와 로그는 `artifacts/expansion/quality-final`, 간추린 결과는 `simulation_results.csv`입니다. 중간 실패 실험 폴더와 최종 결과를 구분합니다.
검사 실행 파일 SHA-256: `7B2EB48B8E26FE98B9983FFB96AA65A888ABC44F979A98754656B40AC537F691`.
하루6시에 시작해 200일을 진행하므로 끝까지 생존한 판의 마지막 달력 날짜는201일입니다.

장기 측정 뒤 왕성 연구 연금술의 10% 감소를 마법 방어탑·결계의 0.9마정석 소비에도 연결하고 별도 회귀 검사를 추가했습니다.
측정 봇은 해당 연구에 도달하지 않았습니다. 수정 뒤 각 난이도 시드1의 200일 실행을 다시 했고 세 CSV와 세 저장 파일이 원 측정과 바이트 단위로 같았습니다.
최종 CTest에는 이 상급 효과와 무너진 탑의 발사 거절도 포함됩니다. 이번 Windows 세션에서 Linux ASan/UBSan은 실행하지 않았습니다.

## 자동 검사

공유 벌목 한도·한 번 수확·연료 잔여량·초과 재고의 소비·성문/공사/폐허 보호구역·의료 자격·후보 유지·빈집 물 공급·사료 선차감/부분 공급·성장 상한·계약 시각·손상 범위·할당 실패를 검사합니다.
`native_runtime`은 실제 경로·방향 걷기·적 전투와 5분 실내 진입/퇴장을 검사합니다. 그림 검사는 260방향·아틀라스의 내용·투명도를 확인합니다.

## 화면 확인

`--screen rotations`는 성채·주택·농장·병영·항구·마탑 4방향 비교입니다.
첫 촬영에서 병영의 이웃 셀 조각을 찾아 원화를 보정하고, C 패커가 투명한 골에서 자르도록 수정했습니다.
제목·게임·주민·연구·승급·시장·저장과 최소 창 크기의 실제 PNG를 확인합니다. 사람의 직접 조작 검사와 구별합니다.

## 제안 목표와 한계

왕성160~190일은 기획서의 제안 목표이며, 미달을 통과로 기록하지 않습니다.
현재 자동 봇은 정해진 성벽 경로를 사용해 물가·기존 문 때문에 보호구역을 닫지 못할 수 있습니다. 생존과 왕성 도달을 분리해 기록합니다.
실제 플레이어의 성벽 설계·일꾼 배치·식량 비축 숙련을 증명하는 검사는 아니며, 30분 이상 수동 플레이와 환경별 성능 확인은 남아 있습니다.
