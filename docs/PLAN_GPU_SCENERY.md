# GPU 조명과 살아 있는 픽셀 풍경 계획

상태: 사용자가 OpenGL 업그레이드·GPU 컴퓨트·필요한 보호 파일 수정을 승인했습니다. 공용 렌더러와 네 움직임 효과를 구현했으며 실제 결과와 남은 하드웨어 검사는 [GPU_SCENERY.md](GPU_SCENERY.md)에 기록합니다. 대상 노트북은 Windows 11과 모바일 RTX 4060입니다.

사용자 벤치마크 이후의 픽셀 통일·정확한 접촉부·연속 초지/물가·큰 연기와 새 색 방향은 [PLAN_NATURAL_SCENERY.md](PLAN_NATURAL_SCENERY.md)가 정본입니다. 이 문서는 GPU 기반을 도입한 당시의 기능 계획으로 유지합니다.

## 1. 목표와 표현 기준

현재 승인된 원화·명암 완화·법선 조명·건물의 각진 그림자·작은 물체의 둥근 그림자를 기준으로 삼습니다. 여기에 흔들리는 잎과 풀, 떠오르는 굴뚝 연기, 움직이는 수면을 더합니다. 화면과 카메라는 계속 2D이며 원화의 색·선화·픽셀 크기를 유지합니다. 건물 입체 자료는 그림자 계산에만 씁니다.

런타임 조명과 효과는 처음부터 공용 GPU 렌더러에 만듭니다. 현재 브라우저 CPU 비교 화면은 수치·외관 대조용으로 쓰며 실제 게임의 효과 실행 경로로 옮기지 않습니다. 오프라인 원화 추출·명암 완화·법선 제작은 기존 아트 파이프라인을 유지합니다.

## 3. GPU 기반과 공용 자료

### 그래픽 요구 사항

도입 전에는 raylib 5.5의 OpenGL 2.1과 GLSL 120 경로였습니다. 현재 공용 렌더러는 OpenGL 4.3과 GLSL 430 컴퓨트를 사용하고, 초기 기하 참조 셰이더는 GLSL 330으로 옮겼습니다. 컴퓨트에 필요한 OpenGL 4.3 요구는 [raylib 5.5 공식 예제](https://raw.githubusercontent.com/raysan5/raylib/5.5/examples/others/rlgl_compute_shader.c)에서도 확인할 수 있습니다.

권장안은 **OpenGL 4.3을 새 GPU 렌더러의 최소 요구 사항으로 정하는 것**입니다. GPU 상태 갱신·바람·파동·광원/차폐 분류·조명에는 컴퓨트를 쓰고, 스프라이트의 그리기·깊이·혼합에는 정점/프래그먼트 셰이더를 함께 씁니다. 그리기 작업까지 모두 컴퓨트로 강제하지 않습니다. 이 결정은 오래된 GPU의 실행 가능 범위를 줄이므로 승인 항목에 포함합니다.

현재 Windows/MSVC·Linux 경로를 대상으로 합니다. macOS의 기본 OpenGL은 4.1까지이므로 이 OpenGL 4.3 경로를 그대로 실행할 수 없습니다. [Apple의 공식 설명](https://developer.apple.com/videos/play/wwdc2020/10631/)도 이 한도를 명시합니다. Mac 실행이 필수라면 구현 전에 Metal 또는 WebGPU 계열의 기반을 선택해야 하며, 이 계획에서 Mac 지원까지 완료한다고 간주하지 않습니다.

시작 시 컨텍스트, 컴퓨트, SSBO, 이미지 쓰기와 필요한 한도를 확인합니다. 지원하지 않는 장치를 GPU 성능 검사 성공으로 처리하지 않습니다. 현재 환경에서 확인된 llvmpipe 결과는 소프트웨어 실행 검사이며 실제 그래픽 카드의 성능 증거로 쓰지 않습니다.

### 렌더러 구성

1. CPU는 카메라, 장면 객체, 공개 게임 상태, 광원·굴뚝·물 영역의 변경 자료만 전달합니다. 화면의 픽셀이나 개별 풀·연기를 CPU로 매 프레임 계산하지 않습니다.
2. 컴퓨트가 월드에 고정된 공용 바람, 수면 변화, 연기 입자, 보이는 효과 인스턴스와 광원/차폐 목록을 갱신합니다.
3. 원화, 법선, 높이·재질, 물체 번호를 GPU 화면 버퍼에 기록합니다. 움직이는 잎과 풀은 모든 버퍼에 같은 변형을 적용합니다.
4. 타일별로 해당하는 광원과 차폐 영역만 골라 조명·그림자를 계산합니다. 전체 160×160 지도의 모든 물체를 모든 픽셀에서 검사하지 않습니다.
5. 연기와 수면 효과를 깊이에 맞게 합치고 기존 픽셀 밝기 단계·가까운 이웃 확대를 적용합니다. UI는 이 처리 뒤에 기존 해상도로 그립니다.

렌더러는 장면 제출, 시간 갱신, 그리기, 진단 화면, 자원 해제의 작은 C 인터페이스로 분리합니다. 시험 실행 파일과 실제 게임이 같은 렌더러 소스를 링크하게 만듭니다. GPU 버퍼의 메모리 배치와 물체 번호는 처음부터 확장 가능한 형식으로 정하고 물체 번호는 32비트를 사용합니다.

GPU 결과를 매 프레임 CPU로 되읽지 않습니다. 컴퓨트 뒤에는 읽는 용도에 맞는 메모리 배리어를 두고, 성능 질의도 나중 프레임에서 비동기로 회수합니다. 목록 용량 초과는 검사·표시하고 그림자를 조용히 누락하지 않습니다.

공용 raylib 배치를 비운 뒤 사용자 GPU 패스를 실행하고 프레임버퍼·블렌드·셰이더 상태를 복원합니다. 메뉴·HUD 그리기에 GPU 상태가 새지 않는지 진단합니다.

### 공용 바람과 시간

낮은 해상도의 월드 바람 필드에 큰 바람, 이동하는 돌풍, 작은 흔들림을 섞습니다. 위치와 별도의 장식용 시드로 변화를 만들고 서로 다른 크기·속도를 사용합니다. 잎·풀·연기·물은 같은 필드를 각자의 무게와 지연으로 읽습니다.

장식용 난수는 게임 규칙의 난수와 분리합니다. 기본 효과 시간은 실제 시간 기준이어서 게임 배속에 따라 연기가 급가속하지 않습니다. 창이 비활성이면 정지하고 복귀 시 큰 시간 차이를 한꺼번에 적분하지 않습니다. 캡처에서는 시드와 시간을 고정합니다.

## 4. 이전에 승인된 조명과 그림자

- 기존 6종 원화의 반사율·법선·미세 표면 강도·발광·픽셀 밝기 단계를 GPU로 옮깁니다. 미세 질감이 다시 평평해지지 않게 원화와 법선의 표본 해상도를 보존합니다.
- 태양, 등불, 창문과 이동광을 같은 월드 좌표에서 계산합니다. 수신 높이와 화면 Y의 관계도 현재 비교의 0.9 배율을 유지합니다.
- 건물은 벽 상자·경사 지붕·굴뚝, 주민·바위·나무는 현재 승인된 둥근 근사를 유지합니다. 자기 물체와 소속 광원의 제외 규칙도 보존합니다.
- 광원별로 차폐를 계산하고 주변광과 다른 광원의 빛은 남깁니다. 접지 음영과 큰 그림자가 불필요하게 검게 누적되지 않게 합니다.
- 정적인 지면 수신점은 건물·지형의 차폐 결과를 월드 청크별로 캐시합니다. 태양 방향, 광원 위치, 건물·수목·지형이 바뀌면 관련 캐시를 갱신합니다. 단순한 등불 밝기 깜빡임에는 같은 차폐를 재사용합니다.
- 움직이는 주민의 그림자는 별도로 갱신합니다. 높은 주민·벽·지붕 수신점에는 높이에 맞는 차폐를 계산하며 지면 그림자 텍스처를 그대로 씌우지 않습니다. GPU 타일 목록과 기존 볼록 평면·타원체 교차를 사용해 현재 제외 규칙을 유지합니다.
- 첫 성능 목표는 태양 1개와 가까운 그림자 광원 4개입니다. 8개·16개 중첩도 별도 검사합니다. 수용 가능한 범위를 측정한 뒤 품질 한도를 정하며 조용히 광원을 없애지 않습니다.

## 5. 기능별 동작

### 잎

기존 나무 그림에 줄기·가지 고정 영역과 잎 무게 마스크를 만듭니다. 줄기는 고정하고 큰 잎 덩어리는 느리게, 바깥 잎은 조금 더 빠르게 움직입니다. 기본 변위는 기준 픽셀 약 1~3개로 시작해 원화가 늘어져 보이지 않게 조정합니다.

작게 나눈 2D 잎 영역 또는 마스크를 이용한 변형을 GPU에서 처리합니다. 원화·법선·높이가 같은 위치를 따라 움직이고 표면 방향 변화도 조명에 반영합니다. 소스 셀의 여백과 경계를 관리해 인접 아틀라스 그림이 나타나지 않게 합니다. 나무의 큰 그림자는 저주파 잎 덩어리 움직임을 따라가며 개별 잎마다 별도 광선을 쏘지 않습니다.

검토 기준: 줄기와 뿌리가 미끄러지지 않음, 잎이 고무처럼 늘어나지 않음, 나무들이 같은 박자로 움직이지 않음, 법선과 원화가 어긋나지 않음.

### 풀

기존 잔디 바닥은 유지하고 그 색·픽셀 질감에 맞는 작은 풀 묶음을 얹습니다. 뿌리는 땅에 고정하며 끝으로 갈수록 바람의 영향을 크게 받습니다. 바닥 타일 전체를 움직여 땅이 흐르는 느낌을 만들지 않습니다.

월드 위치와 고정 시드로 풀 모양, 높이, 방향, 밀도, 흔들림의 반응을 다르게 배치합니다. 큰 빈 곳과 작은 군집도 섞고 도로·건물·물 영역은 마스크로 제외합니다. 화면 안의 청크만 GPU 인스턴스로 처리합니다. 카메라가 돌아와도 같은 풀은 같은 자리에 남습니다.

바닥도 같은 팔레트의 원화 변형 여러 개와 아주 약한 큰 색 분포를 월드에 고정해 반복된 정사각형이 드러나지 않게 합니다. 원화 변형을 회전·반전하면 법선 방향도 함께 바꿉니다. 계절·눈·물 상태는 현재 게임 자료를 따릅니다.

한 종류의 사인파를 같은 시간에 적용하지 않습니다. 공용 돌풍과 개별 미세 움직임을 섞고 픽셀 단계로 표현합니다. 멀어지면 안정적인 월드 시드로 밀도를 줄여 프레임마다 풀이 반짝이거나 새로 생기지 않게 합니다.

검토 기준: 타일/청크 경계에서 패턴이 갈리지 않음, 바람에 따라 군집이 순차적으로 움직임, 복제된 풀 무늬가 줄지어 보이지 않음, 주민의 발과 풀의 앞뒤 관계가 맞음.

### 굴뚝 연기

굴뚝 꼭대기를 방출점으로 지정합니다. 작고 짙은 픽셀 연기가 위로 올라가며 커지고, 공용 바람에 따라 옆으로 흘러가고, 몇 단계의 투명도로 사라집니다. 방출 간격·수명·크기·모양을 굴뚝과 입자별로 달리해 같은 구름이 일정 간격으로 복제되는 느낌을 줄입니다.

고정 크기의 GPU 입자 풀과 작은 픽셀 연기 아틀라스를 사용합니다. 입자의 위치·나이·속도 갱신은 컴퓨트, 그리기는 인스턴스 쿼드로 처리합니다. 월드 높이를 사용해 지붕·나무의 앞뒤를 판정하고 해·등불 색을 약하게 받게 합니다. 먼저 동시에 보이는 2,048개 입자를 검사하고 겹침 면적과 수명을 제한합니다. 연기의 입체 유체 시뮬레이션과 연기 자체의 큰 그림자는 필수 범위에 넣지 않습니다.

검토 기준: 연기가 굴뚝에 붙어서 시작함, 바람과 일관되게 흘러감, 지붕을 뚫고 잘못 앞으로 나오지 않음, 방출을 반복해도 입자·GPU 메모리가 계속 늘지 않음.

### 물

기존 물의 색·바닥 그림과 해안을 유지합니다. 큰 느린 물결, 작은 잔물결, 드문 국소 물결을 서로 다른 크기·방향·속도로 섞습니다. 바람의 방향과 세기가 수면에 약한 영향을 줍니다. 표면 높이의 기울기로 동적 법선을 만들고 해·등불의 반응과 기존 큰 그림자를 받게 합니다.

GPU 컴퓨트가 월드 좌표에서 파동·노이즈 필드를 만들고 물 재질이 이를 읽습니다. 타일마다 UV나 애니메이션 시간을 처음으로 돌리지 않습니다. 월드 좌표 기반 해시, 여러 공간 크기와 완만한 시간 변화를 조합해 짧은 반복 노이즈 하나를 확대하지 않습니다. 무작위 값을 프레임마다 새로 뽑아 끓는 듯한 반짝임을 만들지 않습니다.

물 영역 마스크와 물가까지의 거리는 지도 변경 시 갱신합니다. 물가 가까이에서는 움직임을 약하게 하고 제한된 잔물결·얕은 물색을 더합니다. 땅은 변형하지 않습니다. 반짝임과 물결 선은 기존 원화에 맞는 적은 색 단계와 픽셀 크기로 제한합니다. 전체 장면의 실시간 반사는 별도 선택 기능으로 남깁니다.

검토 기준: 넓은 수면에서 같은 무늬의 타일 반복이 드러나지 않음, 물결이 경계에서 이어짐, 카메라를 움직여도 물이 화면에 붙어 움직이지 않음, 해안이 새거나 출렁이지 않음, 질감이 흐려지거나 지나치게 번쩍이지 않음.

### 반복을 확인하는 방법

수학적으로 무한히 반복되지 않는다는 약속 대신 플레이 중 보이는 타일 복제·동기화·짧은 루프를 없애는 것을 목표로 합니다. 넓은 잔디와 호수의 30초·3분 영상을 보고, 타일 경계와 청크 경계를 가로질러 이동하고, 같은 곳을 다시 방문해 배치의 안정성을 확인합니다. 돌풍과 미세 움직임의 시간 간격을 달리하고 공간 노이즈는 월드에 고정합니다.

## 6. 제작 자료와 수명

기존 실행 원화를 보존합니다. 필요한 잎 무게 마스크·풀 묶음·연기 아틀라스·물의 법선/재질 자료는 art/에 원본을 두고 두 매니페스트에 연결합니다. 새 생성 요청은 art/recipes/provenance.json, 권리는 CREDITS.md에 기록하고 assets_regenerate와 assets_reproducible을 통과시킵니다.

첫 GPU 비교는 현재 6종 표본과 물로 시작합니다. 실제 게임 연결 전에는 매니페스트에서 지형·도로·물·바위, 나무의 종류/성장 단계, 건물의 방향/상태, 주민의 외형/행동 프레임을 조사해 재질 적용표를 만듭니다. 원화 프레임과 법선·높이·움직임 마스크의 개수와 실루엣을 맞추고 좌우 반전·회전에 따른 법선 방향도 검사합니다. 법선이 빠진 임시 재질을 기본 평면 법선으로 표시할 수는 있지만 이를 아트 적용 완료로 세지 않습니다. 굴뚝 위치는 건물의 방향과 그림 프레임에 맞는 메타데이터로 둡니다.

런타임 소유 번호, 바람과 파동, 입자, 카메라별 GPU 버퍼는 저장 스키마에 넣지 않습니다. 렌더러가 전부 소유하고 해제합니다. 메뉴 전환과 화면 크기 변경 때 만들어지는 버퍼도 계수로 추적합니다. 반복 전환 후 살아 있는 자원 수가 늘지 않고 메모리 사용량이 안정되는지 확인합니다.

## 7. 구현 순서와 승인 범위

| 순서 | 구현 | 다음 단계로 가는 기준 |
|---|---|---|
| 1 | OpenGL 4.3 GPU 기반, 자원 수명·진단·시간/성능 질의, 현재 6종 픽셀 조명과 건물/둥근 그림자 이전 | 현재 비교와 시각·수치 대조, GPU에서 실행됨을 확인, 기본 성능 보고 |
| 2 | 공용 바람, 잎과 풀 | 원화 유지, 고정된 뿌리, 비동기 움직임, 타일/아틀라스 경계 검사 |
| 3 | 수면 필드·동적 법선·물가 | 넓은 수면과 3분 재생에서 반복·이음매·번짐 검사 |
| 4 | GPU 연기와 전체 조명 합성 | 굴뚝 연결, 바람·깊이 일관성, 입자 한도와 메모리 안정성 |
| 5 | 실제 게임 렌더러 연결과 회귀 | 네 해상도, 화면 전환, 기존 자동 실행 경로, MSVC WERROR 빌드·전체 검사 |

첫 단계에서 GPU 경로의 정합성과 진단 기능을 확인한 뒤 뒤의 효과를 얹습니다. 실제 그래픽 카드의 성능 확인은 완료 판정에 필요하며 소프트웨어 실행 검사로 대신하지 않습니다. 각 효과는 같은 장면에서 켜고 끄며 비교할 수 있게 만듭니다. 계산 결과의 CPU 되읽기에 의존하는 별도 구현을 먼저 만든 뒤 다시 이식하지 않습니다.

승인된 구현의 파일 범위는 다음과 같습니다.

- 시험·공용 GPU 모듈: tools/lighting_lab/gpu/** 및 해당 독립 실행 파일의 CMake 설정. 최초에는 독립 OpenGL 4.3 시험 빌드로 기존 게임의 OpenGL 2.1 설정과 분리할 수 있습니다. 같은 모듈을 나중에 실제 게임에도 링크합니다.
- 아트와 설명: art/**, game/assets/**, tools/art/**, 두 매니페스트, CREDITS.md, docs/PIXEL_LIGHTING.md 및 이 계획 문서.
- 실제 게임 연결: game/CMakeLists.txt의 GPU 버전·렌더러 소스 연결, game/src/render/world.c의 그리기 경로, 새 game/src/render/gpu_bridge.* 및 필요한 game/src/main.c의 초기화·해제 연결점. 입력 처리는 바꾸지 않습니다. 렌더러의 독립 문맥이 자원을 소유하므로 game/src/app.h는 바꾸지 않습니다.
- 이번 구현은 core/**, 저장 코드·스키마, cli/**, tests/**, game/src/ui/tutorial.*, .github/workflows/ci.yml, PROGRESS.md, README.md, docs/GAME_STATE.md, docs/PLAYER_GUIDE.md, docs/SPEC.md를 수정하지 않습니다. 루트 CMake에는 GPU 검사의 명시적 선택 옵션을, tools/lighting_lab에는 Windows 실행·벤치마크·MSVC 검사 도구를 추가합니다.

실제 게임 연결은 [이전 파일 담당 계획](PLAN_MAIN_SCREEN_TUTORIAL.md)의 메인 화면 전용 범위를 넘어섭니다. 사용자가 이후 대화에서 필요한 보호 파일 변경도 명시적으로 허용했습니다. 커밋·푸시·PR·병합은 이번 구현에 포함하지 않습니다.

## 8. 검사와 성능 기준

- 기준 6종 장면과 별도로 넓은 잔디·큰 호수·건물 100개·주민 500명·나무 200개·풀 묶음 10,000개·굴뚝 64개·연기 입자 2,048개의 밀집 장면을 렌더 자료만으로 구성합니다. 이는 게임 규칙 변경이 아닌 상한 부하 검사입니다.
- 태양, 4개 지역 광원, 8개·16개 중첩 광원을 나눠 검사합니다. 화면 밖/광원 밖 제외와 캐시 갱신 비용도 기록합니다.
- 800×600, 1024×768, 1440×900, 1920×1080에서 CPU 제출 시간, GPU 단계별 시간, 전체 프레임 p50/p95/p99, GPU 메모리와 자원 수를 따로 기록합니다. 기존 게임과 같은 시드·카메라·시간의 기능 전환 비교를 합니다.
- 60 FPS의 전체 프레임 예산은 약 16.7ms입니다. 최초 목표는 지정한 실제 GPU의 1080p 기본 광원 장면에서 새 네 가지 움직임 효과의 추가 GPU p95를 4ms 안에 두는 것입니다. 이는 달성한 수치가 아니라 검증할 목표입니다. 기존 게임의 기록된 약 28ms 기준 프레임도 함께 다시 측정하며 GPU 조명만으로 전체 60 FPS를 보장하지 않습니다.
- 원화·법선·높이가 맞물려 움직이는지, 벽의 모서리·지붕·굴뚝과 높은 수신점의 그림자가 맞는지, 물과 풀의 픽셀이 남는지 확인합니다. 시드·시간 고정 캡처와 CPU 수치 참조를 사용하고 GPU 부동소수점 경계의 허용 오차는 기록합니다.
- 30분 실행, 창 비활성/복귀, 확대·축소·청크 이동, 화면 크기 변경과 메뉴→새 게임/튜토리얼/이어하기/불러오기→메뉴 반복을 검사합니다. GPU 입자·버퍼·셰이더의 생성/해제 수가 균형을 이루어야 합니다.
- --screenshot --screen title|tutorial|game 및 --smoke-test를 유지합니다. 아트 재생성·재현성과 기존 전체 검사를 실행합니다. PR 단계에서는 최신 기준 브랜치 반영 후 전체 MSVC 빌드와 검사를 CASTLE_WERROR=ON으로 완료합니다.

승인된 결정은 기존 2D 원화 유지, OpenGL 4.3 GPU 기반과 1~5단계 순서입니다. 소프트웨어 기능 검사와 실제 노트북의 성능 통과는 구분합니다.
